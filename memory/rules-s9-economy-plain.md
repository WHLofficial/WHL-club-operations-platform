## §0 一句话

现在能做的分**三个通道**：**改参数**（分钟级生效、零发版、可回滚）、**造经营事件**（零发版、可定向给某一队、还能写故事）、**改代码发版**（忠诚缴池、团结金、富人税去悬崖这类新机制，赶得上 S9 中期窗关窗）。规则只要写清五件事：**什么时候 / 谁交 / 谁拿 / 按什么算 / 上限与例外**，剩下的交给对应通道。

#### §1.2 交易税（= 流动税）的量级与四个事实（2026-10-14 核准）

- **方向**：打**卖方**、基数成交价、分档按球员 RC：`tax(P,RC) = min(P,RC)×0.10 + max(0, min(P,1.5RC) − RC)×0.20 + max(0, P − 1.5RC)×0.40`（`src/core/tax.ts:22-29`）。
- **第三段 0.40 实际打不到**：挂牌上限 = 1.5×RC（`listing_cap_coef = '1.5'`），而 0.40 从 1.5×RC 起征 ⇒ 正常挂牌成交的有效税率只有 **10% ~ 13.3%**（P=0.5RC ⇒ 10% of price；P=RC ⇒ 10%；P=1.5RC ⇒ 13.3%）。
- **强制拍卖是另一套、且极端**：`auctionTax = price × 0.5`（`DEFAULT_AUCTION_TAX_RATE = 0.5`，`src/core/tax.ts:31-34`，注释原话「强制拍卖特例：整单一档税率（默认 50%）」）⇒ **卖方净得一半**，全系统最反流动的参数。
- **税是销毁的、不进池**：`src/core/tax.ts:4` 注释「税额销毁（回收），卖家净得 P − tax」，账本 memo「交易税（销毁）」⇒ 「流动才能收税」收上来的钱目前直接烧掉；要让税进池/再分配 = 新增联盟账户与转账语义（0068 迁移 + ADR），属发版。
- **量级**（基数 ΣRC 7061、成交额 = 换手率 × ΣRC）：换手 5% ⇒ 成交 353 ⇒ 税 **35~46**（正常挂牌）/ **177**（全走拍卖）；10% ⇒ 706 ⇒ **71~94 / 353**；20% ⇒ 1412 ⇒ **141~185 / 706**。⇒ 换手率翻倍税翻倍，但抬税率会压低换手、两者相抵 ⇒ **靠流动收税的收入天花板由换手率决定，不由税率决定**。对照：工资口 **2102**/赛季、忠诚（3 年一轮）**824**、维护 **385**。
- 结论：**促流动的第一杠杆是运营闸**（窗口开够长够频繁、开窗即生成招商轮、意向单开窗自动转挂牌），税率只在第二位。当前 25 天 0 窗口 / 0 挂牌 / 0 竞价 / 0 成交 / 59M 冻结（held）⇒ 即使税率降到 0，也不会有一笔成交。

#### §1.1 A3 的三个口径缺陷（2026-10-14 取证；不修则这套单价一分也发不出来）

1. **算不出入场队数 ⇒ 直接不发**：`stageEntryCount`（`src/worker/results.ts:495-507`）只认 `entry_count / entryCount / bracket_size / bracketSize / size`；赛事系统给该阶段写的是 `{"legs":2,"third_place":false,"source":{"from":1,"to":8,"fromStage":6}}` ⇒ 返回 null ⇒ `koProgressPrize`（`src/worker/prizes.ts:116`）第一行就 `return null`。S9 淘汰赛 14 场**全 pending**，尚未触发 ⇒ **目前没有欠账**。
2. **轮次差一位**：赛事系统 `match.round` 从 **1** 起算（实测 S9 stage7 = 1/2/3），而算式 `before = entry / 2 ** round` 隐含 0 起算。只把入场队数补成 8 ⇒ 第一轮按**决赛档 12.5** 发、第三轮 `before = 1` ⇒ **决赛反而不发**。正确为 `2 ** (round − 1)`。
3. **两回合会双发/错发**：奖金在**每场**确认时结算（`src/worker/results.ts:344-360`），一个两回合对阵 = 两条 match 行、`round` 相同 ⇒ 修好前两条后同一对阵发 **两次**；且每腿的 `winner_entry_id` 是**该腿**胜者（赛事系统 `worker/routes/admin/scoring.ts:284`，总比分晋级方由 `worker/lib/standings.ts` 的 `aggTwoLegs` 另算）⇒ **总比分被淘汰但赢了某一腿的队也会拿晋级奖**。要按对阵结算：`MATCH_SELECT`（`src/worker/results.ts:41-55`）目前没取 `leg / slot / stage_id`。

**修正**：8 队淘汰赛（S9 是 5 组取 8 队、未来 16 队制是 4 组×4 每组前 2 ⇒ 都是 **8 队**）实际只用三档 ⇒ 满发 **4×10 + 2×12.5 + 5 = 70**（`quarterfinal` 7.5 那档只在「16 队全进淘汰赛」才会出现）。我此前 v4 里的「淘汰 130 / 杯赛 330」按那个错误假定算，**高估 60** ⇒ 真实杯赛 = 池 200 + 70 = **270**。

## §2 钱是怎么流进流出的（人话）

**三层账**：

1. **进水管（凭空生钱）**
   - 比赛日：门票 + 商业 + 广播（每场结算；广播与上座无关，按级别逐场固定）
   - 联赛：每场胜/平/负即时入账 + 赛季末入场奖
   - 杯赛：小组赛每场胜/平 + 剩余池（按胜场分）+ 淘汰赛晋级即时奖 + 资格赛止步保底 + 超级杯
   - 其它：冠名费与奖金、卖球员收入、活动/场地收入、管理端调整
2. **水池（钱停在哪）**：俱乐部余额；报价冻结的押金（`fund_holds`）**不算可用余额**（可用 = 余额 − 冻结）
3. **出水管（钱消失）**
   - 经常性：工资、球场维护费、**忠诚支出（v6.47.0 起是出账）**
   - 一次性：富人税、扩建、升档、设施升级、商店、买球员（含交易税，**税打在卖方**）
   - 罚款类：违约金、下架费、冠名违约

**关键机制（决定了「规则怎么写」）**：现在每笔流水都是**单边**的 —— 只写「哪个队 +/− 多少钱」，**没有对手方**。所以账本里一条「再分配」必须写成**两条**：一队扣一笔（sink 类 memo）、另一队加一笔（faucet 类 memo），两条合计为零。联盟整体净额不变，只是钱在内部换了位置。

**一笔再分配长什么样**（以忠诚部分缴池 P=1/2、S9 中期窗关窗那一刻为例）：
- 每队按自己的合同算出一笔忠诚支出（合计 **591.65**）；
- 其中一半 **295.83 直接销毁**（钱没了），另一半 **295.83 记进联盟池**；
- 同一次关窗批里，池按分配键发回 18 队：**均分** ⇒ 每队 **16.44**；**K3（次级×1.5）** ⇒ 次级每队 **20.64**、顶级每队 **13.76**；
- 于是每队看到两条流水：`忠诚支出 −X` 与 `忠诚池分配 +Y`。净效果：合同贵的队净出钱、合同便宜的队净收钱。

**为什么现在能先干起来**：池总额在关窗批执行前就已确定，所以「两条单边」就能做出跨队净额为零的效果，不必等迁移 0068（代价：账目无法按队溯源，真正的转移语义仍留给 0068）。

## §3 规则怎么写

### 3.1 每条规则写清五件事

**① 什么时候触发 ② 谁交钱 ③ 谁拿钱 ④ 按什么算 ⑤ 上限与例外**。
五件事写全，就能直接判定它落在哪个通道、什么时候生效、要不要发版。

### 3.2 三个通道（选一个落地）

| 通道 | 怎么落地 | 生效时点 | 需要什么 | 适合写什么规则 |
|---|---|---|---|---|
| ① 改参数 | `PUT /api/admin/config`（或我写成一键 prod 批） | 立即；或下一次关窗/结算 | 键必须在白名单内（`prize_table`、`tier_table`、`wage_cap`、`wage_floor_gap`、`loyalty_tiers`、`tax_rates`、`event_signals`、`event_clamps`…） | 单价、池子大小、费率、门槛、档位 |
| ② 经营事件 | 管理端 `POST /api/admin/events/trigger`（可带 `clubIds`）；事件内容可用 `POST /events/llm-draft` 起草后 `drafts/:id/adopt` 采纳 | 下一次关窗批消费（维护费 / 冠名费 / 死忠） | 零发版、零新代码；效果受 `event_clamps` 钳幅 | 定向补贴/处罚、故事线、临时系数 |
| ③ 改代码发版 | 开发 → push → 自动部署 | 发版后下一次关窗/结算 | 一次发版窗口（半天） | 新 faucet/sink、跨队转移、新科目、联赛系数 |

### 3.3 六条可直接批准的规则草案

**规则 1 · 忠诚部分缴池**（通道 ③，截止 10/25）
> 每赛季第二个正式窗关窗时，各队按合同球员的效力档缴纳忠诚支出；其中 **P** 份额缴入联盟池，同一次关窗按 **分配键** 发给 18 队，其余销毁。

落点：`loyalty_tiers`（已生效）+ 新增两个键 `loyalty_pool_share`（P）、`loyalty_pool_key`（K3 / 均分 / 绝对量键）。建议 P=1/2。

**规则 2 · 团结金**（通道 ③）
> 赛季末统计各队门票收入，超过全联盟门票中位数的部分按档计提，计提所得发给门票低于中位数的队。触发档随门票基尼自动升降。

落点：`season-settle` 新增一次性计提。两套阈值可比：**旧阈值**（≤0.20 / 0.20–0.28 / 0.28–0.36 / >0.36 → 0 / 15 / 30 / 45%）在修正赛制后的门票基尼 **0.2407** 下落 15% 档（池 18.08）；因修正后整体基尼偏低（旧口径 0.3004），**建议阈值下调为 ≤0.16 / 0.16–0.22 / 0.22–0.28 / >0.28**，现状即落 **30% 档（池 36.16）**。

**规则 3 · 参与层拉平**（通道 ①，今天就能做）
> 顶级与次级的联赛入场奖设成同一个数（15）：参赛即得、两级同额。

落点：`prize_table.league_premier.entry` = `league_second.entry` = 15。

**规则 4 · 杯赛预算**（通道 ①）
> 冠军杯只发逐场奖与淘汰赛晋级奖，不再保留「剩余池」科目：小组赛池设成逐场奖上限（16 队赛制 = 24 场胜 × 7.0 = **168**）。

落点：`prize_table.champions_group.pool` = 168（或 176/184 留一点给小组第一）。

**规则 5 · 定向经营事件**（通道 ②，替代罚金）
