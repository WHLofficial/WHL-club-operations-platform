## 1. 需求真源（口径表）

| # | 口径 | 落地位置 |
|---|------|----------|
| 1 | 判定起点是**挂牌日次日**，不是出价次日：挂牌当天任何出价都进不了当日成交 | `src/core/market-rules.ts` `firstOffset = Math.max(1, minOffsetDays ?? 1)`；调用点 `src/worker/routes/market.ts:182/:894/:1077`（强拍传 2）、`src/worker/bypass.ts:895`（传 2） |
| 2 | 出价当日只要「静默段整段落在交易日 18:00-23:00 时段内」就可当日判定：18:43 → 21:43、19:11 → 22:11、12:00 → 21:00 | `bidDeadline` 按候选日 `start = max(时段起, lastBid)` 排队 |
| 3 | 静默段跨出时段尾就顺延下一交易日 21:00：20:30 → 23:30 越界 ⇒ 次日 21:00 | 同上 |
| 4 | 强拍恒比普通挂牌多一天（X+2） | `minOffsetDays: type === 'forced' ? 2 : 1` |
| 5 | 结算只看落库列：`deadline_at` 非空即按它判定，规则回退不会自愈历史数据 | `src/worker/market-settle.ts:500-502` |
| 6 | 数据订正只碰三张、且带双保险条件（旧值 + 仍在竞价中） | 见第 5 节 SQL |

## 2. 范围

**In**：`bidDeadline` 的候选日排布；挂牌日次日下限；强拍 X+2；三张挂牌的 `deadline_at` 订正。

**Out**：交易日历与节假日顺延逻辑（未改）；`deadline_hours` / `silence_hours` 配置（生产无覆盖行）；v6.64.3 的训练营匹配窗改动（不受影响）；v6.64.4 在途工作的两例回归失败（`NOTIFY_META`、注册名单 422）不在本版。

## 4. 变异验证（人工核过即可）

- 把那行 `if (dayStr <= bidDayStr) continue;` 加回去 ⇒ TC-BD-01 必红（截止被推到次日 21:00）。
- 把 `Math.max(1, minOffsetDays ?? 1)` 改成 `0` ⇒ TC-BD-03 必红（挂牌当天就能当日成交）。
