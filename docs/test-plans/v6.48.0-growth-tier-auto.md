## 范围与风险

**In**：五条件判定（含上限截断、缺数据不猜、港澳台不算中国籍、坏 JSON 兜底）；SQL 真源与 TS 镜像的逐条一致；重算的写入面（只写差异、锁定跳过、并发改过不盲写、分片/截断、审计口径与 origin 透传）；九个触发点是否真的挂钩（含源码扫描锁）；建档必填国家的校验与三条建档入口的差异（手动必填 / 机器与批量同步留空）；公开球员页 `tierBasis` 与人工锁定可见性；rekey 换壳的国家声明与工件内容。

**Out**：年龄滚动（c5 按导入时 `age` 静态判定，后续版本）；赛季结算与窗口机器挂钩（不写归属/国家/未来之星）；`config.tier_conditions`（死配置，无读取者）；前端视觉细节（沿用既有组件语言，e2e 只验结构）；生产回填（上线后管理端操作，不在本批代码内）。

**最坏情况口径**：
- **错档位静默**：档位错在页面上看不出来（只是一串数字），所以每条会改归属/国家/未来之星的路径都必须挂钩 —— 漏一处就是「部分球员永远停在旧档」。闸门 = 源码扫描测试（写 `players.club_id` 的文件必须调 `hookTierRecompute`）+ 四个触发点直调用例（转会/解约/导入/合同认领）。
- **人工值被自动值盖掉**：管理组核定过 5 档的球员，一次全量重算被改回自动值 ⇒ 管理组的判断无声失效。闸门 = 锁定行跳过（值 + 审计双不写）+ 预览 `locked` 计数 + 解锁才回到自动值。
- **审计恒空**：审计守卫写错（复用「旧档」谓词）时写入照做、留痕全无 ⇒ 事后无法回溯谁改的。闸门 = 断言 `growth_tier_set` 行数等于变更行数、`before/after` 快照逐字。
- **坏 JSON 炸端点**：`json_valid AND json_extract` 在 SELECT 投影里抛 `malformed JSON`（AND 不保证短路）⇒ 一个坏行让整页 500。闸门 = 裸表上的坏 JSON fixture + `COALESCE(…, 0)`（NULL 会污染整条档位表达式）。
- **建档漏国家**：手动建档不校验国家 ⇒ c2 永远判不出来且无人察觉。闸门 = 缺国家 400 + 不建档 + `clubsWithoutCountry` 提示。

## 已知边界与待办

- **c5 无年龄滚动**：`age` 是导入时由 birthdate 算一次的快照，赛季推进不会自动 +1 ⇒ 跨赛季后 18 岁边界会偏。留待后续版本（本版口径写进 TECH_DESIGN §10.3）。
- **机器通道建队无国家**：`routes/internal.ts` 与 `teamSync.ts` 不传 `country`（没有现实资料可填）⇒ 该队球员 c2 一律记假，靠管理端「未设国家的队」提示补录；补录后立即重算。
- **rekey 手写 SQL 绕过管理端**：换壳工件直接改 `clubs.id` / `country`，自动挂钩不触发 ⇒ 工件检查清单与 README 要求执行后到档位页补一次重算（已写进工件文本）。
- **`config.tier_conditions` 死配置**：注册了键但全仓无读取者（条件与分值在规则层硬编码）⇒ 待确认后清理或标注。
- **导入批量重算的读量**：一次导入收尾按 fcIds 范围重算，只读变更行（keyset + 索引），但仍会跑一条范围聚合计数 —— 大批量导入（万级）时的 D1 rows read 需在首次回填时实测登记。

## 修正（2026-10-16，v6.51.x 轮；用户裁决 A：只改断言、不扩端点过滤）

**症状**：㉒ 的 ⑤ 步自 v6.48.0 起从未通过 —— 断言（原 `scripts/e2e/smoke.mjs:3540-3544`）要求 `GET /api/admin/growth/tier-changes` 返回 `action='club_country_set'` 且 `targetId === clubId` 的行，而端点 `src/worker/routes/admin/growth-tier.ts:113` 的过滤是 `WHERE action LIKE 'growth_tier%'` ⇒ 该行按构造不可能出现。断言与端点同出提交 `1593362`，属自相矛盾，不是回归。实证：`audit_log` 里 `id=188 action='club_country_set' target_id=1` 确实写入（写路径正常），端点只返回 `id=189–192` 的 `growth_tier_set` 行 —— 即改国家**确实**触发了该队重算，被过滤掉的只是「触发事件」那一行。

**为什么不能断批次汇总行**：改国家走 `POST /clubs/:id/country` → `hookTierRecompute` → `applyTierRecompute`，只写**球员级** `growth_tier_set` 差异行（`src/worker/growth-tier.ts:168-177`，`after.auto = true`、`targetType='player'`）；`growth_tier_recompute` 批次汇总行（`targetId: null` + `after.scopeIds`）只由管理端批量重算入口 `recomputeGrowthTiers` 写（`src/worker/growth-tier.ts:262-280`），这条路径上不产生。

**修法**：断言改看「效果」而非「触发者」，并按行 id 增量取新行（不依赖总数）——
1. 改国家**前**取基线游标：`GET /api/admin/growth/tier-changes?limit=1` → `feedIdBefore = entries[0].id`；
2. 改国家（`POST /clubs/:id/country`，拿回 `tier {up, down}`）；
3. 改后取 `?limit=200`，`fresh = entries.filter(e => e.id > feedIdBefore)`；
4. 断言 `fresh.length === up + down` **且** 每行 `action === 'growth_tier_set' && targetType === 'player' && after.auto === true`。
