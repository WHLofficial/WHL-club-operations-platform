# v6.65.4 测试计划 · 谈判桌收口（已结束的谈判区 + 球员要求单卡折叠）

- **判级**：minor（新增只读的「已结束的谈判」区与单卡折叠能力；无迁移、无生产写路径变化）
- **需求真源**：owner「签约谈判区内每一个谈判可折叠」（v6.65.2 已上线）→「『球员要求』部分也要可折叠」→ grilling 答复「Q1-②，其余遵循推荐」→「按 6.65.4 版本号开工」
- **范围**：`GET /api/negotiations?mine=1` 的响应形状与分页参数、谈判页签底部已结束区、球员要求卡折叠；不含结算/作废逻辑改动、不含管理端

## 1. 口径（实现即契约）

| # | 口径 | 落点 |
| --- | --- | --- |
| 1 | 进行中会话**全量**返回（不再 LIMIT 50 与已结束混排） | `src/worker/negotiations.ts` `listMySessions` active 查询 |
| 2 | 已结束（`settled` / `cancelled`）按 `COALESCE(settled_at,'') DESC, id DESC` 分页，默认 10、上限 50，游标 `endedBefore`（id < 游标） | 同文件 ended 查询 + `src/worker/routes/negotiations.ts` |
| 3 | 游标只在「本页拉满」时下发（`endedNextBefore` 为末行 id），拿不到更多时为 `null` | `endedNextBefore` 计算 |
| 4 | 已结束行不下发逐轮 `attempts`（避免历史页膨胀） | `toDto(r, [], voidReason)` |
| 5 | `outcome`：`settled` → `signed`、`cancelled` → `void`、active → `null`；`endedAt` = `settled_at` | `toDto` |
| 6 | 作废原因从 `audit_log` 派生（`negotiation_timeout` / `transfer_self_cancel` / `admin_negotiation_void`），`after.reason` 决定文案；查不到时按 action 兜底 | `loadVoidReasons` + `src/core/negotiation-rules.ts` `voidReasonText` |
| 7 | 参数非法（`endedBefore` 非正整数、`endedLimit` ≤0 或非数字）→ 400 | `src/worker/routes/negotiations.ts` |
| 8 | 页签计数只数进行中 | `web/src/pages/market/desk/MarketDeskPage.tsx` |
| 9 | 已结束区默认收起，展开后一行一条；「查看更多」按游标续拉并去重 | `NegotiationsSection.tsx` |
| 10 | 球员要求：待处理 / 还价中默认展开，已接受 / 已拒绝 / 已过期默认收起 | `DemandSection.tsx` `cardOpen` |
| 11 | 折叠只加 `hidden` 不卸载，还价面板草稿与两段式确认保留 | `demand-body` 容器 |
| 12 | 卡头整行可点，但链接 / 按钮 / 输入框保留自身行为；chevron 是真按钮（`aria-expanded` + `aria-controls`） | `DemandCard` 卡头 |
| 13 | 折叠态记 `whl-demand-fold-v1`；`?demand=<id>` 深链强制展开目标卡 | `readDemandFold` / `writeDemandFold` / `cardOpen` |
| 14 | 进行中要求从 0 变回 >0 时，清掉这些卡的手动收起记录（避免新一波要求全被折起来） | `prevActiveCount` effect |

## 2. In / Out

- **In**：上述 14 条口径的行为与边界；已结束/进行中的分离与分页；作废原因文案；两条折叠交互与草稿保留。
- **Out**：作废/结算业务逻辑；管理端谈判页；历史 `attempts` 回看详情页；移动端专项（沿用既有响应式）。

## 3. 用例

| 编号 | 用例 | 断言 |
| --- | --- | --- |
| TC-DC-01 | 进行中 30 张 + 已结束 60 张 | `sessions` 返回全部进行中；`ended` 10 条；`endedNextBefore` 非空 |
| TC-DC-02 | 用 `endedBefore` 翻到底 | 末页 `ended` 不足 10 条且 `endedNextBefore` 为 `null` |
| TC-DC-03 | `endedLimit=3` | 只回 3 条且给游标；`endedLimit=0/abc/-1` → 400 |
| TC-DC-04 | 一条静默超时作废 | `outcome='void'`、`voidReason` 含「静默超时」、`attempts=[]` |
| TC-DC-05 | 一条成交已结束 | `outcome='signed'`、`voidReason=null`、`attempts=[]` |
| TC-DC-06 | 已结束区交互 | 默认无 `.nego-ended-row`；点开后成交显示「X.XXm/窗」、作废显示原因 |
| TC-DC-07 | 球员要求默认态 | pending 卡正文可见、accepted 卡 `hidden=true`；chevron `aria-label` 分别为「收起这张要求」/「展开这张要求」 |
| TC-DC-08 | 收起再展开 | 还价输入值保留（`hidden` 不卸载）；深链 `?demand=<id>` 强制展开已结束卡 |

## 4. 变异验证（改坏必须变红）

1. `endedNextBefore` 恒为 `null` → TC-DC-01/02/03 红。
2. `loadVoidReasons` 返回空 → TC-DC-04 红。
3. 正文改 `{open && …}` 条件渲染 → TC-DC-08 红（草稿丢失）。

- 退出：`npm run typecheck` 三份 tsconfig 全清；`npm test` 180 文件 / 2,937 例全绿；`npm run build` 通过；上述 8 条用例与 3 个变异靶均符合预期。

## 6. 上线后手工验收（owner 下令部署后）

1. 转会台 → 签约谈判页签：底部出现「已结束的谈判 · N 场」，默认收起；展开能看到成交工资与作废原因，「查看更多」能续拉。
2. 同一页签的「球员要求」：待处理的卡是展开的、已接受的卡是收起的；点卡头能收起/展开，收起前在还价框里填的数字展开后还在。
3. 从通知或深链进 `?tab=negotiations&demand=<id>`：目标卡自动展开并高亮。
4. 进度条外的行为不变：页签计数只数进行中，进行中的卡仍然默认展开并可折叠。
