## 范围

**In**：视觉模型适配层（`src/lib/llm.ts` 的 `llmVisionJson` / `extractJsonObject`）、识别结果解析与认人（`src/core/growth-ocr.ts` 的 `parseOcrVision` / `matchRosterPlayer` / `buildOcrEntries` / `ocrCrossChecks`）、端点 `POST /api/admin/growth/match-entry/:matchId/ocr`（零 DB 写）、前端合并与零封联动（`web/src/lib/growth-ocr.ts` 的 `mergeOcrEntries` / `sideConcededOf`、页面上传条）。
**Out**：视觉模型本体准确率（spike 已量化：glm-4v-flash 四图 100%，见 `memory/spike-v6.43.0-vision.md`）、夺回球权识别（裁决：不识别、保持手填）、进球/助攻预填（自动通道已覆盖，识别值只做交叉校验）、R2 截图存档（本期不做，上传图不留库）。

## 最坏情况口径（铁律）

- 模型回包是垃圾：围栏 + 前后闲话 + 非法 JSON → `extractJsonObject` 兜底，仍失败则 502 带中文原因，绝不 500、绝不写库。
- 模型幻觉编造滚动条外的行 / 认人歧义（同队同名）→ 逐行进 `unmatched`，不冒充预填。
- 识别评分 < 7.0 → 不预填评分（只预填出场），警告「7.0 以下不给 XP」。
- 恶意上传：非 base64 / 伪 MIME（PNG 前缀骗 `image/jpeg`）/ 超 5MB → 400，魔数嗅探为准。
- 未配置 LLM / 模型网关炸 → 503 / 502 旁路，录入页其余功能不受影响（识别是增强不是依赖）。
- 零封联动不越权：本侧失球 > 0 时绝不自动勾；门将被锁定（已录入）时不联动。
