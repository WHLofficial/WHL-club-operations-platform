# v6.68.0 期 A 测试计划 · 全站实体编号露出（IdTag）

- **判级**：minor（纯前端展示与复制；零迁移、零资金、零权限变更）
- **需求真源**：owner「管理面板审核根本不好用，要输好多 ID，有些 AI 比如挂牌 ID 我都无法在 UI 层面获取到」
- **设计定稿**：`docs/superpowers/specs/2026-11-02-admin-review-workbench-design.md`（Q1–Q12 决策记录）
- **范围**：期 A = 编号露出 + 点击复制。期 B（队列单号/直链/键盘/批选）与期 C（`/admin/workbench`）不在本次。

## 1. 口径（实现即契约）

| # | 口径 | 落点 |
|---|------|------|
| 1 | 编号形态 = 灰色 `#123` 文本按钮，点击复制**纯数字**（不带 `#`），成功 toast「已复制 挂牌 #18」 | `web/src/components/IdTag.tsx`、`web/src/lib/clipboard.ts` |
| 2 | 复制失败（Clipboard API 不可用且 `execCommand` 也失败）必须显性：按钮标红 + toast「复制失败，请手动选择 #18」 | 同上 |
| 3 | 外层本身是按钮时（`/market` 卡片整体是 `<button>`）不嵌可点按钮，只渲 `.id-tag.static` 露号 | `web/src/pages/market/MarketBoardPage.tsx` |
| 4 | 编号不是权限：露出的都是各列表本来就可见的实体 id（挂牌/出价/报价/谈判/转会/球员/俱乐部/工单） | 10 处落点 |
| 5 | 激活举报的审核行带 `report.listingId`（期 B 直链依赖），且仅管理员可见该队列 | `src/worker/routes/admin/reviews.ts` |

## 2. In / Out

- **In**：`IdTag` 组件 + `copyText`；10 处落点；`report.listingId`；`styles.css` 的 `.id-tag` 规则组。
- **Out**：批量审批、`/market?listing=`、`/admin/workbench`、凭证查看端点、`0089` 迁移（均属期 B/C）。

## 6. 已知边界

- 每个 `IdTag` 自己持有一个 `useToast` 实例：同一屏连续点两个编号，两条 toast 会在同一位置短暂叠放（3 秒各自消失）。换成全局单例 toast 属于跨页面重构，本期不做。
- `.id-tag` 的 `aria-label` 是「挂牌 #18，点击复制」，屏幕阅读器读到的是编号本身而不是纯数字——复制走的是 `copyText(String(value))`，两者不冲突。
