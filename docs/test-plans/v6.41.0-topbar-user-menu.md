## 一、不变量

1. **菜单对所有人渲染**：≡ 按钮与弹层必须落在 `user === undefined ? null : user ? … : …` 三态条件**之后**——时区对公开页（球员库 / 球队页时间显示）生效，未登录也必须能切档。
2. **登出只在「已登录 + OIDC」出现**：门控仍是 `user && authMode === 'oidc'`；兼容模式的会话真源在赛事系统，本站无从登出（不给假入口）。
3. **登出仍是原生表单整页 POST**：`<form action="/api/auth/logout" method="post">` + `type="submit"`，不是 fetch——302 链（club→认证中心→回 club）由浏览器跟随，后端顺带吊销本地会话并清 cookie。
4. **时区口径一字不动**：偏好落 `localStorage['whl.tz']`，同页切换派发 `whl:tz-change`、跨标签页走 `storage`；默认档「北京时间」；点档位即生效（重渲染链不变）。
5. **交互与语义**：按钮 `aria-label="菜单"` / `aria-haspopup="menu"` / `aria-expanded`；弹层 `role="menu"`，档位 `role="menuitemradio"` + `aria-checked`，当前档前缀 `✓ `；点档位后收起；外点与 Esc 都关闭（监听器只在展开时挂）。
6. **零残留**：顶栏不再有 `.tz-btn` / `.tz-pop` / `.tz-wrap`，也不再有平铺在 `.userbox` 直下的登出表单。
7. **弹层右锚**：`.user-menu` 是 `position: absolute; right: 0`（≡ 是 userbox 最右一格，弹层向左展开），375 视口下右缘不得越出视口。

## 七、评审登记

1. **为什么弹层不用 `<details>` / 原生 popover**：仓内已有 `MultiSelect` 的 Popover 先例（外点 + Esc + `role` 语义），顶栏复用同一套交互习惯；`<details>` 的箭头与默认样式要覆盖，`popover` 属性在测试环境（jsdom）不实现，会把可测性推给 e2e。
2. **为什么未登录也渲染菜单**：时区是**显示口径**、不是账号设置——v6.25.0 的既有约束就是「未登录可见」（球员库 / 球队页是公开页）。菜单放在三态条件之后是这个约束的唯一实现方式，故写成静态锁（TC-MENU-13）。
3. **为什么登出还走原生表单**：`/api/auth/logout` 的设计是「整页 POST → 302 链 → 回站」，浏览器跟随重定向顺带完成 OIDC 侧登出；改 fetch 就得在前端复刻跳转链，且后端清 cookie 的响应头在 fetch 里不生效。
4. **为什么弹层 `min-width` 从 132 提到 148**：菜单现在多了一行小标题「显示时区：北京时间」（11 个全角字符），132px 会把小标题挤成两行；148px 是让三档选项 + 小标题都单行放下的最小值。
5. **为什么不做键盘上下键导航**：范围控制——菜单只有 4 个可点项，Esc/外点/原生 Tab 已可完整操作；`role="menu"` 的箭头键行为属于「实现了才该加 role 的那套」权衡，仓内其他浮层（MultiSelect）同样没做，保持一致。
6. **为什么保留 `normKey`/旧类名注释**：CSS 里那条注释（`原 .tz-wrap/.tz-pop`）是有意留的考古线索，静态锁因此只禁**选择器**形态（`^\s*\.tz-`），不禁文本提及——否则注释也会被误判成残留。
7. **为什么 `<form>` 直接挂在 `role="menu"` 下、没加 `role="none"`**（code-review-skill 过审时记下的一条）：`<form>` 没有可访问名时按 HTML-AAM 不映射成 `form` 角色（等于无语义容器），`role="menu"` 的必需子元素（`menuitem`/`menuitemradio`/`separator`）允许夹在无语义元素里被找到，登出按钮的 `role="menuitem"` 播报不受影响；仓内同款浮层（`web/src/pages/club/card-parts.tsx:364-396` 的 `.sqc-assign-pop`）也没有对 wrapper 做角色处理，保持一致。若下批重构时想更严，给 form 加 `role="none"` 即可（无语义、不改行为、不动本计划的任何断言）。

## 八、注意事项

1. 前端改动后跑 e2e 前**必须先 `npm run build`**（dev 的静态资源取 `./web/dist`），并确认 8791 上 `assets/index-*.js` 是本次产物。
2. 静态锁 TC-MENU-12 用**索引序**而不是正则匹配嵌套：菜单结构一改（比如把登出包一层 `<div>`），只要顺序不变仍成立；若有人把登出挪到菜单外，`user-menu-wrap < user-menu < action=` 这条就会红。
3. 历史测试计划 `docs/test-plans/v6.25.0-timezone-display.md` 的 TC-B01/B02/E01 引用旧 `.tz-btn`/`.tz-pop`，属历史记录**不回改**；将来若有人拿它当活文档跑，会得到「选择器已退役」的结论——以本计划为准。
