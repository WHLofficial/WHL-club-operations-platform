# 测试计划 · v6.49.0 运营时刻表（11 键双锚）+ 统一到期引擎（报价回合 / 谈判静默）+ 管理端只读甘特图 + 教练侧置灰读秒

增量计划与设计稿：`memory/plan-v6.49.0-ops-schedule.md`、`memory/design-ops-schedule-expiry.md`。

## 范围与风险

**范围**：① `ops_schedule` 表 + 11 行操作键（10 项转会操作 + 消费中心整体）+ 双锚解析（`window_open`/`window_close` 随窗、`absolute` 具体时间、`none` 不限制）；② 统一到期引擎 `runExpiryTick` 接入 `runSettleTick` 第 5 步，两适配器（报价回合时限锚 `MAX(o.expiry_anchor_at, o.updated_at)`、签约谈判静默锚 `MAX(expiry_anchor_at, created_at, MAX(attempts.created_at))`）；③ 15 处写入口接 `assertOpOpen`；④ 管理端时刻表页（逐项表单 + 只读甘特图，手绘 SVG）；⑤ 教练侧置灰与读秒。

**安全默认（最重要的回归口径）**：迁移 0069 的 11 行种子**全为 `start_anchor='none'` + `end_anchor='none'`** ⇒ 上线即「不限制」，与上线前行为逐字一致；报价/谈判两个新时限的 `close_inflight` 默认 `0`，且**存量 pending 行首次扫描按 `now + N 小时` 回填 `expiry_anchor_at`**（不按历史锚实时算），避免首次 tick 批量误杀。

## 自动化用例（vitest）

### `tests/ops-schedule.test.ts`（16 例）
- **注册表与种子**：`OPS_KEYS` 11 键与迁移 0069 的 seed 逐键对齐（键序、label、`requires_window`）；只有 `transfer_offer` 与 `transfer_negotiation` 是 `requiresWindow: false`。
- **五态解析**：`resolveOpsRow` 的 `unrestricted` / `not_started` / `open` / `closed` 判据（含随窗两锚：窗口已开 ⇒ 解析出 `openedAt`；窗口已关 ⇒ 结束、`endIsWindowClose`）；`unrestricted` 按**锚型**判（`startAnchor==='none' && endAnchor==='none'`），不按解析时间判。
- **校验文案**：`validateOpsInput` 六条（缺时间 / 起止倒置 / 随窗锚却填了时间 等）。
- **管理端保存**：`saveOpsRow` 写库 + 审计 `ops_schedule_set`（`guardSql='changes() > 0'`）+ 保存后读回 + 缓存失效；未知键 404 `unknown_op_key`。
- **闸门**：`assertOpOpen` 在「未开始 / 已结束」抛 409（`op_not_started` / `op_closed`，文案含北京时间），默认全 `none` 时**全部放行**（与上线前逐字一致）；未知键不拦。
- **教练侧静态锁**（v6.49.0 追加 2 例）：9 个写入口文件都必须含对应键的 `useOpsGate(...)` 与 `<OpsGateNote`；`venueCards.tsx` / `MarketActivationPage.tsx` 的闸门必须出现在早退之前（防 conditional hook）。

## 未验证项（明示）

- **未跑 `wrangler dev` + 手动 tick 的本地端到端演练**（计划 §10）：本批以「真 D1 夹具全链单测 + 手动调用 `runSettleTick`/`runExpiryTick`」覆盖，端到端改由生产回读（第 3 步）补。若回读发现异常，回滚位是 11 行 `none`。
- **3 个新通知模板未在真实 QQ 通道投递验证**（`offer_deadline` / `negotiation_timeout` / `negotiation_deadline`）：模板渲染由 `notify-meta` 双向锁与 `notify.ts` 的 case 覆盖，投递链路与既有 30 模板同构；上线后首个到点事件时目视。
- **甘特图在真机窄屏（375 / 768）的观感未目视**：静态锁只保证「横滑 + 定宽落在样式表」，视觉细节（斜纹带、窗口带、刻度密度）需上线后管理端目视；未加 e2e。
- **存量宽限在生产规模下的批次数未实测**：`EXPIRY_LIMIT=50`/tick，若生产 pending 报价/谈判多于 50，首次回填需多个 tick（每 5 分钟一批）；回填只写锚不动作，不产生副作用。
- **`.gantt-band` 的 `fill` 不得写进 CSS**（会覆盖 SVG `fill="url(#…)"` 把斜纹吃掉）：这是实现期踩到的坑，目前只有注释与代码约束，未加静态锁。
