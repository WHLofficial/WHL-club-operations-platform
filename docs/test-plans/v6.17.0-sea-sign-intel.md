## 范围

**In scope**

- `GET /api/market/sea-signs`：已完成 `free_agent` 单据全服动态（season/windowSeq 过滤、最近优先、LIMIT 30、signFee = 成交新违约金 × 30%、原东家名含 CPU 队与真自由身 null）。
- `GET /api/market/cpu-board`：CPU 队 `free`/`normal` 球员按 CA 降序（字段口径、白名单过滤、CROSS JOIN 读量护栏）。
- `GET /api/players/:id` 详情的 `seaSign`（可签判定：window / ownership / status / banned / listing / pending / ok 六关与文案）与 `seaComps`（同档 ±5 最近 5 笔 → global 最近 3 笔 → none）。
- 退役面回归：`GET /api/market/free-agents` 已删（旧名单用例改写为详情判定例）；`POST /api/transfers/free-agent` 既有拒绝路径与文案不变；trainees 列表/激活入口不受影响。

**Out of scope**

- 前端情报台页面交互（web/ 由并行 agent 承接，本轮只看接口；`npm test` 不 typecheck web）。
- 判定守卫的实现重构（`checkSeaSignEligible` 只测行为，不测内部函数调用顺序；顺序用「更早的关先给文案」从响应上验证）。
- 海捞签入费的资金链路与成约谈判链本体（v3.2.0 起已有用例覆盖，本轮只在 TC-REG 里锁「拒绝路径不变」）。
- transfers 索引优化（零迁移是本增量既定约束，见 TC-SEA-06 的读量口径）。

## 最坏情况口径（铁律）

- **判定与提交不同源 = 界面能点、提交报错（或反过来）**：`createFreeAgent` 必须直接吃 `checkSeaSignEligible` 的 verdict，两边文案逐字一致；任一关只在一边改就会漂移。→ TC-JUDGE-08 + 变异 V1/V2
- **本窗解约禁签被绕开 = 解约洗白**：`termination completed` 同 season+window_seq 必须 409，且必须是**全联盟**（不只是原东家）；跨窗（上窗解约）不得误伤。→ TC-JUDGE-04 / TC-JUDGE-07 + 变异 V1
- **守卫顺序被调换 = 文案指向错误的动作**：有东家且已退役的球员若先报「状态不能海捞」，用户会去等退役恢复而不是找东家；在途单据与状态同理。→ TC-JUDGE-06 + 变异 V2
- **±5 同档边界写松写紧 = 参照不可比（CA 差 6 的球员被当同档）或参照永远为空**：`BETWEEN ca-5 AND ca+5` 必须恰含差 5、不含差 6。→ TC-COMPS-02 + 变异 V3
- **签约费率漂移 = 报价口径错**：`signFee` 与提交预检必须同源 `freeAgentFee`（30%），前端照 signFee 报价才不会「点进去钱不够」。→ TC-SEA-04 / TC-COMPS-06 + 变异 V4
- **成交动态顺序/上限被改 = 情报台失真**：`ORDER BY completed_at DESC, id DESC`（同刻按 id 倒序）与 LIMIT 30 是「最近优先」的全部实现；改成一味 id DESC 会把补录的旧单顶到最前。→ TC-SEA-02 + 变异 V5
- **CROSS JOIN 被「优化」成普通 JOIN / IN 子查询 = 生产读放大**：生产 17,731 名自由身，优化器会改用 `idx_players_status` 扫全部自由身（实测见下），CPU 榜只该扫 CPU 队的百来人。护栏锁 SQL 文本的 `CROSS JOIN` + 计划里 clubs 驱动。→ TC-BOARD-06 + 变异 V6
- **seaComps 的跳过口径漂移 = 公开面白算参照 / 可签面板拿不到参照**：详情是公开端点（无限流无缓存），参照在前端只出现在「可签 → 展开海捞面板」这一条路径里，故只对 `stage === 'ok'` 才算（评审 P1，发布前修正——初版曾对窗口关/禁签/在途也算参照，属无人消费的死账）。→ TC-COMPS-05 + 变异 V7
- **在途单据漏查**：`findInFlight` 先 listings 后 transfers `pending_review`，只查一边会让同一球员被重复下单。→ TC-JUDGE-05 + 变异 V8
- **最大组**：sea-signs 单页上限 30 条（灌 32 笔验证截断 + 排序），cpu-board LIMIT 500 是防 CPU 队扩容的上界（本用例不灌 500）。→ TC-SEA-02 / TC-BOARD-06
- **鉴权面**：两个情报口是教练功能（requireCoach），匿名 401 / 观众 403；球员详情是公开只读，匿名也应能读到 seaSign/seaComps（情报台不额外收权）。→ TC-SEA-07 / TC-BOARD-05 / TC-JUDGE-09

## 用例

### TC-SEA 海捞成交动态（GET /market/sea-signs）

**TC-SEA-01 · 只收已完成的海捞单据**（P0 · vitest）
- 前置：插 `free_agent/completed` ×1；再插 `free_agent/pending_review` ×1、`termination/completed` ×1、`rc_change/completed` ×1（都带 to_club_id 与 completed_at）。
- 步骤：GET /api/market/sea-signs。
- 预期：只回 1 条且是那笔 free_agent/completed；其余三类不出现。

**TC-SEA-02 · 最近优先：completed_at DESC → id DESC → LIMIT 30**（P0 · vitest）
- 前置：插 32 笔 `free_agent/completed`，completed_at 与 id 故意反向（第 1 笔时间最新），最后两笔同一时刻。
- 步骤：GET。
- 预期：`seaSigns.length === 30`；完整顺序断言（同刻两笔按 id 倒序 → 第 1 笔 → 其余按时间递减，最旧两笔被截掉）——纯 `id DESC` 或纯 `completed_at DESC` 的改写都会在这个序列上露馅。

**TC-SEA-03 · season / windowSeq 过滤与非法参数**（P0 · vitest）
- 前置：跨 2 个赛季、每赛季 2 窗各 1 笔成交。
- 步骤：`?season=4`、`?season=4&windowSeq=1`、`?season=0`、`?season=abc`、`?windowSeq=1.5`。
- 预期：前两次各只回对应窗口/赛季；三次非法参数均 400 且 `error` 逐字为 `season 应为正整数` / `windowSeq 应为正整数`（0、非数字、小数都进不了 SQL）。

**TC-SEA-04 · signFee = 新违约金 × 30%，无值回 null**（P0 · vitest）
- 前置：插 fee=6 ×1、fee=7 ×1、fee=NULL ×1。
- 步骤：GET。
- 预期：`newReleaseFee` 分别为 6 / 7 / null，`signFee` 分别为 1.8 / 2.1 / null（与 `freeAgentFee` 同源，非 30% 或按现值算都红）。

**TC-SEA-05 · 原东家/捞入队名与显示名口径**（P1 · vitest）
- 前置：一笔 `from_club_id = NULL`（真自由身）、一笔 `from_club_id = CPU 队`；球员 `display_name` 非空 ×1、为空 ×1。
- 步骤：GET。
- 预期：`fromClubName` 分别为 null / `AC米兰(CPU)`；`toClubName` 为捞入队名；`playerName` 取 `COALESCE(display_name, name)`；`playerCa` 取现值 `players.ca`。

**TC-SEA-06 · 读量口径：LIMIT 30 与排序写死在 SQL**（P1 · vitest）
- 前置：捕获 `env.DB.prepare` 的 SQL 文本（同 TC-BOARD-06 的包装写法）。
- 步骤：GET。
- 预期：SQL 含 `ORDER BY t.completed_at DESC, t.id DESC` 与 `LIMIT 30`；不断言查询计划——transfers 无 `(type,status)` 索引，全表扫是零迁移下的既定口径（源注释已写明量级），锁计划只会把将来的加索引优化变成假红。

**TC-SEA-07 · 鉴权：匿名 401 / 观众 403 / 教练与管理员 200**（P0 · vitest）
- 步骤：分别用无 Cookie、`tok-viewer`、`tok-coach`、`tok-admin` GET。
- 预期：401 / 403 / 200 / 200（缺权限时 requireCoach 文案 `没有权限进行此操作`）。

### TC-BOARD CPU 捞人榜（GET /market/cpu-board）

**TC-BOARD-01 · 只列 CPU 队且状态限 free/normal**（P0 · vitest）
- 前置：CPU 队球员 `normal` ×1、`free` ×1、`trainee`/`retired`/`listed` 各 ×1；非 CPU 队球员 CA 更高 ×1（含「球员无归属」×1）。
- 步骤：GET /api/market/cpu-board。
- 预期：只出现 CPU 队的 normal/free 两人；trainee/retired/listed 与非 CPU 队球员（无论 CA 多高）都不出现。

**TC-BOARD-02 · CA 降序，同 CA 按 id 升序**（P0 · vitest）
- 前置：CPU 队 3 人 CA 78 / 90 / 90（同 CA 两人 id 一大一小）。
- 步骤：GET。
- 预期：`ca` 序列 90, 90, 78；两条 90 中 id 小的在前（`ORDER BY p.ca DESC, p.id`）。

**TC-BOARD-03 · 字段齐全与显示名**（P1 · vitest）
- 前置：一条 `display_name` 非空、`fc_id`/`position`/`age`/`pa` 齐全的 CPU 球员。
- 步骤：GET。
- 预期：行含 `{id, fcId, name, position, age, ca, pa, clubName}`，`name` 取显示名，`clubName` 为 CPU 队名（`AC米兰(CPU)`）。

**TC-BOARD-04 · 无 CPU 队时空数组不报错**（P2 · vitest）
- 前置：库里没有任何 `is_cpu = 1` 的队。
- 步骤：GET。
- 预期：200 且 `cpuBoard` 为 `[]`（不是 404/500）。

**TC-BOARD-05 · 鉴权：匿名 401 / 观众 403**（P1 · vitest）
- 步骤：无 Cookie / `tok-viewer` / `tok-coach`。
- 预期：401 / 403 / 200。

**TC-BOARD-06 · 查询计划护栏：clubs 驱动、无自由身全表扫**（P0 · vitest，改写 `tests/market-routes.test.ts` 原「海捞名单查询计划」用例）
- 前置：CPU 队 ×1 + 该队 20 名 `normal` 球员；400 名 `club_id IS NULL` 的自由身球员（沿用原用例灌行数，逼优化器做选择）。
- 步骤：包装 `env.DB` 捕获 `prepare` 的 SQL → GET /api/market/cpu-board → 对捕获 SQL 跑 `EXPLAIN QUERY PLAN`。
- 预期：SQL 含 `CROSS JOIN`；计划含 `SCAN cp`、匹配 `/SEARCH p USING INDEX idx_players_club/`（**实测源 SQL 走 `idx_players_club(club_id=?)`，不是任务书预设的 `idx_players_club_ca`**：`ORDER BY p.ca DESC` 跨多队需要临时 B-TREE，优化器不会为此选 club_ca 索引；断言用前缀 `idx_players_club` 兼容将来任一 club 前缀索引）、不含 `SCAN p`、不含 `idx_players_status`、不含 `MULTI-INDEX OR`。
- 理由：留在 `market-routes.test.ts` 原位是「改写」的最小改动；该 fixture 已有 seedMarket 与灌行写法（`createClub` + `UPDATE clubs SET is_cpu = 1` + `sqlAll(EXPLAIN QUERY PLAN ...)`），搬到新文件等于复制一套 fixture。

### TC-JUDGE 可签判定 seaSign（GET /players/:id，公开只读）

- 步骤：GET /api/players/:id。
- 预期：`seaSign = { eligible: false, reason: '转会窗口没开，现在不能海捞' }`。

**TC-JUDGE-02 · 有东家且非 CPU 队**（P0 · vitest）
- 前置：正常球员挂在 `clubA` 名下 ×1。
- 步骤：GET。
- 预期：`eligible: false`，reason `海捞只能签无归属的球员（这名球员有东家）`。

**TC-JUDGE-03 · 状态 retired / listed**（P0 · vitest）
- 前置：无归属 `retired` ×1、无归属 `listed` ×1。
- 步骤：GET 两次。
- 预期：都 `eligible: false` 且 reason `当前状态不能海捞`。

**TC-JUDGE-04 · 本窗被解约（全联盟禁签）**（P0 · vitest）

**TC-JUDGE-06 · 守卫顺序：ownership 优先于 status，listing 优先于 pending**（P0 · vitest）

**TC-JUDGE-09 · 详情匿名可读且带 seaSign/seaComps**（P1 · vitest）

### TC-COMPS 参照 seaComps（GET /players/:id）

**TC-COMPS-01 · 同档：现值 CA ±5 内最近 5 笔**（P0 · vitest）
- 前置：待判球员 CA 80（无归属正常）；同档成交 7 笔（CA 75..85，completed_at 递增）；另有一笔 CA 60 与一笔 CA 95 的超界单。
- 步骤：GET 详情。
- 预期：`scope = 'same_tier'`，`rows.length === 5`，全部来自同档（超界两笔不在），按 completed_at DESC, id DESC 取最新 5 笔。

**TC-COMPS-02 · ±5 边界：恰差 5 含、差 6 不含**（P0 · vitest）
- 前置：待判球员 CA 80；参照 CA 85（差 5）与 CA 86（差 6）各一笔，85 的 completed_at 更早；另有一笔 CA 74（差 6，下限侧）。
- 步骤：GET → 断言只含 CA 85 那笔；再把该笔改成 CA 86 后重 GET。
- 预期：第一次 `rows` 只含 CA 85（含边界），第二次同档为空并回落 `global`（差 6 被排除，上下两侧同口径）。

**TC-COMPS-03 · 同档空 → global 最近 3 笔 → 全空 none**（P0 · vitest）
- 前置：待判球员 CA 80；全局成交 5 笔（CA 差都 > 5，completed_at 递增）；先 GET；再删掉这 5 笔后重 GET。
- 步骤：两次 GET。
- 预期：第一次 `scope = 'global'` 且 `rows.length === 3`（最新 3 笔，倒序）；第二次 `scope = 'none'` 且 `rows = []`。

**TC-COMPS-04 · 待判球员现值 CA 为空 → 直接 global**（P2 · vitest）
- 前置：无归属正常球员 `ca IS NULL`；全局成交 2 笔。
- 步骤：GET。
- 预期：`scope = 'global'`，回 2 笔（不因 CA 为空报错、不原地走 same_tier）。

**TC-COMPS-05 · 跳过口径：守卫链未全过（非 ok）一律不给参照**（P1 · vitest）
- 前置：同档成交参照若干；球员 A 挂 `clubA`（ownership）、球员 B `retired`（status）、球员 C 无归属 + 本窗解约（banned）、球员 D 无归属 + 活跃 listing（listing）、球员 E 无归属但窗口关闭（window）、球员 F 全过（ok）。
- 步骤：逐个 GET 详情。
- 预期：A–E 的 `seaComps` 均为 `{ scope: 'none', rows: [] }`（E 的 `seaSign.reason` 照给）；仅 F 给 `same_tier` 参照——实现口径 `compsSkip = verdict.stage !== 'ok'`（评审 P1 修正后的定稿口径），这一条把它锁死。

**TC-COMPS-06 · 参照行字段与 signFee 口径**（P1 · vitest）
- 前置：同档参照一笔 `from_club_id = NULL`（真自由身）、一笔 CPU 原东家、`players.display_name` 非空。
- 步骤：GET 详情。
- 预期：行含 `{playerId, playerName, playerCa, fromClubName, toClubName, newReleaseFee, signFee, season, windowSeq, completedAt}`（注意参照行没有 t.id，口径与 sea-signs 同源但字段面更窄）；`signFee = fee × 30%`；`fromClubName` 分别为 null / `AC米兰(CPU)`；显示名优先。

### TC-REG 回归

**TC-REG-01 · createFreeAgent 既有拒绝路径与资金预检不变**（P0 · vitest）
