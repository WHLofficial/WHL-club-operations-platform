# v6.76.0 测试计划 · 一线队号码分配（批量改 / 清 / 对调）

- **设计真源**：本轮 grilling 裁决 Q1–Q15（最终态提交、开窗门禁、全有或全无、草稿对调、冲突保留草稿、迁移 0092 唯一索引）。视觉稿见会话内 `squad-numbers-board.html`，用户已定稿。
- **需求来源**：owner「球员号码修改不便」→「无法批量改、清、换也是问题」；确认做浮层、不做独立更衣室页面。
- **范围**：`PUT /api/club/squad/numbers` 与共享写入核心；迁移 `0092`；`SquadNumbersDialog`；阵容页 `tier-head` 与球员页合同卷宗两处入口；保存后缓存失效。
- **不包含**：全队一键清空；冲突自动合并/自动改他人号码；独立页面；新的读接口；号码历史表。

## 5. 最坏情况与变异验证

- 最坏数据：100 人同时改号；全队对调/链式换位；payload 含 no-op；别队占号；关窗；浏览器里存着过期名单后撞号。
- 变异验证（逐条临时改坏、确认命中对应用例后恢复）：
  1. 写最终值前不置 NULL → TC-BE-01/02 红（0092 唯一索引）；
  2. 冲突检测只看 payload、不看其他队友 → TC-BE-08/09 红；
  3. 变动过滤去掉 `before !== after` → TC-BE-04 红（多出 no-op 审计）；
  4. 409 时清空草稿 → TC-UI-11 红；
  5. 保存后关闭浮层 → TC-UI-10 红；
  6. 入口不判开窗 → TC-UI-02 红。
