## 范围与风险

**In**：三批迁移的结构与数据（幂等、可重放、不写 `BEGIN/COMMIT`）；落点名的合成口径与「快照优先、空则现拼」；改名是否留半截（`brand_pool` 与 `naming_contracts` 两处）；档案字段的长度 / 格式校验与「至少给一个字段」；性格 → 套餐映射与回退；`prefer` 命中判定（前 25% 分位、样本 < 4 队退化）与加成封顶；抽签**确定性**（同签名逐字一致）与**权重偏向**（统计口径）；阈值反解（比率型 / 计数型）与 G1 上下限逐条；G1b 触界剔除重抽、G1c 兜底链四档；G2 / G3 支出与累计上限；G4 无主场判不达；结算双路（`bet_terms` v2 逐条 vs 空 / v1 走旧绝对线）。

**Out**：本批上线动作（迁移 `0071`–`0075` apply 生产 + push + 部署 + 回读，待令）；生产首季实际达线率与 `dropped` 占比的长期观察；真实商标库撞名核验（渠道未打通）；插件仓 `brand_service.py` 种子表（以平台迁移为准）；前端视觉像素级走查（e2e 量与人工验收覆盖）。

**最坏情况口径**：
- **阈值被钳低 = 白送钱**：反解线超出上限时若「钳到上限」，弱队会拿到一条几乎必达的条款（每窗白付 0.25×底价）。闸门 = G1b 做法是**剔除该项重抽**（`dropped` 记账），唯一允许向下钳的路径是「可行池 = 0」且记 `guard='ceil'`；用例 TC-BET-06 / TC-BET-08 分别锁两条路径。
- **重跑不一致**：关窗批若中途失败重跑，抽签结果必须逐字相同，否则同一窗口会算出两份不同奖金。闸门 = seed = `(season, windowSeq, clubId, 品牌哈希)` 走仓内确定性 `seededUnit`；用例 TC-BET-11 断言同签名恒同结果、换季换窗换品牌换 seed。
- **双达概率偏离 p²（经济式不成立）**：两条条款若抽到同相关族（如上座率 + 满座场次），双达概率远高于 p²，对赌支出被系统性抬高。闸门 = 第二条排除同族（A={attend, sellout}、B={points, goals}、C={fans}、D={cleansheet}）；用例 TC-BET-09 断言同族池只抽 1 条。
- **无主场窗误发达线奖金**（沿用旧「无主场缺省上座率 1」的坑）：闸门 = 结算侧必须拿到本窗主场场次，`homePlayed = 0` 时 `attend` 判不达；用例 TC-BET-19。
- **结算把老合同弄坏**：`bet_terms` 只对新合同写入，历史合同的空串 / v1 旧格式 / 坏 JSON 必须走旧 `bet_attend` / `bet_fans` 且不抛错（否则关窗批整批失败）。闸门 = `parseBetTerms` 只对 v2 结构认账，其余回 `null`；用例 TC-BET-21 / TC-BET-22。
- **改名留半截**：只改 `brand_pool` 不兜底 `naming_contracts.brand`，历史合同品牌名与池脱钩。闸门 = 迁移两处幂等 `UPDATE` + 全池无真实名残留断言（见 TC-NAME 段与 e2e ㉓）。
- **档案校验放过非法值**：超长简介 / 非法品牌色（`#GGGGGG`、6 位以下）进库 ⇒ 前端色块与卡片破版。闸门 = 服务端校验（长度上限、`^#[0-9A-Fa-f]{6}$`、`origin` / `style` 枚举、`prefer` ≤3 且标签白名单）+ 400 不动库断言；用例 TC-BP-05 / TC-BP-06。
- **性格回退错档**：`style` 为空或脏值时必须回 `packageNoForTier`（头部 2、其余 1），不得一律递稳健。闸门 = TC-BP-01 表。
- **`prefer` 加成失衡**：命中 3 个标签若线性累加会到 +0.06，超出满意度上限设计。闸门 = `min(命中数 × 0.02, preferBonusCap 0.04)`；用例 TC-BP-07。
