> 同版本另有「球队中心页签化 + 施工开窗闸 + 球员表列集重定」一路，见 `docs/test-plans/v6.29.0-club-center-rework.md`。

## 1. 目标与口径

关窗前后的行为改两条：

1. **报价链放开**：窗口关闭不再一律禁止报价 / 还价 / 同意。关窗期谈成的单子落为**意向单**（`offers.status='intent'`）——不挂牌、不动兄弟 pending 单、资金继续保持冻结。
2. **开窗后不自动推进**：窗口一开只提醒双方，须**卖方手动确认**才走既有挂牌链路（挂牌 + 兄弟 pending 过期 + hold 转正 + 领先出价）。买方随时可撤回，卖方确认前也可放弃。
3. **消费侧反向收紧**：消费工单提交（`POST /api/shop/orders`）在关窗期 409 拦下，与转会操作同口径；档期、冠名等既有动作口径不变。

## 3. 状态机与关键判定

| 场景 | 结果 |
| --- | --- |
| 开窗期 `acceptOffer` | 现状不变：`accepted` + 立即挂牌（`fulfillAcceptedOffer(..., 'accept')`） |
| 关窗期 `acceptOffer` | `status='intent'`（原子 `UPDATE ... WHERE id=? AND status='intent'` 归窗到当前窗 + 挂牌） |
| 关窗期达线自动同意 | 同样只落意向单（否则会写出 `season`/`window_seq` 为 NULL 的挂牌） |
| 关窗期同意时该球员已有意向单 | 409 `intent_exists`（不落任何改动） |
| 有 Intent 在等开窗时挂牌 | 409 `intent_exists`（窗口开着也不给挂） |
| 非卖方确认 | 409 `intent_seller_only` |
| 卖方无窗时确认 | 409 `no_window` |
| 确认成功 | 归窗 + 挂牌 + 兄弟单 `offer_expired`(reason `sold`) + hold 转正 + 领先出价 + `confirm` 事件 + 买方 `offer_intent_confirmed` |
| 卖方放弃 / 买方撤回 | 终态（`rejected` / `withdrawn`）+ 释放冻结 + 对方 `offer_intent_closed`（`data.action` 区分） |
| 置非卖品 | pending 与 intent 一并自动拒 |
| 球员状态变化 | `expireStaleOffers` 自愈过期，reason `state`（不再有 `window` 原因） |

## 7. 风险与遗留

1. **前端无本地窗态闸**：`OffersSection` 靠后端 409 + toast 呈现，未按窗态预置灰；`SideOps` 的报价按钮已放开、报价面板文案分窗态两分支。属有意选择（窗态可能中途翻转，服务端为准）。
2. **跨文件语义闸带**：`SideOps` 的徽标仍只统计 `pendingMine`（未含 `intentsMine`），球员页入口不变；意向单入口统一在转会桌「我收到的」页签。
3. **闸位层级不齐**：消费闸在路由层（`routes/shop.ts`），施工闸在 ops 层（`stadium-ops.ts`），文案与 code 一致但落点不同——口径统一、实现位置由各自模块结构决定，已记档。
4. **移动端**：`windowOpen` 加入消费卡 `disabled` 合并计算后，375×812 视图的空态文案由「余额不足」改为「关窗期」提示优先，属预期。
