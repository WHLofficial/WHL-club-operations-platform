# v6.66.0 测试计划 · 审核通过即过户（第 1–2 期）

- **判级**：minor（新增「成交即挂单终态」这条可见规则，修掉一条把球员永久锁死的缺陷；无迁移、无账本改动）
- **需求真源**：owner 2026-11-01「为什么挂牌截止之后变成待审核了（即使是审核之后、谈判之后）？」→「把扣钱、挪球员的操作放在谈判之前」→「先落文档，然后 brainstorming，然后 grilling」→「按顺序开工，并分配版本号」→「分配一个版本号比较好吧」（全案一个版本 v6.66.0，三期三个提交）
- **设计定稿**：`memory/design-transfer-before-negotiation.md`
- **范围**：第 1 期 = `completeTransfer` 成功路径回写 `listings`、`findInFlight` 补谈判段、14 条生产脏数据一次性修复；第 2 期 = 「谈判在途」判据从单据 `signing` 换成会话 `active`（8 处 + 海捞两处口径）；**不含**顺序翻转、`applyContractTerms`、撤销入口（第 3 期）

## 1. 口径（实现即契约）

| # | 口径 | 落点 |
| --- | --- | --- |
| 1 | 过户成功是挂单的终态之一：`completeTransfer` 成功批次里必须把该挂牌写 `delisted` | `src/worker/transfers.ts` `completeTransfer`（`UPDATE transfers …` 之后） |
| 2 | `deadline_note` 写「已成交」，与失败路径的「审核驳回」「被匹配，球员留队」并列可读 | 同处 |
| 3 | 收口只认幂等键 `listing:<id>` 反查出的挂牌；`match:<id>`（匹配留人）已在 `activations.ts` 自行收口，不重复处理 | `listingIdFromTransfer` |
| 4 | 收口 UPDATE 带状态白名单（`listed`/`bidding`/`matched_pending`/`pending_review`），已 `delisted` 的行不被改写；重复调用幂等 | 同 SQL 的 WHERE |
| 5 | 收口与过户在**同一批**里：过户成功但挂单没改不可能发生 | `db.batch` |
| 6 | `findInFlight` 新增 `'negotiation'` 段，判据 = 该球员有 `negotiation_sessions.status='active'` 且其 `transfers.status <> 'signing'` | `src/worker/bypass.ts` `findInFlight` |
| 7 | `<> 'signing'` 是刻意的：今天所有 active 会话都挂在 `signing` 上，各调用点另有 signing 闸，谈判段不得抢文案 | 同上（测试锁） |
| 8 | `ensureNotInFlight` 对 negotiation 的文案：「这名球员已经成交，还有一场签约谈判没结束，等它结束再操作」 | 同上 |
| 9 | 会话一结束（`settled` / `cancelled`），谈判段立刻放开 | 同上 |
| 10 | 生产 14 条「已成交仍 pending_review」一次收口，只改 `listings.status` / `deadline_note`，不动 transfers / players / contracts / 账本 | `scripts/prod-20261101-listing-closeout/` |
| 11 | `signing` 的 6 条**不手工改**，等它们按本版新路径成交时自行收口 | 同上（README 写明） |

## 2. In / Out

- **In**：上述 11 条；成交路径的挂单终态；`findInFlight` 谈判段的三态（无会话 / signing 会话 / 已完成单 + active 会话）。
- **Out**：审核通过即过户（第 3 期）、8 处 `signing` 判据替换（第 2 期）、撤销入口（第 3 期）、迁移 0088、前端「合同谈判中」标。

### 第 3 期补：界面口径（D9「合同谈判中」小标）

成交即过户之后，「人已在队内、条款还没谈定」不再由 `transfers.status` 表达（它已是 `completed`），只能看有没有 active 会话。`GET /api/club/players/:id/requests` 因此加 `negotiating: boolean`（`negotiation_sessions.status='active' AND transfers.status='completed' AND transfers.terms_applied=0`），球员页在途区据此出紫色「合同谈判中」小标。

- TC-LC-01′ 追加两条断言：审核通过、会话 active 时 `negotiating === true`；谈定（`terms_applied=1`、会话 `settled`）后 `negotiating === false`。
- 市场页「待审核」页签保留原样（它看的是 `listings.status='pending_review'`，与本标无冲突）。
