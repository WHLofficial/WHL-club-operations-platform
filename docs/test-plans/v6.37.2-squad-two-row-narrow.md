# v6.37.2 阵容/注册卡两行式窄屏布局 —— 测试计划

> 版本：v6.37.2（与 v6.37.0/v6.37.1 同系列）。
> 范围：360px 级窄屏下阵容页签四视图卡与工作台注册卡的两行式重构 + 顶栏 nav 短文案收纳 + 全站窄屏 padding 收窄。
> 背景：v6.37.1 只救回 88px 名字区——360 真机教练视角名字仍被压到 23px（合同）/0px（成长、市场）；内联徽章「+N」点击无反应；超管 8 项 nav 横向溢出 117px。用户实测裁决「padding 占太多，不希望引入滑动」。

## 根因账（探针实测，viewport 360×760）

| 项目 | 数值 |
| --- | --- |
| 层级 padding（container 32 + .card 36 + .sqc-card 24） | 68px（收窄后 48px） |
| 分配下拉 `.sqc-assign`（教练视角每卡恒在） | 71px |
| 合同视图值区（2×60 钉宽） | 120px |
| 教练视角合同视图名字区（修复前） | 23px |
| 成长/市场视图名字区（修复前） | 0px（逐字竖排） |
| 成长/市场值区（3×50/52 钉宽） | 150/156px |
| 超管 nav 8 项总宽 | 453px > 可视 336px |

## 修复方案（v6.37.2 定稿：两行式）

- **第一行** = 序号 `.sqc-no` + 名单区（`flex:1`）+ 分配下拉（回行尾）。
- **第二行** = 值区 `.sqc-m` `flex-basis:100%` 独占整行，`repeat(var(--sqc-mcols,3), 1fr)` 均分——列数 = 各视图值数（basic 3 / growth 3 / contract 4 / market 3），值恒单行不折。
- **组头列头** `.sqc-ghead .sqc-gcols` 同款 1fr 网格折到组头第二行，与行卡值区逐列右缘对齐（ghead padding 对称 10/10）。
- **短文案 nav**：≤640 显 `.nav-ts`（我的/球员/球队/转会/消费/财政/管理），桌面显 `.nav-tf` 全称；aria-label 保留全称。
- **+N 徽章**：span→button，点击就地展开其余徽章、再点收回（照 CardSubline 位置 +N 先例），`aria-expanded` 翻转。
- **padding 收窄**：≤640 时 `.container` 16→12、`.card` 18→12、`.sqc-card` 12→10。
- **违约金/激活价**：`moneyIntText` 带 ` m` 单位（37 → `37 m`）。

**流程教训**：`npm run dev` = `wrangler dev --port 8791`，服务的是 vite build 后的 hash 资产（无 HMR）——e2e 前必须 `npm run build`，否则变异/改动根本没进被测资产（本轮第一轮变异 e2e 全绿的假象即由此而来）。M4 原设计（删 `.nav-ts` 的 640 显示规则）会让窄屏双 span 全空、nav 反而变短测不出越界——变异必须制造「原样式更宽」的差值才有锁力。
