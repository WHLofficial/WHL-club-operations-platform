## 四、登记（如实）

1. **错报更正**：早期答复 m02661 的「本赛季小组赛已发放 168」是错报（`memo LIKE '冠军杯%'` 漏 4 笔：弃权场 #2 的 id 254 + 3 笔误写「联赛胜场奖金（比赛 #N，CPU 期补发）」的 #18/#22/#27 id 256/264/257）⇒ 真实即时值 **196.00**；池下调算术随之从「省 32」更正为「**只动池最多省 7.5**」。
2. **池取值 192.5 而非 120**：用户要「本赛季不再分配剩余池」；S9 口径下 192.5 与 120 效果相同（都 −7.5），192.5 不预设 S10 目标值。
3. **首轮执行撞瞬时故障**：02 报 `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c, line 76`、03 报 proxy 提示后 exit 1，两次均 **0 条落库**（只读复核确认）⇒ `--retry=3` 重跑成功。
4. **通道约束**：`exec-shards.mjs` 走 `wrangler d1 execute --command` ⇒ 拒含 `" % & | < >` 的语句；JSON 改用 `json_object(...)` 构造、守卫写 `NOT EXISTS`；`--file` 通道在 `--remote` 偶发 `A fetch request failed`。
5. **遗留**：① S9 结算仍会按 config 发基础入场额（次级合计 = 20）；② S10 起若版权池（300）取代入场奖金，需处理 `entry` 字段的语义；③ 池 120 + 逐场单价（胜 4.0 / 平 1.5）同批下调仍待令；④ 本地演练夹具里俱乐部 1 写成 32.42（生产实际 49.68，为阿斯顿维拉的值），已在批件 README §3 更正登记，不影响批件行为。
