# 测试计划 · v6.59.0 球场与冠名页签 / 子设施档位上限 / 队壳首窗

> 按 qa-test-planner 约定设计。执行层 = vitest（单测 / 集成 / 静态锁）+ 本地真栈 e2e（`npm run dev` 8791 + 本地 D1）。
> 需求来源：用户 2026-10-29 消费中心改造（页签重排、球场升级门槛、子设施上限、医疗隐藏、队壳窗口）。术语见 `GLOSSARY.md`「消费券 / 球场档位 / 子设施」。

## 一、范围与目标

**In scope**
1. **消费中心页签**：新页签「球场与冠名」排第一；设施经营 + 冠名市场两卡只在该页签渲染，底部旧位置移除；`?tab=venue` 深链可达。
2. **队壳窗口**：`POST /api/shop/orders` 的 `club_shell` 只在赛季第 1 个窗口（`window_seq=1` 且开窗）放行；前端按钮同口径禁用并给专属文案。
3. **球场升级门槛**：删除「容量 ≥ 下一档 `min_seats`」硬闸，改文案「建议达到」；升级只看开放进度（`stadium_max_open_tier`）。
4. **档位编号**：面向用户的档位整体 +1（库内 `tier=0` 显示「社区级 (1)」），覆盖设施卡、主场档案。
5. **子设施上限**：上限 = 球场档位（`facilityCapForTier(tier)=min(5,tier+1)`）；后端越限 400、`build-info` 回 `facilityCap/cap/canUpgrade`；前端到限显示「已达上限（升级球场后解锁）」，满 5 级才显示「满级」。
6. **医疗中心**：本轮前端隐藏（不渲染行），后端 key 与历史等级保留。

**Out of scope**：医疗中心数值效果设计（现无常驻系数）、冠名市场逻辑改动、迁移与数据回填（无 schema 变更）、跨仓契约。

## 三、用例

### A. 消费中心页签

**TC-VN-01 · 页签顺序与卡片归属（P0）**
步骤：进 `/shop`；读页签文本；点/深链 `?tab=venue`；再切 `?tab=pa`。
预期：① 页签顺序为 `球场与冠名 / 买 PA / 徽章 / 角色（职责）/ 位置热区 / 队壳申请`，默认仍 `pa`；② `venue` 下渲染设施经营 + 冠名市场，默认 `pa` 下两卡不在 DOM；③ `?tab=venue` 命中选中态。

**TC-VN-02 · 窄屏（375）零溢出（P1）**
步骤：`/shop?tab=venue`，375×812。
预期：文档级横向溢出 ≤1px；页签条 `overflow-x:auto` + 6 个按钮可横滑；`.facility-row` 为 `flex` + `flex-wrap:wrap`，4 行全部右缘 ≤ 视口。

### B. 队壳申请窗口

**TC-VN-03 · 仅赛季第 1 窗（P0）**
步骤：分别在第 1 窗 / 第 2 窗 / 无开窗提交 `category:'club_shell'`。
预期：① 第 1 窗 201；② 第 2 窗 409 `shell_first_window`，文案含「赛季第 1 个窗口」；③ 无开窗 409 通用「转会窗口没开」；④ 前端非第 1 窗按钮禁用、title 与提示同文案；第 1 窗恢复可点。

### C. 球场升级与档位显示

**TC-VN-04 · 删座位下限（P0）**
前置：tier 0、容量 12,000（低于下一档建议 20,000），开窗、余额充足。
步骤：`POST /api/club/stadium/upgrade`。
预期：200，tier→1，容量保持 12,000；`build-info.nextTier` 不再含 `capacityOk`；前端不再出现「容量不足」。

**TC-VN-05 · 档位文案整体 +1（P1）**
步骤：读设施卡与主场档案。
预期：设施卡「社区级 (1)」/「下一档 地区级 (2)（建议达到 20,000 座）」/「球场档位开放至 地区级 (2)」；主场档案「专业（4 级）」对应库内 tier=3；`至少` 字样消失。

### D. 子设施上限

**TC-VN-06 · 上限随档位（P0）**
步骤：① tier 0 连续升商业区两次；② tier 4 连升到 5 级后再升；③ 读 `build-info`。
预期：① 第二次 400 含「当前球场档位上限（1 级）」；② 5 级后 400 含「上限」；③ `facilityCap=1`（tier0），每项 `cap/canUpgrade` 与等级一致，到限项 `nextCost=null`。

**TC-VN-07 · UI 到限文案（P1）**
步骤：fixture `level=1,cap=1,nextCost=null`；另一 fixture `cap=5,level=5`。
预期：前者「已达上限（升级球场后解锁）」且无「满级」；后者「满级」。

**TC-VN-08 · 医疗中心隐藏（P2）**
步骤：`build-info.facilities` 含 `medical`，渲染设施卡。
预期：页面只出现 4 行子设施与 4 个升级按钮；`医疗中心` 文本不可见；后端 `medical` 行仍可被直调升级（本轮不封端点）。

### E. 最坏情况

**TC-VN-09 · 并发与关窗（P1）**
- 两请求并发升档：一成一败（`tier` 等值 + `changes()>0` 守卫），失败 409 可重试，无半套账。
- 关窗时低容量升档：不再 400「容量不足」，落到 409 `no_window`。
- `ledger_accounts` 无行 + 券抵扣：券守卫 `COALESCE(...,0)` 不误判，资金不足先拦。
