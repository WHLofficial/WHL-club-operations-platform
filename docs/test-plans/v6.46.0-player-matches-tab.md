## 最坏情况口径（铁律）

- **出场是四源并集，必须逐源可证**：① 该场有成长记录（appearance/rating/进球/助攻/零封/扑救任一行）② 该场赛事仓有该球员事件（含助攻）③ 该场球队**真实提交**的首发名单含该球员 ④ 该场伤病停赛名单（只计「缺阵」列、不计出场）。命中任一即计。**链式沿用不算**（赛事系统的 `tactic_submission` 未提交场次会按上一场算，那种「凑巧 11 人」不是本场首发）⇒ 必须要求 `starters.length === 11` 且 JSON 可解析，且只认 `status IN ('live','finished')` 的场次。
- **弃权场与未确认场必须整场丢弃**：丢弃发生在读确认行之前——`walkover_side` 非空、或没有 `result_confirmations` 行，则该场连成长记录一起不认（否则弃权场的脏录会把出场与均分顶起来）。
- **黄牌口径 = 排除同场两黄变一红的那张**：同场 `red_2y` 存在时该场 `yellow = 0`，但事件串仍要如实列出「黄牌 30′」与「红牌（两黄） 80′」（档案展示的是事实，计数按纪律口径）。红牌计数含 `red` + `red_2y`。
- **乌龙不计个人进球**；**伤退按场计上限 1**（同场两次受伤只算一次伤退）。
- **均分只统计有评分的场次**：`ratingCount` 必须一起返回；合计行是「该赛季全部评分场次的加权平均」，不是各赛事均分的算术平均（两者在不平衡样本下会差）。
- **门将零封/失球取 `result_confirmations` 的比分快照**，不取成长库 `clean_sheet`（后者只对有事件的防守位置球员写入、太稀疏）；且只有在 `side` 判得出、比分非空、且该场计出场时才累加——判不出就显示「—」而不是猜。
- **非 XP 场次只能录出场与评分**：`goal`/`assist` 会顶起里程碑 XP（`src/worker/growth.ts` 的累计 SQL 无赛事过滤），`duels_won`/`saves` 会污染跨场累计基数 ⇒ 这两类一律整批 400 拒收，且这些行 `xp` 一律写 0。这条是「XP 仍只在原范围产生」的落地方式。
- **评分放宽不能让 XP 出现负向或白拿**：`< 7.0` 记 XP 0（`xpForEvent` 表不动），区间外（负数、>10.0）整批 400；`duels_won` 0 合法、`saves` 正整数。
- **`:id` 兼容两种 id 不能混**：`players.id`（1–18301）与 `players.fc_id`（19541–279948）零重叠，端点先按 `fc_id` 命中、否则按内部 `id` 兜底；数字不合法一律 400「球员 ID 不对」、查不到一律 404。
- **侧别判不出时宁可「—」**：`conceded`/`cleanSheet` 只在 `side !== null` 时给值；队名兜底失败（两队名都落在「我方队名集合」里，例如该球员本季有 completed 转会）时 `side = null`，汇总不累加。
- **本地 TOUR_DB 是旧 schema**（缺 `tactic_submission`/`injury`/`injury_miss`）⇒ 端点本地必 500，e2e ㉑ 必须打桩，否则挂的是环境不是产品；真实端点由 `tests/player-matches.test.ts` 13 例覆盖。

## 实施期踩坑（写进代码注释与 e2e 头注）

1. **CSS 注释里绝不能出现 `*/`**：我写「赛事/出场*/均分」把注释提前闭合，esbuild 报 `Unexpected "*"` 两个语法警告（这是 `npm run build` 早先一直在报的既有噪声，本版顺手修掉）。
2. **窄屏副行别塞回「赛事」格**：9px 小字 `white-space:nowrap` 会把首列撑到 144px，卡内立刻横滑 56px（e2e 实测）。改法是副行独占一整行（`tr.matches-subrow > td[colspan=头数量]`），并加窄屏密度档（表 11px / th 11px 7px 5px / td 6px 5px / 徽章 min-width 40px）。
3. **窄屏不能用 `nth-child` 斑马纹**：每赛事两行（数据行 + 副行）会让奇偶错位 ⇒ 窄屏改由 JS 按赛事序号挂 `.matches-alt`，桌面仍用 `table.zebra`。
4. **e2e 取样前必须先落到同源页**：`E2E_ONLY` 单跑时页面还停在上一场景，相对路径 `fetch('/api/players?limit=1')` 报 `Failed to parse URL from /api/players?limit=1`。
5. **e2e 表头断言要容纳两种变体**：本地取样球员是门将（阿大），窄屏表头是 赛事/出场*/均分/零封/失球/黄牌/红牌 ⇒ 断言写成「前三列固定 + 其余 ∈ {场上四列, 门将四列}」。
6. **测试夹具的两条流水要错开**：`date`/`stageLabel`/`score` 相同会让 `getByText` 报 `Found multiple elements`；两条赛事的副行文案同理不能撞。
7. **`cleanSheetSide` 只是「本侧失球 0」的描述**，不受 `allowCounters` 影响，全仓无消费方——断言它等于把描述当开关，写测试时别误当联动结果（我第一版就断言错了）。
8. **`PlayerMatchesInput.teamNameById` 只装「我的队」**：测试若把两队都塞进去，队名兜底会两队同时命中 ⇒ `side=null`，用例得按真实取数行为构造。
9. **`node:sqlite` 拒绝双引号字符串字面量**（`no such column: "拉伤" - should this be a string literal in single-quotes?`）⇒ 夹具改用绑参。
10. **jest/vitest 的 5s 默认超时对 jsdom 重渲染用例偏紧**：`TC-ENTRY-E4`（51 行 × 51 次 `fireEvent`）单跑 4.5 s、全量并发时假失败 ⇒ 该用例显式 `}, 20000)` 并注明原因。
