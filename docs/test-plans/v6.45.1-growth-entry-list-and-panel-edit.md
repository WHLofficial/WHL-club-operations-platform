## 最坏情况口径（铁律）

- **赛果值为准**：`source='auto'` 的进球/助攻/赛果零封在录入台改不动；批量端点必须在**写任何一行之前**校验完（整批 400、零写入零审计），不允许「改了一部分才报错」。
- **重提同值永远是 no-op**：写入 0、XP 不加、`duplicates` 计数（HTTP 200）；只有 `written + updated > 0` 才 201。
- **改值差额可为负**：`players.growth_xp` 允许回退，`delta === 0` 时不下发 UPDATE（同档位改值不改 XP）。
- **累计项连带重算必须按录入序**：`duels_won`/`saves` 的 XP 取决于「此前累计值」，所以改一场要重放该球员同类型的**全部**事件（`ORDER BY created_at, id`），链上后续行的 `xp` 一并更新；否则历史各场的 XP 之和与实际累计值脱节。
- **在飞的保存不许被吞**：确认条点「保存并继续」时若上一笔行内保存还没落地，必须先 `await` 它再算脏行——否则那一行基线未前移会被判「不脏」而漏提交，或反过来被重复提交。
- **丢草稿必须先问**：收起面板、切换比赛、切换视图三条路径都会重挂/卸载面板，一律过 `guard`。
- **改值 ≠ 删值**：面板可改的是「换成另一个值」；把已录的手录值**清空**等于删事件（没有删除通道），提交会被 `toEntry` 跳过 ⇒ 这一行会永远算脏（基线是旧值、格子空着）却什么都存不进去。所以清空按**非法输入**拦下（行内红字 + 行内保存禁用 + `saveAll` 计入 skipped + 确认条「保存并继续」不放行），要么填新值、要么走「不保存，继续」丢草稿。
- 判不出/异常时宁可拒绝也不静默：改值失败的行逐行打红字（`失败：…`），不静默吞。

## 实施期踩坑（写进代码注释与 e2e 头注）

1. **e2e ⑭ 的 detach 超时不是产品 bug**：早前失败的轮次都在末尾回滚 SQL 之前就挂了，本地库留着手录 `rating` 行 ⇒ 面板一打开该格就带旧值且 class 已是 `recorded editable` ⇒「填值 + 等 class」这个等待条件打字当下即满足 ⇒ 保存还在飞就点「收起」⇒ 行基线未前移仍算脏 ⇒ 确认条拦住、面板不卸载（`locator.waitFor: Timeout 15000ms exceeded`）。产品侧修「保存并继续等飞行中保存」，e2e 侧改成等真实 POST 响应（`saveResponse` 由 `onSave` 兑现）。
2. **变异前先确认测试有牙**：M6 第一次只变异「按赛事」一侧，测试没红——用例只走正向切换；E3 扩成双向后即红。
3. **`errorText(res)` 一次用例只能调一次**（Body 只能读一次），否则抛 `Body is unusable: Body has already been read`。
4. **`wrangler deployments list` 输出旧→新**（看最新用 `tail`）；访问生产须 `curl --noproxy '*'`；`git status --short | grep -v '^??'` 无输出时 grep 退出码 1 会截断 `&&` 链。
5. **批量改写文档一律用 Edit 逐处改**：Node 脚本按「首个『）。』」取段会跨行吞掉整行（v6.45.0 回写时的事故）。
6. **可改值带来「清空」这个新边界**（code-review 发现）：`toEntry` 只带「非空且未锁」的字段 ⇒ 擦掉已录的手录值提交后端收不到该字段、什么都不写，但 `rowDirty` 拿空串比旧基线恒为真 ⇒ 确认条永远弹、「全部保存」反复无效。修法是把它当非法输入拦，而不是让它静默过去。
7. **test 里 mock 的「手动放行 promise」不要用 `let x = null`**：TS 对闭包内赋值不做流分析收窄，`x?.()` 会被推成 `never` 报 TS2349（vitest 因不做类型检查而全绿，只有 `npm run typecheck` 抓得到）⇒ 用 `const gate = { resolve: () => undefined }` 这类对象持有。
