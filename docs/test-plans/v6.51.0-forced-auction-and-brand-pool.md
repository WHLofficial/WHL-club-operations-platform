## 范围与风险

**In**：三道硬闸是否真的消失（门将 / 队内第七 / 缺 CA 各自 201 + 参考值字段）；保留的五道闸是否照旧（无归属 404、无窗 409、时刻表 `transfer_forced_auction` 段、CPU 队 400、状态非 normal / 已在市场流程里 400）；预检与建单**同源同文案**（预检的 `blockers` 与建单抛的 `error` 逐字相等）；预检**不写库**；参考值口径（`caRank` = 队内非门将 `ca` 严格更高者 + 1、`topSixLine` = 队内非门将 CA 降序第 6 名、`inTopSix` 三态、门将 / 缺 CA 记 `null`）；迁移 0071 的改名与扩编（`INSERT OR IGNORE` 幂等 + `naming_contracts` 兜底 UPDATE）；扩编对档位自动校准与招商轮报价量的连带影响（旧断言同步为 16 家口径）。

**Out**：本批的上线动作（迁移 `0071` apply 生产 + push + 部署 + 回读，待令）；管理端 v6.48.0 首次回填与时刻表真实时段（仍待用户操作）；插件仓的种子表（以平台迁移为准）；新品牌的档位长期走势（关窗自动校准每次重算）。

**最坏情况口径**：
- **删闸删过头**：把该保留的闸（无窗 / CPU 队 / 已在流程里）一起删掉 ⇒ 无窗也能挂单、CPU 队成交入账。闸门 = 三例既有用例（无窗 409 / CPU 400 / 已在流程 400）全部保留，并新增「预检与建单同句」断言。
- **预检与建单分叉**：两处各写一套判断 ⇒ 预检说「可挂」建单却 400。闸门 = 建单内部直接调 `inspectForcedAuction`（同一函数），用例断言 `blockers[0].message` 与建单 `error` 逐字相等。
- **预检写库**：预检顺手改状态 / 建挂牌 ⇒ 管理端一填 ID 就产生副作用。闸门 = 关窗 / 建前建后 `listings` 计数不变 + 预检用例断言 `COUNT(*) = 0`。
- **改名留半截**：只改 `brand_pool`、不兜底 `naming_contracts` ⇒ 历史合同品牌名与池脱钩（生产实测 0 行，但本地与未来导入可能带上）。闸门 = 迁移带两处幂等 UPDATE + 名单断言含「西维斯健康」且不含「CVS Health」。
- **扩编打破既有口径**：新品牌挤掉头部 / 新兴档位，或改变招商轮报价量而无人察觉。闸门 = `tests/naming-tiers.test.ts` 头部三家属地断言（新品牌热度最高 0.95 < 1.0 ⇒ 不进来）+ 招商轮 offerCount 全部改为 16 家口径。
