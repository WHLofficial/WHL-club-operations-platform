## 范围与风险

**In**
- **① 截断前缀层**：`matchRosterPlayer` 第六层 `'truncated-prefix'`——`truncatedNameKey(raw)`：trim 后尾部必须带省略号痕迹（`/(?:\.{2,}|…)$/`，剥痕），折叠成字母数字键（`nameKeyOf` = `foldName` 后去非 `[a-z0-9]`），键长 ≥ `TRUNCATED_KEY_MIN = 4` 才生效；在本侧花名册里找**唯一**前缀命中（`officialName` 或 `displayName` 任一前缀命中；命中 ≥2 ⇒ null）。
- **② 「不保存，继续」只丢当前队侧**：换队侧闸门只看当前队侧脏（`sideDirty`，面板 `useEffect` 上报 `onSideDirtyChange`）；`discardDrafts` 只重建当前队侧（`{ ...prev, [side]: buildSideRows(...) }`），另一队侧草稿保留；确认条文案同步改。
- **③ 截图上传改 JPEG 0.92**：2× 放大后 `canvas.toDataURL('image/jpeg', 0.92)`，超 `OCR_MAX_DECODED_BYTES`（4.5 MB）再降 0.8，仍超退回原图；PNG 编码路径删除（服务端 `decodeOcrImage` 仍收 PNG，兼容旧客户端）。

**Out（有意不做）**
- 提示词改动（不加「截断时猜全名」之类指令——模型照抄是**期望行为**，猜名会引入幻觉）。
- 无痕迹短名的前缀兜底（`'T. Alexander-Arn'` 不带 `...` 仍不认）：前缀匹配一旦不看痕迹，`'D. Carvajal'` 之类正常短名会去撞 `'D. Carvajal-XXX'`，宁缺勿错。
- 截断键长 < 4 的极端短名（如 `'A. So...'` ⇒ `aso`）：键太短前缀命中率过高，落回手填。
- 服务端后处理与模型侧优化：实测模型调用占全程 ~80-90% 且对体积不敏感（见「实测」），后处理纯计算 ≈0.4 ms。

**最坏情况口径**
| 场景 | 结果 |
| --- | --- |
| 截断键命中两支球员（同队 `Gabriel Martinelli` + `Gabriel Martins`） | 回 null ⇒ 照旧「认人失败…请在表内手填」（TC-MATCH-06 twin 花名册钉住） |
| 正常名恰好以 `...` 结尾 | 折叠键等于某球员全名键 ⇒ 前缀命中唯一 ⇒ 认回；生产 570 名 rostered 无 `.` 结尾名 |
| 换队侧时另一队侧有未保存改动 | 保留（本次修复的目标行为）；保存走「保存并继续」（两支一起提交）或回该侧单点保存 |
| 收起面板 / 切比赛 / 切视图 | 面板重挂，两侧草稿都作废（确认条文案已写明「丢弃全部草稿」） |
| JPEG 有损影响识别 | 5 张真图 PNG vs JPEG q92 逐行零差异（name/rating/goals/assists）；唯一差异 a3 的 `team` 由「利物浦」变「LIVERPOOL」⇒ 由 v6.51.8 的 FC26 英文名兜底接住（19/20 队命中） |
| JPEG 体积仍超上限 | 降 q80 再试；仍超 ⇒ 退回原图上传（服务端 5 MB 硬上限仍在） |

## 登记

**未验证项**
1. 真机体感：上传体积 ≈1/5 后「选图到出结果」的等待是否有感改善（模型侧 7.5-8.5 s 不变）⇒ 用户侧验收。
2. 截断兜底真机命中：重传利-曼图（`T. Alexander-Arn...` 那行应直接预填、不再出现在「认人失败」行）⇒ 用户侧验收。
3. 生产库其余 7 名 >16 字符长名（尤文 3 / 曼城 1 / 皇马 1 / 奥林匹亚科斯 1 / 慕尼黑1860 1）在真实截图上的截断形态未逐张验证（前缀唯一性已核对）。
4. 端到端墙钟：模型调用不可压缩（见「实测」），无进一步优化空间。

**口径**
1. 截断痕迹必须存在（`/(?:\.{2,}|…)$/`）才走第六层：模型在 JPEG 下仍照抄 `...`（探针实测），无痕迹的前缀匹配会误伤正常短名。
2. 唯一命中才认（`hits.length === 1`）：与 v6.51.3 队名对侧的「歧义不猜」同口径——多命中回 null 落手填，不引入二选一 UI。
3. 第六层排在 `surname-initial` 之后（最后兜底）：只对「前五层全落空」的截断名生效 ⇒ 现有认人结果逐条不变（无回归风险）。
4. 「不保存，继续」的丢弃范围按**当前队侧**（用户原文「当页」= 当前队侧页签）；收起/切比赛/切视图三路仍丢全部（面板重挂，草稿物理消失，文案已写明）。
5. 上传编码改 JPEG 0.92：视觉 token 由分辨率决定而非文件体积（PNG/JPEG prompt tokens 同为 6925）⇒ 账单不变、识别不变，只省上传字节与浏览器编码时间。
