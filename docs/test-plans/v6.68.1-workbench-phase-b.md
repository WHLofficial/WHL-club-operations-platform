## 1. 口径（实现即契约）

| # | 口径 | 落点 |
|---|------|------|
| 1 | 队列行：球员名 → `/players/<fc_id>` 链接；`IdTag 球员` 露内部 id；`IdTag 转会` 露 `transfers.id`；举报行 `IdTag 挂牌` 露 `listings.id` | `web/src/pages/admin/MarketPage.tsx` |
| 2 | 批量只处理 `transfer_confirm`；激活举报行不可勾（要逐条看截图） | 同上 |
| 3 | 批量上限 50 条、`ids` 去重、逐条处理；某条已处理 ⇒ 该条 `ok:false, error:'已处理'`，不影响其它 | `src/worker/routes/admin/reviews.ts` `POST /reviews/batch` |
| 4 | 批量不接改价：`body.fee` 被忽略（Q1 裁决），改价必须逐条走原端点 | 同上 |
| 5 | 每条仍写自己的审计，另写一条 `admin_review_batch` 汇总（`after.action / ids / ok / failed / note`） | 同上 |
| 6 | 键盘 `j`/`k`（或 ↑↓）移游标、`a` 批准、`r` 驳回、`Esc` 清选择；焦点在输入框内不触发 | `onQueueKeyDown` |
| 7 | `?listing=<id>` 一次性直达：只认正整数；命中当前在售列表才开浮层，否则静默忽略；参数用完 `replace` 清掉 | `web/src/pages/market/MarketBoardPage.tsx` |
| 8 | `?entity=transfer&id=` 定位并高亮队列行（2.6s 褪色）；`entity=listing\|bid\|session&id=` 预填干预框并滚过去。**transfer id 不塞进干预框**——那个框的按钮会把它当挂牌/出价/谈判解释 | `ReviewsSection` 的 `useSearchParams` 效果 |

## 2. In / Out

- **In**：队列渲染、键盘、批选、批量端点、`/market?listing=`、`?entity=&id=` 落地。
- **Out**：`/admin/workbench` 在途表、凭证查看、`0089` 迁移（期 C）；批量改价（永不做）。

| ID | 场景 | 期望 |
|----|------|------|
| TC-BAT-01 | 批量批准两条待审续约单 | 200，`results` 两条 `ok:true`，两单 `transfers.status='completed'`，`audit_log` 有 1 条 `admin_review_batch`（`ok:2, failed:0`） |

## 6. 已知边界

- 队列键盘没有单测（`ReviewsSection` 不是导出的独立组件，整页渲染要打桩 4 个 section 的查询）；TC-UIQ-01~05 走手动验收，设计文档 §5.3 有交互口径。
- 批选只覆盖当页（`GET /api/admin/reviews` 固定 `LIMIT 100`），跨页批选不做。
- 「去处置」对转发行是「定位 + 高亮」而不是「填干预框」：干预框的三个动作只认挂牌/出价/谈判 id，塞 transfer id 会点错动作。
