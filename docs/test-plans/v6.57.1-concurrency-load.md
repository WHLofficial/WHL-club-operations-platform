## 一、范围与目标

**In scope**：v6.57.0 额度线在并发下的三件事——
1. 读不变量：`available = balance − held + creditLine` 在任意并发交错下逐响应成立；
2. 写挤兑：K 个并发冻结申请争同一份额度时，恰好 `floor(available/F)` 单成功、其余被拒，**任何路径都不得超冻**（应用层预检 + 0081 触发器双层）；
3. 一致性：压测后冻结表/账本与快照对账吻合，触发器对绕过 HTTP 的直库写入同样拦截。

**Out of scope**：生产端到端延迟（需打生产，不做）；海捞/报价/续约其余冻结面（挤兑机制与出价同源，出价为代表路径）；长稳/疲劳（分钟级以上）。

## 三、用例

### TC-L-001 · 并发读：快照恒等式 + 吞吐（P0）

**前置**：种子完成后 `GET /api/club/balance` 200，`available` 与 `balance − held + creditLine` 一致。
**步骤**：16 并发 worker × 各 50 次 `GET /api/club/balance`（共 800 请求）。
**预期**：① 全部 200；② **每个**响应满足 `|available − (balance − held + creditLine)| < 0.005`（任一违反即 P0 失败）；③ 记录 p50/p95/max 与 req/s（登记数字，无硬阈值——本地 dev 口径供基线）。

### TC-L-002 · 并发挤兑：额度精确到 floor，绝不超冻（P0）

**前置**：读快照取 `available₀`；单次冻结 F=100；K=24 个并发 `POST /api/market/listings/:id/bids`（24 个不同挂牌 910101…910124，首价 ask 50 < 100，互不抬价）。
**步骤**：24 请求同刻并发（`Promise.all`）。
**预期**：① 恰好 `floor(available₀/100)` 个 200；② 其余全部 4xx 且文案含「可用资金不足」（路由预检 400 或触发器 `WHL_BID_REJECT_FUNDS` 映射 400，两形态都算过）；③ **零 5xx**；④ 事后快照 `held = held₀ + 100 × 接受数`、`available = available₀ − 100 × 接受数 ≥ 0`。

### TC-L-003 · 压测后对账（P0）

**前置**：TC-L-002 结束。
**步骤**：直库 `SELECT SUM(amount), COUNT(*) FROM fund_holds WHERE club_id=1 AND status='held' AND ref_type='listing' AND ref_id BETWEEN 910101 AND 910124`，与 HTTP 快照对账。
**预期**：SUM = 100 × 接受数；行数 = 接受数；与快照 `held` 差值恰为种子前既有的非本批冻结（本口径下应为 0）。

### TC-L-004 · 直库超冻被触发器拦截（P1，最坏情况：绕过应用层）

**步骤**：`wrangler d1 execute --local` 直接 `INSERT INTO fund_holds (club_id, amount, …) VALUES (1, 999999, 'held', 'listing', 910001, …)`。
**预期**：语句失败，错误含 `WHL_BID_REJECT_FUNDS`（0081 触发器兜底与 HTTP 无关）。

### TC-L-005 · 种子与清理幂等（P2）

**步骤**：连续跑脚本两遍。
**预期**：两遍结果一致（清理彻底、种子可重放，不因残留数据假红）。

## 四、风险与缓解

| 风险 | 缓解 |

**执行层踩坑（已修进脚本）**：① wrangler `--command` 带 SQL 被 shell 拆参（改走 `--file`，smoke.mjs 同款坑）；② wrangler 的 WARNING 走 stderr，stdout/stderr 拼接后 JSON 解析炸（只解析 stdout）；③ **CLI 直写本地 D1 后，dev 服务器第一条走 D1 的 HTTP 请求可能 ECONNRESET、随后自愈**（快照热身重试兜住，POST 不重试防双花）；④ 出价成功是 **201** 不是 200；⑤ 本机代理 env 会让 Node fetch 把 127.0.0.1 也丢给代理（脚本内删代理 env 直连）。
