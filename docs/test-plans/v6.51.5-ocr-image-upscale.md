## 范围与风险

**In**
- 上传前把截图等比放大 2×（最长边封顶 4096、已超长边不缩小）。
- 放大用浏览器原生 `createImageBitmap` + canvas（`imageSmoothingQuality: 'high'`），输出 PNG。
- 超限回退链：PNG 解码后 > 4.5MB → JPEG 0.92 → 仍超或环境不可用/解码失败 → 原图 base64。
- 页面 OCR 主路径与歧义选边重试都走同一份 base64（`fileToOcrBase64`）。

**Out（有意不做）**
- 不裁切（实测否决：队名区在裁切外）。
- 不改提示词、不改 `LLM_VISION_MODEL` / `LLM_VISION_MAX_TOKENS` / `thinking` 配置。
- 不做拼写容错层（编辑距离 / 近似建议）——放大已消掉已知两处固定误读，且用户上次已裁「暂时不做」。

**最坏情况口径**
| 场景 | 结果 |
| --- | --- |
| 浏览器不支持 `createImageBitmap` / canvas 2d 上下文取不到 | 退回原图 base64，识别照旧（与 v6.51.4 行为一致，不会更差） |
| 放大后解码体积超 4.5MB | 回退 JPEG 0.92；仍超则退回原图（服务端 5MB 上限不会被新代码撞破） |
| 原图已超 4096 长边或本来就很小 | 不放大、不缩小，原样送 |
| 放大算法与真机 canvas 有差异 | 单测里 canvas 是桩，像素质量只有真机能验 ⇒ 见「登记·未验证项 ①」 |
| 请求体变大后命中服务端 5MB 校验 | 回退链保证解码字节 ≤ 4.5MB（留 0.5MB 余量），且 400 文案不变 |

## 登记

**未验证项**
1. 真实浏览器 canvas 放大的像素质量与识别效果——单测把 canvas 当桩，只有管理端用 `E:\成长录入图` 4 张图复跑才能验收（预期认人失败清零；若仍有误读，下一步可试 3× 再考虑提示词侧「逐字照抄」规则）。
2. 超大/超长截图的回退分支在真机的行为（单测已覆盖逻辑，真机未构造）。
3. 移动端浏览器（`createImageBitmap` 支持面较窄）；不支持时退回原图，行为与旧版一致。

**口径**
1. 放大倍数固定 2×（实测 4/4 全对）；封顶 4096 长边，避免超出常见视觉模型的图像尺寸上限与解码内存。
2. 回退阈值取 4.5MB 解码字节（服务端上限 5MB，留 0.5MB 余量），超限先用 JPEG 0.92 而不是直接放弃画质。
3. 失败一律「退回原图」而不是报错——识别是辅助录入，宁可回到旧行为也不阻断用户。
4. 本轮实测的模型调用数：8（确定性复现）+ 4（full2x）+ 4（crop2x）+ 2（双线性）= 18 次探针调用。
