# v6.63.2 测试计划 · 海捞单直签训练营按 5m 违约金重算签入费

> 判级 **patch**（无迁移、无新端点、无存储形状变更；只加一条核心纯函数 + 成约前的一次差额结算 + 前端提示）。
> 需求真源：owner 口述两条（2026-10-31）——「海捞直接签训练营合同的，要检查海捞给的违约金是否小于 5，如果少，要按 5 违约金补收海捞费用差值」+「如果超过了 5 违约金也要退款」。
> 相关口径：规则 4.4.3（海捞签入费 = 新违约金 × 30%）、规则 4.3.4(1)（训练营条款固定 0.75m / 5m）。

## 1. 需求真源（锁定口径）

| # | 口径 | 出处 |
| --- | --- | --- |
| 1 | 海捞签入费在**审核通过**时按「提交的违约金 × 30%」收，此时还不知道最终合同形态 | 4.4.3 + `chargeBypassFee` |
| 2 | 直签训练营会把违约金落回固定 **5m**（不看提交价），训练营工资固定 0.75m | 4.3.4(1) |
| 3 | 因此训练营落定时签入费应以 5m 为基准 = **1.5m**：提交价 < 5m ⇒ **补收**差额；提交价 > 5m ⇒ **退还**差额；正好 5m ⇒ 不动 | 本版裁决 |
| 4 | 差额结算时点 = **直签训练营的成约动作里**、`settleActiveSession` 之前（与「签约谈判」时段闸同序） | 本版 |
| 5 | 补收不过资金闸（可支配含预期收入额度）⇒ 409 挡下，**不**允许白过成约；退款是入账，不设资金闸 | 沿用 `availableBalance` 口径 |
| 6 | 补收 / 退款都走 `ledger_entries`（kind `free_agent_fee_topup` / `free_agent_fee_refund`），幂等键 `(club, kind, transfer, refId)`；同批把 `transfers.extra_fee` 改成 1.5 | 沿用 `ledgerMovement` |
| 7 | 只作用于 `transfers.type='free_agent'`（海捞明标 + 暗标胜出同一条路）；续约 / 匹配 / 解约 / 激活 / 强制拍卖不受影响 | 本版 |
| 8 | 训练营合同本身仍不接受改违约金（400），本次不改该闸 | 既有 |
| 9 | UI 在谈判卡片的「直接签训练营」按钮下明示方向与金额：会补收 Xm / 会退回 Xm，合计 1.5m | 本版 |

## 2. 测试范围

**In**：差额函数单测、海捞 → 审核 → 直签训练营的端到端资金流（补收 / 退款 / 持平 / 资金不足四态）、前端提示文案（既有 jsdom 用例不回归）。

**Out**：明标段常规工资谈判成约（违约金仍是提交价，签入费不动）；暗标出标冻结口径（v6.50.0 既有用例覆盖）；训练营门槛（名额、年龄、PA）——本次不动。

## 5. 手工验收（上线后，不写生产数据）

1. 找一张 `type='free_agent'` 且 `status='signing'` 的海捞单（S9W2 待审 20 张过审后即进入该态），看谈判卡片是否出现「直接签训练营」下的差额提示。
2. 若提示「补收」：俱乐部可用资金不足时应被 409 挡下（文案含「要补收」），补足后可成约。
3. 成约后核对 `ledger_entries` 的 `free_agent_fee_topup` / `free_agent_fee_refund` 行与 `transfers.extra_fee = 1.5`、`contracts.release_fee = 5`。
