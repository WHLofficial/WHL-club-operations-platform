## 5. 风险与最坏情况口径

| # | 风险 | 防线 | 验证 |
| --- | --- | --- | --- |
| 1 | **只改提交侧拦不住审核扣款**——`approveTransferDeal` 现用 `rcChangeFee(ev.oldReleaseFee, transfer.fee)` 无上下文重算，豁免必须进 evidence 并在审核侧读 | 审核侧 `chargeBypassFee` 前读 evidence `freeRcChange` | M-01 / TC-RF-01 步骤 2 |
| 2 | **upsert 列清单残留旧值**——换队 `DO UPDATE SET` 逐列枚举漏加新列，用过机会的球员换队后新合同带 `used=1`（免费机会被偷走） | 列清单加 `free_rc_change_used = excluded.free_rc_change_used` | M-02 / TC-RF-04 |
| 3 | **apply 漏置 1**——免费通道永不消耗，无限免费 | apply 同批 UPDATE | M-03 / TC-RF-03 |
| 4 | **免费单误入退款循环**——4.4.10 退款按 `extra_fee > 0` 过滤，免费单 extra_fee=0 天然跳过；将来过滤条件改坏会对免费单退 0 元写流水 | 退款断言：免费单回滚后**无**退款流水 | TC-RF-07 |
| 5 | **免费通道放开守卫**——训练营 400 / 同窗一次 409 / RC 边界 / renewalRaise 基准被顺手放宽 | 守卫全部维持现状断言 | TC-RF-11 |
| 6 | **降价不消耗** →「降价白嫖保护期 → 提价又免费」双白嫖 | 消耗与方向无关 | TC-RF-03 |
| 7 | **apply 写 `used=1` 不带行守卫**（同批执行顺序里守卫读到已变更值）——沿用 `applyPendingContractChanges` 现行 pending 行守卫模式 | UPDATE 挂同批 + 行守卫（`status='pending'`），与效果语句同批同守卫 | TC-RF-01 步骤 4 断言同批性 |
| 8 | **闹涨薪 accept 的 NULL 与免费续约的 NULL 混淆**——两者 `protection_ticks_new` 都是 NULL 但语义同（不变）、source 不同（demand vs renewal） | source 收窄为 `('demand','renewal')`；demand apply 本就不碰该列 | RG-RF-02 |

### 6.1 详案

**TC-RF-01 首次免费提价全链路 — P0**
前置：球员合同旧 RC=15、`free_rc_change_used=0`；教练余额 < (20−15)×0.3=1.5（故意不足）。
1. 教练提交续约单（新 RC=20）。**预期**：201；transfers 行 `pending_review`；evidence 含 `freeRcChange:true`；无余额预检 400（免费跳过预检）。
2. 管理端审核通过。**预期**：**无** `rc_change_fee` 流水、余额分文不动、`rc_fee_charged_at` 不落；谈判会话以 `fixedReleaseFee=20` + `renewalRaise` 基准开启（E = expectedWage(20)×U(1.05–1.15)）。
3. offerWage 成约。**预期**：`contract_pending_changes` 行 `source='renewal'`、`free_rc_change=1`、`protection_ticks_new IS NULL`、`rc_fee=0`；contracts 三列一字未动。
4. 关窗 apply。**预期**：`release_fee=20` 生效；`protection_ticks` **保持原值**（COALESCE 接 NULL，不是重置为 baseTicks）；同批 `free_rc_change_used=1`；下一张续约单不再免费。

**TC-RF-02 二次提价恢复现状 — P0**
前置：TC-RF-01 完成后的合同（used=1）；教练余额充足组 / 不足组各一。
1. 再提交提价续约（20→25）。**预期**：pending `free_rc_change=0`、`protection_ticks_new=baseTicks`（4.4.6 收口）。
2. 审核通过（余额充足）。**预期**：`chargeBypassFee` 扣 (25−20)×0.3=1.5、写 `rc_change_fee` 流水、`rc_fee_charged_at` 落值。
3. 审核通过（余额不足）。**预期**：400 拒绝（免费时不可达的路径，非免费时恢复）。
4. 关窗 apply。**预期**：`protection_ticks` 收口为 baseTicks。

**TC-RF-03 降价同消耗 — P0**
1. used=0 的合同提交降价续约（15→10）。**预期**：pending `free_rc_change=1`（自动走免费通道，虽然降价本就不收费）、`protection_ticks_new IS NULL`。
2. apply。**预期**：`release_fee=10`、`free_rc_change_used=1`。
3. 随后提价续约（10→15）。**预期**：非免费——审核扣 (15−10)×0.3=1.5、保护期收口。

**TC-RF-04 换队卖出刷新 + B 买回刷新 — P0**
1. used=1 的球员被他队买走（`completeTransfer` 换队 upsert）。**预期**：新队合同行 `free_rc_change_used=0`（excluded 默认值）。
2. 该球员再被原队 B 分支买回（新签）。**预期**：合同行 used=0（同 upsert 路径）。

**TC-RF-05 match 成约不动列 — P1**
1. used=1 的球员经 match 流程成约。**预期**：UPDATE 不含该列，used 仍 1。

**TC-RF-06 闹涨薪接受不消耗 — P0**
1. used=0 的合同接受闹涨薪要求（source='demand' pending）。**预期**：apply 后 `wage` 新值生效、`free_rc_change_used` 仍 0；该球员随后提交续约单仍走免费通道。

**TC-RF-07 4.4.10 回滚不消耗 + 退款跳过 — P0**
1. used=0 的合同提价续约（免费单），在 apply 前 4.4.10 回滚（`rollbackRcChangeForPlayer`）。**预期**：pending 作废、`free_rc_change_used` 仍 0、**无**退款流水（退款循环按 `extra_fee>0` 过滤，免费单 extra_fee=0）、再续约仍免费。
2. 对照：used=1 的非免费提价单回滚。**预期**：30% 退款流水照旧（现行行为不回归）。

**TC-RF-08 离队 void 不消耗 — P0**
1. 有免费续约 pending 的球员离队（关窗批 void 分支，`void_reason='left_club'`）。**预期**：pending 置 void、不 apply、`free_rc_change_used` 仍 0；30% 不退亦不收（免费单）。

**TC-RF-09 A 分支买回用现值 — P1**
1. used=1 的球员被买走后 A 分支买回（本窗已闹买回、纯回归）。**预期**：合同行免费列**不被快照覆盖**（transfers 快照三列不含 `free_rc_change_used`）、买回后 used=1 沿用合同行现值；同场景 used=0 时买回后仍 0（不多不少）。

**TC-RF-10 兼容：evidence 无标记按非免费 — P1**
1. 构造 0085 上线前已在途的续约单（evidence 无 `freeRcChange` 字段）。**预期**：审核通过照扣 30%（按非免费处理）、pending `free_rc_change=0`。
2. 对照：降价在途单（evidence 无标记、fee 本就 0）。**预期**：不扣款、行为与现状完全一致。

**TC-RF-11 守卫不因免费放开 — P0**
1. 训练营合同提交续约。**预期**：400（免费通道不改变固定条款判定）。
2. 同窗已有 demand 行 / 在途续约单时再提交。**预期**：409（同窗一次守卫原样）。
3. 新 RC 越界（超出 RC 边界口径）。**预期**：400 原样。
4. 谈判基准：免费单的 offerWage 期望工资 E = expectedWage(新RC)×U(1.05–1.15)，与非免费单同公式。**预期**：基准不变。

**TC-RF-12 UI 提示 — P1**
1. used=0 的球员续约表单。**预期**：提交入口提示「本次免费：提价不收差额、保护期不变」。
2. used=1 的球员续约表单。**预期**：维持现状提示（提价收 30%）。
3. 免费单 pending 投影（`PendingContractView.freeRcChange`）。**预期**：渲染「本次免费」小字；非免费单不渲染。
4. 免费单 apply 后投影消失、合同页 RC 新值 + 保护期原值。**预期**：与 TC-RF-01 一致。

**TC-RF-13 迁移 0085 — P0**
1. 形状：`contracts.free_rc_change_used INTEGER NOT NULL DEFAULT 0`。**预期**：既有行读出 0（零回填即「还没用过」）。
2. 幂等：迁移重跑不报错、不重复加列。
3. `tests/d1.ts` 的 `MIGRATION_FILES` 已追加（否则夹具与迁移脱节）。
4. 回滚注释照 0028 模式（该列删除不损数据——机会是状态非资产，丢了只回到「已用」，可接受）。
