## 一、不变量

1. **顶栏双文案成对**：凡带 `aria-label` 的顶栏项都必须是 `.nav-tf`（全称）+ `.nav-ts`（短文案）双 span，桌面（>640px）显 `.nav-tf`、≤640 显 `.nav-ts`；CSS 两条显隐规则必须成对在场。`/market` 项桌面文案 = 「转会中心」、窄屏 = 「转会」（`innerText` 尊重 `display:none`，`textContent` 拼两段 = 「转会中心转会」）。
2. **开桌即读**：列表行（`OfferListItem` + 顶层 `club`）足以拼出完整单据头——球员名 / 当前有效价 / 首报与轮次 / 买卖双方 / `role` / `status` / `myTurn`；事件区在详情未到时必须显示「正在读取谈判记录…」，**不得**显示「这一单还没有事件记录。」（后者是「读完了、确实空」，误显会让人以为谈判记录丢了）。
3. **占位不进缓存**：`placeholderData` 只影响首帧渲染，不写进 TanStack 缓存；详情请求的 `queryKey`（`qk.offer(id)`）与请求行为不变；悬停/聚焦预取只预热缓存、不改任何状态（浮层不开）。
4. **合并只对只读入口生效**：`settleOverdue` 的 `coalesceMs` 是 opt-in——不传、传 ≤0、或显式传 `now` 时**永远真跑**；cron（`src/worker/index.ts`）、关窗（`src/worker/window-machine.ts`）、全部写路径都不传。30s 窗口内回上次 summary；并发请求共享同一次在飞结算；只有成功才记时刻（失败清在飞并照旧抛出）。
5. **写路径先结算**：`POST /api/offers`（及 counter/accept/reject/withdraw）与 `POST /api/market/listings` 在动作前先真结算 ⇒ 刚好到期的单先被收口、动作随后被拒（而不是「先按旧状态动作、下一 tick 才收口」）。
6. **往返预算**（`tests/settle-coalesce.test.ts` 计数版 D1，trips = `first/all/run` + `batch` 各一次）：详情冷读 **≤8**（实测 8，改前 13）、列表冷读 **≤8**（实测 8，改前 14）、两者合并命中 **≤4**（实测 3）。
7. **合批不改变语义**：结算三段扫描（expired / remnants / matchExpired）合一批的前提是「互斥或不可互生」——前两段按「有无出价」互斥；第三段新建的 `matched_pending` 行 `match_deadline` 恒在未来（`new Date(Date.now() + ctx.matchWindowHours * 3600_000)`）⇒ 本段扫不到。`active` 扫与 broken 自愈扫**保持单独**（它们读前面循环写的 `status`）。`expireStaleOffers` 的两扫**不合批**（第二扫带「同球员已有生效挂牌」相关子查询，而第一扫的循环会 `fulfillAcceptedOffer` 建挂牌行 ⇒ 后扫读前扫所写）。
8. **认证探针合一不改语义**：`getTeamBinding` 用 `LEFT JOIN team` 保住「绑了但 team 行缺失」⇒ `bound=true` / `clubId=null`；记忆化按 `Request` + `userId` 键控，失败不缓存；`requireCoach` 的 `locked` 短路顺序不变（locked 时零查询）。
9. **迁移只加索引**：`0067` 三条 `CREATE INDEX`（`idx_offers_status_id` / `idx_listings_status_type_activation_deadline` / `idx_listings_status_type_match_deadline`），无回填、无表结构变更；回滚 = `DROP INDEX` 三条；`tests/d1.ts` 的 `MIGRATION_FILES` 必须同步登记（`TC-MIG-03` 自动校验「登记的最新一枚 == 目录排序最新」）。

## 七、评审登记

1. **「开桌即读」为什么不用乐观渲染事件流**：事件流的顺序与轮次归属要靠服务端算（`myTurn`/`turn`），前端猜错会造成「显示已成交、其实还没」的误导。占位只覆盖**列表行已有**的字段，事件区给明确占位句，等详情替换——观感上「立刻有东西可读」，语义上不撒谎。
2. **为什么合并窗口是 30s**：结算的时效要求来自 cron tick 与写路径（都不合并）；只读入口 30s 内复用结果，最坏情形是「刷新一次看到上一趟的收口结果」，而写路径动作前必真结算 ⇒ 不会出现「按过期状态成交」。
3. **为什么不用 env 开关或 WeakMap(env) 键控合并**：前者要给 52 个夹具逐个加配置（对将来新用例不安全）；后者在生产 env 对象是否按请求重建不确定，可能让特性静默失效。取「模块级状态 + `resetSettleCoalesce()` 挂在 `createTestD1`」——与仓内 `resetGuards` 同款先例，生产靠 isolate 复用跨请求生效。
4. **认证探针合一的边界**：`src/worker/routes/admin/clubs.ts:603` 的 `getBoundClub(c.env, userId)` 保持不传 `request`——那里的 `userId` 是**目标用户**、不是会话用户，记忆化的语义不同。

## 八、注意事项
