## 0. 增量范围（用户四条指令）

1. （m01914）「上次扣工资时忽略了一点：顶级联赛未达53，次级联赛未达43工资的球队，扣工资时按53/43扣除，这个数字是对应级别工资帽-15」。
2. 用户四答：① 存两项帽值（68/58）、代码算「帽 − 15」，并把平台现有工资帽机制从全局单值改成**按级别**；② worker **永久生效 + 本次补扣**；③ 未定级不扣，且工资帽阵容限制也按级别显示；④ 上次的扣款**直接原地改**（不用补偿分录）。
3. （m02029）「cpu也不扣工资」——与奖金/主场收入/拍卖同口径：CPU 队不入账。
4. （m01899 + m02015）「修复消费中心过宽问题，排查类似问题」→「之前的计划呢，加上一起做」⇒ 窄屏修复与工资任务同批。

## 2. 用例

### TC-CAP-01 · 级别帽值默认与 config 覆盖（vitest，`config.test.ts` + `routes.test.ts`）
- `config.test.ts`：`getJson('wage_cap')` = `{ premier: 68, second: 58 }`（缺省不再是 null；`ca_pa_limits` 同款分套默认）。
- `routes.test.ts`：默认顶级 68 时 21 人注册 200 放行（夹具无 AUTH_DB ⇒ tier 走 `league_tier` 回落 premier）；插 `{"premier":20,"second":20}` 后同名单 422，`issues[0].rule === 'wage_cap'` 且 message 含「超出工资帽 20 m」；rules 空态断言 `{ squadMin: 20, wageCap: 68 }`。

### TC-FLOOR-01 · 窗末扣款按级别下限（vitest，`season-settle.test.ts`）
- 三队定级（`season_tournaments` + tour `entry`）：工资 49.23 / premier、37.62 / second、10 / 未定级 ⇒ `summary = { wageClubs: 3, wageTotal: 106, wageFloorClubs: 2 }`，流水 `−53 / −43 / −10`，memo 分别含「未达顶级下限 53 m，按下限扣」「未达次级下限 43 m，按下限扣」、未定级队 memo 无尾注。
- **边界（TC-FLOOR-02）**：工资**恰等于**下限（53）与**略高于**下限（53.01）都**不**按下限记 —— 额度同为实发工资、memo 无尾注、`wageFloorClubs = 0`（这道用例同时锁「下限值必须真是 53」：把 `WAGE_FLOOR_GAP` 改成 0 时它会红）。
- **覆盖值（TC-FLOOR-03）**：`config` 插 `{"premier":60,"second":58}` 后，工资 48 的顶级队**不再**按默认下限 53 扣 —— 实扣 48、`wageFloorClubs = 0`（证明扣款段真读 config，而非只吃常量默认）。

### TC-CPU-01 · CPU 队不入账（vitest，`season-settle.test.ts`）
- `clubs.is_cpu = 1` + 余额 200 + 单份 wage 3 ⇒ `summary = { wageClubs: 0, wageTotal: 0, taxClubs: 0, taxTotal: 0, wageFloorClubs: 0 }`、`statements` 长度 0（不跳过时工资 −3、富人税 −40 都会记）。

### TC-SHOP-01 / TC-SHOP-02 · 消费中心窄屏静态锁（vitest，`mobile-baseline.test.ts`）
- `.shop-main` / `.shop-side` 各声明 `min-width: 0`；`ShopPage.tsx` 用 `className="shop-main"` / `"shop-side"` 且**不再**含内联 `minWidth: 0`（内联会被 TC-SWP-02 固定宽禁令拦下）。
- `.seg` 有 `overflow-x: auto`（基块是 `overflow: hidden` 简写，不误命中）；`venueCards.tsx` 含 `flexWrap: 'wrap'`。

### TC-SHOP-03 · 375 几何闸（e2e ⑱ + ⑫）
- ⑫ 全路由 375 扫描：`/shop` 文档 `scrollWidth − clientWidth ≤ 1`（既有扫描，本版实测通过）。
- ⑱ 375 段：文档零溢出（失败时列出越界元素 `tag.class@right`）；`.seg` `{ overflow-x: auto, wrap: nowrap, scrollable: true, buttons ≥ 5 }`；子设施行 `display: flex`、`flex-wrap: wrap`、右缘 ≤ 视口 + 1（该行缺失时降级放过，避免误拦改版）。

### 回归套件
- vitest 全量 + `typecheck` 三份 tsconfig + `npm run build` + e2e 全量（24 场景）+ 375 截图目测（`scratch/e2e-shop-375.png`）。

### 变异验证（最小三枚，实测）
- **M1 · 下限少减 15**：`WAGE_FLOOR_GAP` 由 `15` 改 `0`（下限变成帽值本体）⇒ **2 红**（TC-FLOOR-01 与 TC-FLOOR-02，后者证明边界用例确实锁住下限值）；撤回后复绿。
- **M2 · 工资段去掉 CPU 排除**：`filter((w) => w.total > 0 && !cpuIds.has(w.club_id))` → 去掉后半句 ⇒ **恰 1 红**（TC-CPU-01）；撤回后复绿。
- **M3 · 删掉两栏的 `min-width: 0`**：`.shop-main` 去掉该声明 ⇒ **恰 1 红**（TC-SHOP-01）；撤回后复绿。
- **等价变异登记**：把下限判定 `total < floor` 改成 `total <= floor` **无红** —— 等号点上两支额度相同（都等于 `floor`），memo 尾注与计数都以 `charge > total` 判 ⇒ 该改法是等价变异，不是漏网缺陷。
