## 范围与风险

**In**
- **D 新索引**：`CREATE INDEX IF NOT EXISTS idx_growth_events_match_ref ON growth_events (match_ref, player_id)`。第二列不是可有可无——只建 `(match_ref)` 时面板那条 `WHERE match_ref = ? ORDER BY player_id, id` 仍要 `USE TEMP B-TREE FOR ORDER BY`（见「实测」）；带上 `player_id` 后三条 match_ref 查询全部走覆盖索引且无临时 B 树（非唯一索引末键是 rowid ⇒ match_ref 等值段内天然按 `(player_id, id)` 有序）。迁移登记进 `tests/d1.ts` 的 `MIGRATION_FILES`（守卫 TC-MIG-03 断言「目录内最新一枚 = 数组末项」）。
- **E 悬停预取**：列表行 `<tr onMouseEnter/onFocus>` 触发 `prefetchPanel(matchId)`——用与面板**同一个 query key**（`matchEntryPanelKey`）写入缓存，新鲜期 `PANEL_PREFETCH_STALE_MS = 30_000`（与 `web/src/main.tsx` 全局 staleTime 同口径）；已展开那场不重复拉；预取失败清掉缓存条目，点开照旧正常取数。

**Out（有意不做）**
- `growth_events` 其它列的索引：`player_id` 前缀查询（`src/worker/player-matches.ts:62`）已吃 UNIQUE 的 `sqlite_autoindex_growth_events_1`，不需要新索引（TC-IDX-05 反向钉住）。
- 面板内的其它请求（OCR、保存后失效）不加预取；触摸端（窄屏卡片视图）无 hover 语义，维持原样。
- 列表端点/面板端点的服务端缓存：数据随录入变化，失效成本高于收益。

**最坏情况口径**
| 场景 | 结果 |
| --- | --- |
| 索引带来的写放大 | 每次 `growth_events` 插入/删除多维护一棵 `(match_ref, player_id)` 索引；表量级（生产 731 行级）可忽略 |
| 迁移回滚 | `DROP INDEX idx_growth_events_match_ref;`（写在迁移头注释） |
| 迁移只建索引、未与代码同批上线 | 无风险：索引不影响任何写入/读取的语义（`IF NOT EXISTS` 幂等） |
| 预取失败（网络抖动 / 会话过期） | 缓存条目被清掉（`getQueryState(key)?.status === 'error'` → `removeQueries`），点开时照旧重新请求、错误由面板自己报，**不闪「面板加载失败」**（TC-ENTRY-E15） |
| 预取白拉（掠过 N 行 = N 趟） | 旧数据 30s 内新鲜、点开不重发；未点开的那些趟是纯浪费——面板响应 6 条本库 SQL，且只在鼠标真正掠过时发生（不做全列表预取） |
| 全局 staleTime 被改成 0（远期） | 预取仍按自己写的 30s 缓存数据，但面板挂载时会按全局口径重取 ⇒ 预取退化成白拉（注释里写明，改全局时要知道这条） |

## 登记

**未验证项**
1. 真机体感：预取命中时点开面板「几乎瞬时」、列表行掠过时不卡（预取是后台请求，不阻塞渲染）⇒ 用户侧验收。
2. ~~生产 `EXPLAIN QUERY PLAN`~~ **已核（2026-10-17 上线时顺带收口，见「上线记录」④）**：列表计数与面板行均走 `idx_growth_events_match_ref`、面板无 TEMP B-TREE。
3. 生产 `rows_read` 净变化：索引让三处 match_ref 查询从整表扫变 seek，预期显著下降，未实测。

**口径**
1. 索引列序 `(match_ref, player_id)`：第二列专为面板的 `ORDER BY player_id, id` 而加（末键 rowid 让等值段内天然有序）；只建单列也走索引，但排序仍要临时 B 树 ⇒ 两列更划算（多一列不改变 seek 能力）。
2. 迁移文件内不写 `BEGIN`/`COMMIT`（执行器自行包事务，同 0059/0069/0070/0071 约定）；用 `IF NOT EXISTS` 保证可重放。
3. 预取写进面板同一个 query key，而不是另立缓存：面板挂载时直接命中，且失效逻辑（保存后 `invalidateQueries`）自动一致。
4. 新鲜期显式写 `30_000` 而不是读全局配置：预取的价值完全依赖「点开时数据还新鲜」，与全局 staleTime 耦合但不想被静默改掉（注释已说明）。
5. 预取只在 `onMouseEnter`/`onFocus` 上触发（`onFocus` 借 React 的 focusin 冒泡覆盖键盘路径），不做滚动可见性/空闲预取——收益不足以换复杂度。
