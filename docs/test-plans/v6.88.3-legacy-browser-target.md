# 测试计划 · v6.88.3 构建目标降级（旧内核兼容）

日期：2026-11-21
增量：`vite.config.ts` 的 `build.target` 由 Vite 默认 `es2020` 降到 `chrome79` / `safari13`。

## 背景与目标

红米手机上百度 / QQ 浏览器打开站点只有背景色。根因是产物含 474 处 `??`（Chrome 80+），旧内核解析期 SyntaxError，整个 bundle 不执行。目标是让 Chromium 79+ 内核能完整执行首屏脚本。

**In scope**：首屏主包与全部懒加载 chunk 的语法降级、体积增量、配置静态锁。
**Out of scope**：Chrome 61–78（需 `@vitejs/plugin-legacy`，本轮未授权）；`:has()` 等 CSS 特性的旧内核表现；真实机型复测（无设备）。

## 测试用例

### TC-BT-01 构建产物语法降级（P0）

- 前置：`npm run build` 成功。
- 步骤：扫描 `web/dist/assets/*.js`，统计 `??` 与 `?.` 的语法出现次数（排除字符串 / 正则内）。
- 预期：主包 `index-*.js` 的 `??` = 0、`?.` 语法 = 0；`xlsx-*.js` 的 108 处 `??` 均在字符串常量（Excel 格式 `# ??/??`）内。
- 实测：主包 `??` 0 / `?.` 1（正则字面量）；xlsx 108 处全部为字符串；34 个 chunk 无语法残留。

### TC-BT-02 体积增量（P1）

- 步骤：对比构建日志的 gzip 体积。
- 预期：主包 gzip 增量 ≤ 10 KB。
- 实测：234.70 KB → 239.75 KB（+5.05 KB）。

### TC-BT-03 配置静态锁（P1）

- 步骤：`npx vitest run tests/build-target.test.ts`。
- 预期：3 例通过（chrome79 在列、safari13 在列、无 `esnext`）。
- 实测：3/3 通过。

### TC-BT-04 类型与回归（P0）

- 步骤：`npm run typecheck` + `npm test`。
- 预期：三份 tsconfig 零错、全量用例全绿。
- 实测：typecheck 全清；222 文件 / 3435 例通过。

### TC-BT-05 旧内核可执行性复核（P1）

- 步骤：`esbuild web/dist/assets/index-*.js --target=chrome79 --log-level=debug`。
- 预期：无 `Transforming` / `error` / `warning` 输出。
- 实测：零输出。

### TC-BT-06 真机复测（P0，未执行）

- 前置：红米设备 + 百度浏览器 / QQ 浏览器。
- 步骤：打开 `https://club.whleague.win`。
- 预期：正常渲染首屏，不再只有背景色。
- 状态：**未执行** — 需部署后由用户真机验证。

## 风险

| 风险 | 概率 | 影响 | 处置 |
|---|---|---|---|
| 内核低于 Chromium 79 | 中 | 仍白屏 | 需 `@vitejs/plugin-legacy`，另立增量 |
| `:has()` 规则被旧内核丢弃 | 高 | 个别样式细节 | 不影响渲染，登记不修 |
| 懒加载 xlsx 在旧内核报错 | 低 | 导出功能失败 | 字符串内 `??`，非语法，实际不触发 |

## 回归套件

- `npm test`（全量）
- `npm run build`
- 上线后：`/api/health` 200、线上首页资产 hash 与本地一致、真机复测 TC-BT-06
