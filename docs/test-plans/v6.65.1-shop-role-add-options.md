# 测试计划 · v6.65.1 消费中心「角色（职责）」新增下拉枚举修复

## 背景与范围

owner 报障：消费中心 → 角色（职责）→ 新增，永远显示「热区下没有可新增的角色」。根因：`web/src/pages/shop/ShopPage.tsx` RoleCard 的 `roleOptions` 枚举写死 `[1, 2, 3, 4, 5]`（角色全表 49 个基础 ID 只覆盖 GK×2 + RB×3），v6.26.0 建档当天写死、一天起缺陷。服务端 `src/worker/shop-ops.ts` 本就按 1–149 全表校验，零改动。

**In scope**：前端新增下拉选项集合（热区过滤 / 去已拥有 / 单加号+双加号拼段）、GK/RB 球员行为不变、升级与去除操作不受牵连。
**Out of scope**：服务端 role add 校验（已有 `tests/shop-orders.test.ts` 覆盖，本轮零改动）、价格与工单链路、其他商品页签。

## 用例

### TC-R1 ST 球员新增下拉出全段角色（P0，变异锚）

**前置**：squad-state 有一名 ST 球员（`zones: ['ST', null, null, null]`、`roles: []`）；窗口开。
**步骤**：打开 `/shop?tab=role`，选该球员。
**预期**：新增下拉占位文案是「选角色…」（不是「热区下没有可新增的角色」），选项恰为 ST 段 4 个基础角色 ×2 档 = 8 项（含「突前前锋 +」「突前前锋 ++」「禁区之王 +」「伪九号 +」「站桩中锋 +」及其 ++）；选中「突前前锋 ++」后提交按钮可用。

### TC-R2 已拥有角色判重按基础段、标签不双写（P1，变异锚）

**前置**：同上球员已有 `roles: [{ slot: 1, roleId: 41 }]`（突前前锋 +）。
**步骤**：同 TC-R1。
**预期**：突前前锋**两档**（41 与 141）都不在新增下拉——同角色判重按基础段（与服务端一致），升双加号必须走「单加号升双加号」操作；其余 ST 角色 3 个 ×2 档 = 6 项照常。**变异锚**：去掉 ownedBases 过滤 ⇒ 此例红。另断言「现有角色」行的标签是「第 1 槽 ST 突前前锋 +」且全文无「++ ++」（roleLabel 双写后缀修复）。

### TC-R3 GK / 多热区球员行为（P1）

**前置**：a) GK 球员 `zones: ['GK', null, null, null]`；b) 外场球员 `zones: ['ST', 'RB', null, null]`（主位 ST + 热区 RB）。
**预期**：a) 下拉出 GK 段 3 基础 ×2 档 = 6 项（门将 / 清道夫门将 / 出球型门将 ±）——修复前写死枚举连出球型门将（45）都吞掉、只有 4 项；b) 下拉同时出 ST 段与 RB 段共 18 项（RB 含边后卫 / 伪后卫 / 边翼卫 / 进攻型边翼卫 / 内切型边后卫 5 个基础，修复前一项都不出现）。

### TC-R4 升级 / 去除操作不受影响（P2）

**前置**：球员 `roles: [{ slot: 1, roleId: 41 }, { slot: 2, roleId: 141 }]`。
**预期**：「单加号升双加号」只列第 1 槽（41）、「去除」列两槽；提示文案（「没有单加号角色可升」「没有角色可去除」）分支照旧（无角色球员）。

### TC-R5 服务端校验回归（P0，回归套件）

**预期**：`tests/shop-orders.test.ts` 既有用例全绿——角色归属位置拦截、同角色重复拦截、槽满拦截、upgrade/remove 分支零变化（本轮服务端零改动，作回归确认而非新断言）。
