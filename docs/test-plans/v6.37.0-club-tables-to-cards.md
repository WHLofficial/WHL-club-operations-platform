## 范围

**In**：位置四组分组（`groupRowsByPosition`）、行内徽章（`inlineBadgesOf` 优先级）、激活价镜像（`activationFeeOf`）与金额整数化（`moneyIntText`）、指标视图四 chips + 桌面 13 列（`CARD_VIEW_CELLS` / `DESKTOP_CELLS`）、额外列池与 `parseCardExtras`、共享组件 `card-parts.tsx`（CardGroup / SquadCard / RegCard / AssignmentSelect / ViewChips）、SquadTab 与 DeskTab 双端重构、styles.css `.sqc-` 段与两段死粘列 CSS 摘除、mobile-baseline 闸门同步。
**Out**：球员库主表（PlayersLibrary 沿用路线 A 卡片流，不在本轮）、其余 12 处表格（横滚维持现状）、管理端、后端 API 行为（`/api/players` 与 `/api/club/squad` 只补 influence 下发，已有测试覆盖）。

## 最坏情况口径（铁律）

- **窄屏与桌面是两套 DOM**（`useMediaQuery('(max-width: 760px)')` 互斥分支），jsdom 恒走桌面口径 —— 窄屏 DOM 的断言只能由 e2e 三视口（390/768/1280）兜底，单测不得假装覆盖了窄屏。
- **jsdom 无 `showPopover` / 无 `matchMedia`**：HAS_POPOVER 兜底路径与 matchMedia 桩（恒 false = 桌面）是本版测试基座；挂了真 Popover API 的浏览器行为（弹层逃逸裁剪）只由 e2e/真机验收。
- **旧 URL 脏参**：`?cols=wage` 这类已进内置 13 列的旧参数，`parseCardExtras` 必须滤掉（防内置列重复渲染两格）。
- **组序稳定**：空组丢弃、未知位置/null 殿后「其他」——20 队真实数据里 `positions` 为空的球员（含自由身/训练生）必须落「其他」而不是消失。
- **金额口径分叉**：违约金/激活价整数化（去尾零不取舍），工资保持 `money()` 两位小数 —— 两套口径不许互串。

## 变异验证计划（定向打红，按最坏情况口径选点）

实测（2026-10-06，还原后四个受影响文件 102/102 全绿）：

1. `groupRowsByPosition` 丢掉 unknown 档 → **2 红**（TC-GRP「其他殿后」+ ClubDetail 集成「位置四组容器」）。
2. `inlineBadgesOf` 把无合同提到链首 → 首轮**空转**：夹具里无合同 × 四态无交叉行，相对顺序没被钉。补交叉断言「`hasContract:false` + `notForSale` → 非卖品在前」（club-cards.test.ts 注册行用例）后 **1 红**。
3. `activationFeeOf` 非保护改 ×1.5 → **2 红**（激活价镜像 + 取值口径）。
4. `parseCardExtras` 去掉内置键过滤 → 首轮**空转**：第一版夹具用 `wage`，但 wage/releaseFee 在 `parseClubColsParam` 上游就被滤掉；该过滤真正拦的是「仍在可选池内的内置键」（marketValue/baseCa 等）。夹具改 `marketValue`/`baseCa` 并新增 parseCardExtras 单测（club-columns.test.ts）后 **1 红**。
5. 死选择器探针（`:has(td.marker-cell)` 残影）塞回 styles.css → **1 红**（mobile-baseline v6.37.0 死选择器回归锁逮住）。

两个空转各补了一枚钉子（交叉断言 + parseCardExtras 单测），属变异验证净收益。
