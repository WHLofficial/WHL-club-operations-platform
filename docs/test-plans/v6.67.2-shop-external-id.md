# v6.67.2 测试计划 · 消费工单外部录入：提示可见 + FC id 兜底

- **判级**：minor（两处静默失败 + 一处可用性；不动资金、不动归属、零迁移）
- **需求真源**：管理员反馈 2026-11-02「为什么消费工单外部录入不起效果。」→「静默没反应」→「弹了并点了确定却还是没单」→「我填的33/256196的金滑铲徽章」
- **计划文档**：`memory/plan-v6.67.2-shop-external-id.md`（grilling 裁决 Q1–Q6 见该文档）
- **范围**：服务端 `loadPlayer` 的球员键兜底 + `/admin/shop` 两处 `toastNode` 渲染 + 队壳单「取消」被吞 + 输入提示与回显。
  **不含**：把 `confirm` / `prompt` 换成卡内二次确认（Q1 明确不做）、club 侧 `/shop` 购买链路、`parseShopPayload` 各分类范围校验、任何迁移

## 1. 口径（实现即契约）

| # | 口径 | 落点 |
| --- | --- | --- |
| 1 | 球员键先按本地 `players.id` 查，命中即用（行为与 v6.67.1 一致） | `loadPlayer()`（`src/worker/shop-ops.ts`） |
| 2 | 本地 id 未命中时按 `players.fc_id` 再查一次（生产 18,301 行无空值、无重复） | 同处 |
| 3 | 本地 id 命中但 `club_id` 不符 ⇒ 400 `球员不属于你的俱乐部`（不变） | 同处 |
| 4 | `fc_id` 命中但归属不符 ⇒ 400 `这个 FC id 属于俱乐部 #N，不是俱乐部 #M` | 同处 |
| 5 | 两种键都未命中 ⇒ 404 `找不到这名球员（本地 id 或 FC id 都没有这条记录）` | 同处 |
| 6 | 兜底对五个分类（pa / badge / badge_upgrade / role / position）一律生效；`club_shell` 不查球员 | 同处（`prepareShopPlan` 共用） |
| 7 | `/admin/shop` 页面级与「外部录入」卡各自渲染自己的 `toastNode`；两个 `useToast()` 实例互不相通 | `web/src/pages/admin/AdminShopPage.tsx` |
| 8 | 创建失败必须看得到红字 toast（400 / 403 / 404 / 409 都走同一条 `catch`） | 同处 |
| 9 | 队壳单审批时 `prompt` 返回 `null`（取消）⇒ 直接中止，不得继续通过 | 同处 `approve()` |
| 10 | 队壳单 `prompt` 返回空串（确定但留空）⇒ 备注为空，继续走确认 | 同处 |
| 11 | 球员输入框 placeholder = 「球员 id / FC id」；成功 toast 沿用 `summary`（含球员名） | 同处 `ExternalCreateCard` |

## 2. In / Out

- **In**：口径 1–11；`fc_id` 命中本队 / 命中别队 / 两键皆无三种分支；外部单创建 → 确认执行生效落点；队壳取消分支。
- **Out**：club 侧自助下单（球员来自本队名单，不经该入口）、`window.confirm` 依赖改造、前端单测（该页此前无测试文件，见已知边界）。

## 6. 已知边界

- 前端 toast 渲染与「取消被吞」没有自动化用例：`AdminShopPage` 此前无测试文件，为它搭 QueryClient / fetch mock 的成本高于本次收益；上线回读时人工确认一次「填错 id 会弹红字」。
- 审批 / 拒绝仍依赖 `window.confirm` / `window.prompt`（Q1 裁决不改造），浏览器抑制弹窗时仍会表现为无反应。
- `fc_id` 兜底只在「本地 id 未命中」时生效：若某球员本地 id 恰好等于另一球员的 `fc_id`，优先按本地 id 解释（保持既有语义，不做歧义提示）。
