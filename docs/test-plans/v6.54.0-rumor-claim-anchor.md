## 7. 风险与最坏情况

- **最坏情况：买方真料为零但页面看不出**——`offers` 是内部表、`bids` 只在 listing 详情里；若 query 9/10 漏窗口或角色过滤，出价族永远空，玩家只看到卖方三族，以为“买方传闻没做”。→ TC-23/25/26 + D1-RUMOR-01。
- **最坏情况：自由身真料变成不可核对的“内部消息”却仍被当有据**——`offers` 不公开，玩家点不进去；文案若写“可在报价页查证”就是欺骗。→ TC-25/26 文案断言 + §2.4 的 public/internal 分级。
- **最坏情况：真假可由 id/主体归属反推**——id 槽位固定，若 `id` 不带 secret，玩家能按 id 猜位；若无据行总是指向非现东家，主体归属就是侧信道。→ H4 secret + TC-05/11 按族锚点判定。
- **最坏情况：统计帧自己证明自己**——帧行数就是 `m_s`，拿帧 vs 目标做卡方永远 p≈1；必须用球员级置换/低 CA 覆盖。→ TC-27。
- **最坏情况：候选表失败后悄悄直算，D1 读量翻倍**——直算 3.63M/天叠加峰值 5.66M，破 5M；必须 503/旧 ready，不直算。→ TC-29 + CAP-03。
- **最坏情况：缓存 epoch 被市场写打穿**——`cachedJson` 全局 epoch 会让每次市场写后两个 colo 各 miss 一次，响应成本 1.52M/天；必须 `cachedRumorResponse` + `cachedFrame` 独立。→ TC-08/22。
- **最坏情况：P0-0 只改写入不改读侧/通知**——自由身 offer 写入成功但详情 404、过期通知仍说“冻结已退回”。→ TC-25/30 + P0-0 清单。
