## 0. 范围与口径

**B4 交付面（测试只对这些负责，F 编号反推自施工表变异 M1…M6）：**
1. F1：`completeCloseStep`（window-close-runs.ts:469-488 现状无守卫）与 `completeCloseRun`（:354-370）的 step 语句加 `AND status <> 'done'`——对已 done step 零改行。
2. F2：`markCloseStepFailed`（:327-344）的 run 语句（现 `WHERE id = ? AND status <> 'completed'`，:338-341）加 `AND lease_owner = ?`——偷租后旧持有者的失败收口不清新持有者租约、不翻 run。
3. F3：新原语 `renewCloseLease`（CAS 续租：owner 匹配 changes=1、不匹配 changes=0，T07 附加单元 :720-738 同款风格）。
4. F4：六个段提交点（window-machine.ts 的 preflight 收口批 :770、payroll :822、home :833、loyalty :842、squad_audit :855、finalize :889）前调 `assertCloseLeaseHeld`——租约易主抛 409（`CloseLeaseLostError`）；外层 catch（:972-981）对该错误**跳过 `markCloseStepFailed`**（TC-B4-03 断言口径）。
5. F5：`loadCloseSteps`（:678）后的洞校验——steps 必须是「前缀 done」形状（首个非 done 之前全 done），洞态抛 409 含「跳段」文案。
6. 恢复 parity 行为锁（非新功能）：resume 重建的 loyalty 段读「home 段批已提交的 apply 后合同」，与干净整窗的金额漂移按计划 §10.8 第 1 条登记口径钉死（TC-B4-05）。

**硬边界（硬禁，断言里显式锁）：**
- B4 落地不得改 T01–T17 / TC-B3-* 的既有断言面（TC-B4-02/11 回归令）；`CLOSE_STEPS` 七段、claim 三语句、closing 冻结判据（window-guard.ts:25 只读 `season_windows.status`）一律不动。

## 2. 用例（TC-B4-01 … TC-B4-18）

### TC-B4-01 并发 claim：同 tick 两次 POST close · P0 · 文件 tests/window-close-recovery.test.ts（新建）

- **操作**：局 R：`await Promise.all([post('/api/admin/windows/close', {}, 'tok-admin', env), post('/api/admin/windows/close', {}, 'tok-admin', env)])`（同 tick 两请求，见 §0 竞态口径）；局 S：单次 POST。
- **断言**：
  1. 局 R 两响应**恰一个 200、一个 409**，409 文案含「关窗正在处理」（不钉哪个先发起——§0 口径）；
  2. 局 R 库态 = 干净完成态：窗 closed、run 恰 1 行 completed、steps 恰 7 行全 done（claim 批恰好生效一次的间接锁——先到者 changes=1、后到者读已有 run 不重建）；
  3. **零业务写入对账（超出 T01 只对账 run/step 行的面）**：局 R 与局 S 的 `ledger_entries` / `window_close_notifications` / `audit_log` 逐表行数完全一致（seedWindow 形状下预期：outbox 0 行、`window_close` 审计 1 行、流水 **wage 1 行**（seedWindow 仅 clubA 有合同，tests/window-close-runs.test.ts:150-151 仅合同 1）**+ maintenance 0 行**（seedWindow 无 stadiums 行，home 段维护费按球场行数计，home.ts:576-582——评审 fixHint 的「maintenance 2 行」是 parity `seedClubsAndSquad`（:142-144）的形状，与 seedWindow 不符，按核实登记）；断言本体为两局逐表等值，不钉绝对值）；
  4. 局 R 的 200 响应体与局 R `JSON.parse(run.summary_json)` 逐字段相等（回执同源）。
- **红/绿**：无施工前红（行为锁：现状 claim 写闸 + acquire CAS 已保证恰一胜者）；完成后绿。M3 注入不波及本例（围栏在 claim 之后）。

### TC-B4-03 偷租围栏端到端（等价 B 过 TTL 接管后旧持有者被围栏）· P0 · recovery
- **前置夹具**：主局 = `seedWindow()` + `UPDATE season_windows SET is_temporary = 1 WHERE season = 1 AND window_seq = 1`（**临时窗裁决**：temp payroll 批只含富人税、余额 100 不触税（window-payroll.ts:6/:61-64）⇒ payroll 批零业务语句，「零段批业务写入」断言才可满足；常规窗下 wage 必在场、与断言 4 矛盾）+ 关窗前装偷租触发器（等价 B 过 TTL 接管——在 payroll step done 落库瞬间偷换租约为未来时刻）：
  ```sql
  CREATE TRIGGER steal_b4 BEFORE UPDATE ON window_close_steps
    WHEN NEW.step = 'payroll' AND NEW.status = 'done'
    BEGIN
      UPDATE window_close_runs SET lease_owner = 'thief', lease_expires_at = '2999-01-01T00:00:00.000Z'
        WHERE id = NEW.run_id;
    END;
  ```
  （SQLite 默认 `recursive_triggers=OFF`，触发器内的 runs UPDATE 不会再点火 runs 上的触发器。）
- **操作**：`POST /api/admin/windows/close`（tok-admin）。执行序：preflight 收口批提交（preflight done）→ payroll 提交批内 `completeCloseStep(payroll)` 点火偷租（批照常提交：temp payroll 无业务语句）→ home 提交点 F4 围栏读到 `lease_owner='thief'` ≠ 本手 → `CloseLeaseLostError` 409 → catch 跳过 `markCloseStepFailed` → 让位。
- **断言**：
  1. HTTP **409**（文案按 B4 定稿回填断言，写作时点未定稿——只锁 status）；
  2. steps：preflight、payroll **done**（attempt=1）；home/loyalty/squad_audit/finalize/post_close 全部 **pending 且 attempt=0**（CloseLeaseLostError 跳过 markCloseStepFailed 的直接后果）；
  3. run 行：`status='running'`（非 failed）、`current_step='home'`（payroll 批的推进已提交）、`lease_owner='thief'`、`lease_expires_at='2999-01-01T00:00:00.000Z'`（F2/F4 未触碰新持有者租约）；
  4. **零段批业务写入**：`ledger_entries WHERE ref_type='window' AND ref_id=101` 0 行、`audit_log WHERE action='window_close'` 0 行、窗仍 closing；
  5. **对照局**（证明触发器本身不破链路）：同夹具去掉 `steal_b4` 跑一次完整 close → 200、7 段全 done、窗 closed、维护费每队恰 1 行。
- **红/绿**：施工前红（无 F4 围栏 ⇒ home 批照常提交，断言 2/4 红）；完成后绿；**M3 注入 → 断言 2/4 红**（home 流水出现、后段被推进）。

### TC-B4-04 旧持有者 catch 不清新租约（F2）· P0 · recovery
- **前置夹具**：`seedWindow()`（**常规窗**——本例要 payroll 批真提交工资，与 TC-B4-03 的 temp 裁决相反）+ 双触发器同装：偷租触发器（同 TC-B4-03 的 `steal_b4`）+ 深层炸弹 `CREATE TRIGGER fail_b4_loyalty BEFORE UPDATE ON window_close_steps WHEN NEW.step='loyalty' AND NEW.status='done' BEGIN SELECT RAISE(ABORT,'boom-loyalty'); END;`（B2-05 :609-611 同款、打点 loyalty）。
- **操作与断言**（三相）：
  - **phase 1（围栏先手，端到端）**：POST close → 409（home 提交点围栏先于 loyalty 段触达——RAISE 已挂但不可达，这是 F4 先手性的行为锁）。断言：run `status='running'`、`lease_owner='thief'`、`lease_expires_at` 非空且 = '2999-…'；preflight/payroll done（**工资流水在场**——常规窗 payroll 批已提交，与 TC-B4-03 的零业务写不同，此处如实登记）；home/loyalty/squad_audit/finalize/post_close pending 且 attempt=0（**loyalty step 保持 pending**：围栏先手，炸弹未触达）。
  - **phase 2（F2 直接面）**：旧持有者串在 HTTP 层不可观测（owner 含 UUID，window-machine.ts:661）——用任意 ≠ 'thief' 的哨兵串（如 `'owner-old'`）模拟旧持有者 catch：直调 `markCloseStepFailed(db, runId, CLOSE_STEP_LOYALTY, new Error('boom-old'), 'owner-old')`（B4 后签名带 owner；若实现不带走参 owner 则本相退化为「SQL 直改 owner 后直调现状签名」并在收口登记）。断言：run 仍 `status='running'`、`lease_owner` 仍 `'thief'`、`lease_expires_at` 原值逐字不变（**F2 CAS 生效：新持有者租约未被旧持有者 catch 清掉**）。登记：markCloseStepFailed 的 **step** 语句若不同时带 owner 守卫（施工表 M2 字面只守 run 语句），phase 2 会把 loyalty step 标 failed attempt=1——该 step 终态不作 F2 判据，两种落地都合法，收口按实际登记。
