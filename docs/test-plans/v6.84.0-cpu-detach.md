## 1. 口径

| # | 口径 | 落点 |
| --- | --- | --- |
| C1 | 只允许 `status='active'` 的队；预检与写操作都重新查，不信快照 | `GET /clubs/:id/to-cpu`、`rename-local` |
| C2 | 保留阵容与合同；现金与消费券退出流通，余额/券归零并各留一条负数流水 | `ledgerReclaimAll`、`voucherReclaimAll` |
| C3 | 阻断项 12 类：active 谈判、未终态挂牌、pending/intent 报价、pending_review/signing 过户、待签合同诉求、held 资金、open review、pending 事件、pending 消费工单、active 冠名、当前 open 窗档期、名字冲突/超长 | `CPU_DETACH_CHECKS` |
| C4 | 置 CPU 后教练侧全部 403；管理员兼绑也不放行；管理端 `/api/admin/*` 不受影响 | `requireCoach` + `assertNotCpuClub` |
| C5 | `unbind-all` 必须 `is_cpu=1`，否则 409；解绑部分失败保持 CPU、可重试 | `POST /to-cpu/unbind-all` |
| C6 | CPU 队关窗批维护费/冠名/档期不入账；事件触发目标集不含 CPU；queued 报价不转正、不生成冠名 | `home.ts`、`event-ops.ts`、`market-ops.ts` |
| C7 | 转换审计 `club_cpu_detach_local` 的回收金额取批内实际余额，不取路由快照 | `createAuditStatementWithAfterSql` |

## 2. In / Out

- **In**：上述 C1–C7；五步端点；预检 12 项；回收与审计；教练守卫；CPU 不入账/不转正；UI 六项复核。
- **Out**：首次真实转换（佛罗伦萨 110374、阿斯顿维拉 2）；认证中心「撤销未使用绑定码」；自动通知教练；批量转换；生产回读；push/deploy。

## 3. 用例

### 3.1 预检与写操作（`tests/cpu-detach.test.ts`，28 例）

| 用例 | 断言 |
| --- | --- |
| 干净队预检 | `ready=false`（未置 CPU）、建议名带 `(CPU)`、blockers 为空 |
| 12 类阻断 | 每类各造 1 条，`blockers` 含对应 key；`ready=false` |
| 赛事改名失败 | 502，本仓 `name/is_cpu` 不变 |
| 本仓改名成功 | 同一 batch 改名、`is_cpu=1`、`transfer_banned=0`、余额/券归零、流水 -余额/-券、审计 1 条 |
| 批前余额变动 | 预检后把余额 1500→1400、券 3→2，再转换；流水 -1400/-2，审计 `balanceBefore=1400`、`reclaimed=1400`，不按 1500 记 |
| 重放 | `changed=false, flipped=false`，不重复写流水/审计 |
| 撞名 | 409 `name_taken`，本仓零改动 |
| 未置 CPU 解绑 | 409 `not_cpu`，绑定仍在 |
| 部分解绑失败 | `ok=false`，已解绑的进 `unbound`，失败可重试 |

### 3.2 守卫（`tests/growth.test.ts`、`tests/cpu-detach-guards.test.ts`）

| 用例 | 断言 |
| --- | --- |
| CPU 队成长写入口 | `POST /growth/china-playstyles/22` 403，无明细；`levelup/22` 403 |
| 管理员兼绑 CPU 队 | OIDC 权限含 `club.clubs.manage`，`GET /api/me/club` 仍 403 |
| 普通教练绑 CPU 队 | `/api/me/club` 403 |
| 人类队教练 | 不受影响 |

### 3.3 招商轮（`tests/market-rounds.test.ts`）

| 用例 | 断言 |
| --- | --- |
| CPU queued 报价 | `activateQueuedStatements` 返回 0 条；offer 仍 queued；无合同 |
| 人类队 queued 报价 | 正常转正（既有用例回归） |

### 3.4 审计锁（`tests/ledger-audit-lock.test.ts`）

- `src/worker/routes/admin/clubs.ts` 不再手写 `INSERT INTO audit_log`；改由 `lib/audit.ts` 的 `createAuditStatementWithAfterSql` 生成。
- 10 个占位符（4 个金额 × 2 个 club_id）按顺序绑定；guard 要求余额/券=0 才落审计。

### 3.5 UI（`web/src/pages/admin/ToCpuPage.test.tsx`）

- 人类队入口存在、CPU 队入口不存在；
- 阻断项禁用后续按钮；
- 第 3 步显示余额与消费券；
- 复核六项（`isCpu/tourName/localName/bindings/codes/funds`）；
- 余额/券残留时 `ready=false`。

### 3.6 最坏情况

- 2 个绑定 + 40 字队名 + 12 类阻断全中 + 余额/券各 1 笔；
- 批量解绑 2 个账号，1 个 `authUnbindTeam` 失败；
- 预检 12 条 COUNT 合并为 1 条 SQL；列表/详情不新增迁移；
- 转换 batch 固定 4 类语句：UPDATE → 现金回收（2 条）→ 券回收（2 条）→ 审计（1 条），重放 changes=0。
