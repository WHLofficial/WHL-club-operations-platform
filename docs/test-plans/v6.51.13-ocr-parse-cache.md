# 测试计划 · v6.51.13 成长录入截图识别：解析按图片内容缓存（选边不再重复调模型）

- **类型**：patch = 性能与调用量治理（**零迁移、零契约变更、零前端改动、零提示词改动、模型不变**）⇒ 无 UI 验收项、无迁移回读项。
- **缘起**：用户 m03336「成长录入，截图识别，当到达需要用户选边的分支时，选边后现在的行为难道是再调用一遍 LLM 吗？」—— 确认「是」（选边带 `side` 重发同一张图，端点无条件重跑视觉模型）；用户比较 A/B 后裁决 **B**（服务端按图哈希缓存），并要求收尾避免冗长的测试调用（m03369）。
- **落点**：`src/worker/routes/admin/growth.ts`（`OCR_CACHE_TTL_SEC = 600`、`readOcrCache` / `writeOcrCache`、端点内 `cacheKey = 'ocr:' + sha256Hex(image.base64)`）；测试 `tests/growth-ocr-endpoint.test.ts`。

## 一、口径（实现即规格）

| 项 | 口径 |
|---|---|
| 缓存键 | `'ocr:' + sha256Hex(规范化 base64)`（`decodeOcrImage` 之后的 `image.base64`：已剥 `data:` 前缀与空白）⇒ 同一张图恒同键，与比赛、队侧无关 |
| 缓存值 | 模型的**原始解析**（`llmVisionJson` 的返回对象）——**绝不放 entries**（含 playerId 会被固化） |
| TTL | **600 秒**（够点按钮/刷新一次，过夜自动清） |
| 承载 | `SESSION_KV`（与限流、公开缓存代际键同一个 KV） |
| 写缓存时机 | **页签校验通过之后**（`ocr.tab ∈ {summary, goalkeeping}`）⇒ 坏结果不缓存，用户重试仍会重新打模型（保住 v6.51.2 的截断/不可解析重试语义） |
| 故障处理 | KV 读/写全部 try/catch 吞掉 ⇒ KV 故障退化成「每次都调模型」的旧行为，不影响响应 |
| 契约 | 请求（`{ image, side? }`）与响应（`{ team, side, kind, entries, unmatched, warnings }`）**逐字段不变** |
