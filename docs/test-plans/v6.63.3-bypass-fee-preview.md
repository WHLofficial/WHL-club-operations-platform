## 1. 需求真源（锁定口径）

| # | 口径 | 出处 |
| --- | --- | --- |
| 1 | 球员页解约确认面板要显示**本次解约费数字**：付费档带金额与效力赛季数、满 3 赛季档明示免费、无含违约金合同档保持公式文案（后端仍会 409） | 本版裁决（探查结论：客户端早就算好 `termSpend` 但从未上屏） |

| 3 | 海捞明标面板显示**海捞费 = 新违约金 × 30%** 的当前数字（输入变化实时跟随）；暗标面板 label 已有「冻结 X」，不动 | 本版裁决 |
| 4 | 预览数必须派生自 core 单一出处（`terminationFee` / `freeAgentFee`），不许在组件里再抄公式（transfer-bounds.ts 先例）；预览的等价调用 = `terminationFee(rc, 0, serviceSeasons × 2)`（1 常规窗 = 0.5 赛季，函数只用窗数差） | 本版裁决 |

| 6 | 金额口径以服务端提交实算与回执为准（提交后 toast 里的数字是真数） | 既有（440eff8 注释原意） |

## 2. 测试范围

**In**：预览派生函数单测（与 core 实算同值锁、半赛季步进对照、非法输入）、DeskTab 组件级 hint 断言（jsdom）、SideOps 三态文案的派生数（`termSpend` 改走同一派生后的等价性）。

**Out**：解约 / 海捞 / 续约 / 激活的后端行为（本次零后端改动）；暗标面板出标冻结口径（v6.50.0/v6.63.1 既有用例覆盖）；SideOps 组件级挂载测试（hooks 依赖多、无现成挂载先例，用派生函数单测 + DeskTab 组件测试替代，SideOps 的渲染面以 e2e / 手工覆盖）。
