# 测试计划 · v6.60.0 激活通知截图弹窗

> 按 qa-test-planner 约定设计。执行层 = vitest（组件/页面回归）+ 本地真栈手测（拖拽、文件选择、失败重试）。
> 设计依据：`docs/superpowers/specs/2026-10-29-activation-proof-dialog-design.md`；术语见 `GLOSSARY.md`「激活通知 / 激活通知截图」。

## 一、范围与目标

**In scope**：

1. 转会市场激活页点「激活」打开「上传激活通知截图」弹窗，不再直接弹系统文件框。
2. 球员页 SideOps 点「激活」打开同一个弹窗，旧内嵌文件框与「证据制」说明移除。
3. 拖拽/点选、选中后预览、重新选择、取消/Esc/遮罩关闭。
4. 客户端拦截空文件、非 png/jpg/webp、超过 5MB；拦截时不上传。
5. 点「确认激活」才上传截图并创建激活；失败留在弹窗，成功由父组件关闭。
6. 文案含三项合格标准与可选示例，页面不再出现「证据制」。

**Out of scope**：服务端上传/激活逻辑、R2、图片内容识别、管理组核查流程、举报与匹配窗规则、移动端原生文件选择器的系统行为。

## 三、用例

### A. 弹窗与文案（TC-P）

**TC-P-001 · 打开弹窗不选文件（P0）**

前置：可激活名单已加载，球员有激活费。
步骤：点行内「激活」。
预期：① 不再弹出系统文件框；② 弹窗标题「上传激活通知截图」；③ 说明、三项检查、拖拽区、取消/确认按钮都在；④ 「确认激活」禁用；⑤ 没有发出任何上传或激活请求。

**TC-P-002 · 文案完整且无内部词（P1）**

步骤：检查弹窗与页面底部说明。
预期：① 三项检查分别是「你的俱乐部名」「球员名」「竞价结束后请选择是否匹配」；② 示例含对方主教练、我的俱乐部、球员名、匹配提醒；③ 页面不出现「证据制」「QQ 截图」单独指代；④ 不出现无法解释的缩写。

### B. 文件选择与预览（TC-F）

**TC-F-001 · 点选合法图片（P0）**

步骤：点拖拽区 → 选择 `proof.png`（`image/png`，100KB）。
预期：① 文件选择器 accept 为 `image/png,image/jpeg,image/webp`；② 选中后显示缩略图、文件名、大小与「重新选择」；③ 「确认激活」可用；④ 此时仍未上传。

**TC-F-002 · 拖拽合法图片（P0）**

步骤：向拖拽区触发 `dragover` 与 `drop`，携带 `image/jpeg` 文件。
预期：① dragover 时高亮类 `.over`；② drop 后进入预览态；③ 只取第一个文件；④ 不触发页面跳转或浏览器默认打开图片。

**TC-F-003 · 重新选择（P1）**

步骤：选 `a.png` 后点「重新选择」，再选 `b.webp`。
预期：① 预览与文件名切换为 `b.webp`；② 旧 object URL 被释放；③ 取消旧选择不产生上传。

**TC-F-004 · 拖入非文件/多文件（P2）**

步骤：drop 一个空 `DataTransfer`；再 drop 两个合法文件。
预期：① 空 drop 不改变状态、不报错；② 多文件只取第一个。

### C. 客户端校验（TC-V）

**TC-V-001 · 空文件（P0）**

步骤：选择 0 字节的 `empty.png`。
预期：显示「截图是空的，换一张试试」；不进入可提交状态；无上传请求。

**TC-V-002 · 类型不支持（P0）**

步骤：选择 `note.txt` / `anim.gif` / `photo.heic`。
预期：显示「只支持 png、jpg、webp 图片」；无预览或预览被清除；无上传请求。

**TC-V-003 · 超过 5MB（P0）**

步骤：选择 `big.jpg`，大小 `5 * 1024 * 1024 + 1` 字节。
预期：显示「截图超过 5MB，压缩后再传」；无上传请求。

**TC-V-004 · 边界值 5MB（P1）**

步骤：选择正好 `5 * 1024 * 1024` 字节的 jpg。
预期：允许预览与提交（服务端上限为 ≤5MB）。

### D. 确认、失败与关闭（TC-C）

**TC-C-001 · 确认后按序上传并激活（P0）**

步骤：选合法图片 → 点「确认激活」。
预期：① 先 `POST /api/media/activation`（content-type 为文件 MIME，body 为原始字节）；② 成功后 `POST /api/market/activations`，body 含 `playerId` 与 `proofMediaKey`；③ 成功后弹窗关闭；④ 转会市场页出现「落激活首价」；⑤ 两个请求各只发一次。

**TC-C-002 · 上传失败留在弹窗（P0）**

步骤：mock 上传返回 400「截图超过 5MB 上限，压缩后再传」。
预期：① 弹窗不关；② 显示服务端错误原文；③ 「确认激活」恢复可用；④ 可重新选择后重试；⑤ 没有创建激活请求。

**TC-C-003 · 创建激活失败留在弹窗（P0）**

步骤：上传成功、`POST /api/market/activations` 返回 400「截图不属于你的俱乐部，先重新上传」。
预期：① 弹窗不关并显示错误；② 不进入首价表单；③ 重试会重新上传（不复用旧 key）。

**TC-C-004 · 提交中禁止重复与关闭（P1）**

步骤：点确认后请求未返回时，连续点确认、取消、遮罩、按 Esc。
预期：① 按钮显示「提交中…」且禁用；② 弹窗不关闭；③ 不产生第二个上传/激活请求。

**TC-C-005 · 取消/关闭不发请求（P0）**

步骤：打开弹窗后分别点取消、按 Esc、点遮罩。
预期：三种方式都关闭；无上传/激活请求；预览 URL 被释放。

### E. 两个入口（TC-E）

**TC-E-001 · 转会市场激活页入口（P0）**

步骤：`/market/activation` 点某球员「激活」。
预期：打开共用弹窗；确认成功后页面照旧显示该球员的首价表单。

**TC-E-002 · 球员页 SideOps 入口（P0）**

前置：打开别队可激活球员页，转会窗开放。
步骤：点 SideOps 的「激活」。
预期：① 打开同一弹窗；② 页面上不再有内嵌文件框与「证据制」说明；③ 确认成功后 SideOps 刷新并提示「激活挂牌已提交：5 分钟内出首价才算数。」

**TC-E-003 · 不满足激活条件（P1，回归）**

步骤：刚签约/本窗已激活/缺违约金/时段闸关闭时看按钮。
预期：按钮仍按原逻辑禁用并带 title；不会打开弹窗。
