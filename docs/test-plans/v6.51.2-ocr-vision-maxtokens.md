# 测试计划 · v6.51.2 视觉识别 max_tokens 订正

> 增量范围（判级 **patch**：缺陷修补，零新增能力、零契约变化）：① 视觉调用出站 `max_tokens` 缺省 **4096 → 1024**（生产视觉模型 `glm-4v-flash` 的硬上限）；② 新增 `LLM_VISION_MAX_TOKENS` 环境变量（缺省 1024，非法值回落缺省）；③ `finish_reason === 'length'` 从「不是合法 JSON」改判为**点名截断并要求重试**。

> **零迁移、零生产写、零前端改动**（`src/db/migrations/**`、`web/**` 与公开契约均无变化；调用点 `src/worker/routes/admin/growth.ts:491` 不改）。

## 范围与风险

**In**：出站请求体的 `max_tokens`（缺省值、env 覆盖、非法回落）；截断回包的报错文案与「不放行」口径；识别路径零 DB 写不回归。

**Out**：识别准确率与提示词（v6.43.1 已定）；`src/worker/routes/admin/events.ts:182` 的文本草稿 `maxTokens: 1200`（走文本模型 `LLM_MODEL`，上限未知，另批核）；真实模型端到端联调（诊断阶段已用探针跑过，见下）。

**最坏情况口径**：
- **缺省又写死成模型不支持的值**：本版把缺省降到 1024 并加 env —— 将来换付费视觉模型（如 `glm-4.6v`）仍用 1024 只是输出更紧，不会再 400。闸门 = TC-EP-08 断言缺省恰为 1024。
- **env 写错让功能整体不可用**：非整数 / 负数 / 非数字一律回落缺省而不是照发。闸门 = TC-EP-08 第二段（`4096.5` → 出站仍 1024）。
- **截断被当成功**：名单被截断会漏记球员，比要求重试更贵。闸门 = TC-EP-10（截断报错点名 `LLM_VISION_MAX_TOKENS`；**即便截断后 JSON 仍可解析也判 502**）。
- **修复没落到调用点**：`llmVisionJson` 全仓只有 `growth.ts:491` 一个调用方（`git grep llmVisionJson` 可核）且不传 `maxTokens`，才会吃到新缺省；若将来有调用方显式传值，由该调用方自担与模型的匹配。
