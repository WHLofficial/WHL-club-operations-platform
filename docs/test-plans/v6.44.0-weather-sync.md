## 范围与风险

**In**：验签失败口径（fail-closed 503 / 401-403 拒绝 / 时钟偏移窗口）、载荷形状校验矩阵、竞赛名映射、队名归一匹对（`(CPU)` / 全角括号 / 大小写 / 空白）、`match_weather` upsert 幂等与「推者赢」、审计行形状（零写入不审计）、推送系数被结算采用、纯算式抽取的行为等价与 rng 消费顺序、订正批生成器的自检与通道纪律。

**Out**：插件侧实现（另仓测试，本仓只锁跨仓金标准向量）、平台反向推送（设计上不存在）、`match_weather` 读取端改造（`home.ts` 消费口径不变）、生产 secret 配置与部署（已另行完成）。订正批的实际执行曾列为 Out（需用户授权）——**已于 2026-10-13T01:32Z 授权执行并复查通过**（237/237 句、账本 78 行 +0.63、守恒 0.00、收敛 81/81）。

**最坏情况口径**：
- **错配**：队名匹对失败必须逐场落 `unmatched` verdict 且**不写库**，不许「猜一个最像的」——宁可漏同步也不能把 A 队天气写到 B 队头上（平台侧按 `normTeamName(home)|normTeamName(away)` 建索引，命中唯一才写）。
- **覆盖**：推送对已确认场次照样覆盖（推者赢，插件是真源）。风险 = 平台管理端手工预报被插件覆盖；已确认场次 `settled=true` 只**标记**不动 `match_attendance`，历史账由订正批单独收敛。
- **fail-closed**：未配 `WEATHER_SYNC_SECRET` 必须 503 拒绝全部写入，绝不允许「未配 = 放行」。密钥与 `TEAM_SYNC_SECRET` **分设**（两把钥匙开两个端点，泄一把不连带另一把）。
- **算式漂移**：`computeMatchAttendance` 抽取若改变 rng 消费顺序（perturbation 先、fill 后），会让所有既有场次结算数字偏移——用 `tests/home.test.ts` 既有金样（上座 7275 / 票 1.09 / 商 0.15 / 播 0.9 / 合计 2.14）作零回退闸门。
- **订正批**：估算档残余误差上界 ±12%（晴区间最宽，8.7% 半宽 + 3% 扰动），精确档 ≤1 席；满座场只许向下订正（`min`）；权威系数落在区间外必须硬跳过（否则系数比会把量级放大任意倍数）。
