## 范围与风险

**In**
- 联动只勾「识别条目里出现的门将」：`entries` 里 `position === 'GK'` 且未停赛才进 `shownGk`。
- 失球 0 仍以已确认比分为权威（`sideConcededOf`）：条目没带零封（例如门将页失球被读成 >0）时照勾。
- 已录锁定、已勾的行不动；重复上传不重复计数。

**Out（有意不做）**
- 不做跨行推断（不按「门将页大头像」、不按首发名单推上场门将）——截图证据已在识别条目里。
- 不改服务端提示词与解析（`src/core/growth-ocr.ts` 本版零改动）。
- 不做姓名拼写容错层（用户早前已裁「暂时不做」）。

**最坏情况口径**
| 场景 | 结果 |
| --- | --- |
| 门将页只点名一名门将、另一名出现在截图其它区域 | 只勾条目里那名（与用户口径一致：以图为准） |
| 门将评分被模型读成 null | 该行不入识别条目 ⇒ 不勾（选手手填） |
| 本侧失球 0 但条目未带零封 | 仍勾（比分是权威，旧行为保留） |
| 已录过零封（锁定） | 不重勾、`gkAuto` 不增加 |
| 面板里手动勾/取消 | 不受影响（外场「夺回球权 ⇒ 勾零封」与手勾路径未动） |

## 登记

**未验证项**
1. 用户侧真机确认：重传那张图，报告应只勾上场的门将（待执行）。
2. 「条目里出现但实际是替补」无法从数据侧区分——截图与首发名单是唯一权威（不覆盖）。
3. 双门将同场登场（换人）时两条都会勾：本版按「图里出现即勾」，未做区分（罕见，不覆盖）。

**口径**
1. 依据来自服务端 `src/core/growth-ocr.ts:314`：`rating === null` 的行是「N/A/没识别到评分 = 没上场，不预填」；门将页再按 `ocr.gk` 点名上场门将 ⇒ 识别条目里的门将 = 上场门将。
2. 「失球 0 才算零封」的判定权仍在已确认比分（`sideConcededOf(match, side)`），与截图读数无关（旧行为保留）。
3. 外场「手填夺回球权（含 0）⇒ 勾零封」是页面 `onChange` 的另一条路径（卡片视图与表格视图各一处），本版不动。
4. 每勾一名门将 = 0.5 XP、保存即锁（既有口径不变）。
