# 测试计划 · v6.58.0 候选名单 + 消费券（升格统一）

> 按 qa-test-planner 约定设计。执行层 = vitest（单测 / 集成 / 变异验证）+ 本地真栈 e2e（`npm run dev` 8791 + 本地 D1）+ 直库只读探针（对账）。
> 设计依据：`memory/plan-v6.58.0-shortlist-voucher.md`（拍板 1–10 条）；术语见 `GLOSSARY.md`「候选名单 / 消费券」。

## 一、范围与目标

**In scope**：
1. **消费券账务**：迁移 0082（`ledger_accounts.vouchers` 列 + `voucher_entries` 流水表 + `shop_orders.voucher_used` 列 + `player_shortlist` 表 + config `shortlist_cap`）、存量 `build_credit` 搬运幂等、`voucherMovement` 守卫与对账不变量。
2. **建设域切换**：球场扩建 / 球场升级 / 子设施升级三处从 `stadiums.build_credit` 列切换到券账（行为逐值一致：先券后钱、25% 返还、并发守卫）。
3. **工单拆分扣费与双退**：`submitShopOrder` 券+现金双扣（任一守卫失败删单报错）、审核拒绝双退、老单 `voucher_used=0` 兼容。
4. **管理组发放**：`POST /api/admin/vouchers/grant`（权限、审计、批量）。
5. **候选名单**：五端点（GET 名单 / POST 加入 / PATCH 备注 / DELETE 移除 / GET ids）、上限、跨俱乐部隔离、权限键。
6. **三事件通知**：被挂牌（带挂牌价 + 预计竞价截止）/ 被签走（全路径覆盖，带成交价 + 买方名）/ 解约变自由身；排除规则「操作方俱乐部 = 收藏者俱乐部不发」。
7. **前端**：球员库星标列（默认显示、可点击）+「只看候选」筛选、球员页 SideOps 开关行、CoachPanel 候选卡、券余额与流水展示、工单券抵展示。

**Out of scope**：成长类通知（二期）、事件域发券（二期）、冠名市场扣款（收入卡，不在消费区）、生产 apply（上线轮另做）、`ledger-audit-lock` 写入点锁以外的一般账本回归（既有套件覆盖）。

## 三、用例

### A. 消费券账务（TC-V）

**TC-V-001 · 存量迁移搬运与幂等（P0）**
前置：`stadiums.build_credit` 预置（club1=12.5 / club2=0 / club3=8.00，club3 无 ledger_accounts 行）。
步骤：执行迁移 0082 一次；再重跑一次（幂等重放）。
预期：① club1 `vouchers=12.5`、club3 `vouchers=8.00` 且自动补建账户行、club2=0；② 对应 `stadiums.build_credit` 全部清零；③ `voucher_entries` 各恰一条 `kind='migrate'`；④ 重跑后行数与余额不变（migrate 闸拦截重复搬运）。

**TC-V-002 · voucherMovement 守卫与对账（P0）**
步骤：① 券余额 5 时 `voucherMovement(-8, guardSql vouchers>=8)`；② 余额 5 扣 3；③ 连续扣后直库 `SELECT vouchers FROM ledger_accounts` vs `SUM(amount) FROM voucher_entries`。
预期：① 守卫不通过 changes=0（调用方删单报错）；② 余额 5→2、流水 balance_after 逐行可复算；③ 每俱乐部 `vouchers == SUM(amount)` 恒成立。

**TC-V-003 · 幂等闸（P1）**
步骤：同 (club, kind, ref_type, ref_id) 连发两次发放。
预期：第二次整段跳过（NOT EXISTS 闸），流水与余额只记一次。

### B. 建设域切换（TC-B）

**TC-B-001 · 三处行为逐值一致（P0，回归）**
步骤：对扩建 / 升级 / 设施升级各跑「券足额抵 / 券部分抵 / 无券」三形状（既有测试基线迁移）。
预期：与切换前逐值一致——`creditUsed/cash/refund` 同值；账本流水 `stadium_*` 只记现金部分、memo 带「消费券抵 X M」；`voucher_entries` 出现 `build_use`（负）与 `build_refund`（正）；`stadiums.build_credit` 恒 0 不再读写。

**TC-B-002 · 券守卫并发（P0，最坏情况）**
步骤：券余额 3、费用 10（现金 7 足额），构造券守卫不通过（并发扣空后重放）。
预期：整批失败删单/报错，无「券被扣成负数」或「现金扣了券没扣」的中间态。

### C. 工单拆分扣费与双退（TC-O）

**TC-O-001 · 三形状拆分（P0）**
步骤：券 20 / 工单 15（券 15+现金 0）；券 5 / 工单 15（券 5+现金 10）；券 0 / 工单 15（现金 15）。
预期：`shop_orders.voucher_used` 各 15/5/0；现金流水只记实付；券流水 `shop_use` 对应；审核通过后效果生效。

**TC-O-002 · 双退（P0）**
步骤：券部分抵的工单提交 → 管理组拒绝（必填理由）。
预期：现金退 `amount - voucher_used`、券退 `voucher_used`（`shop_refund` 券侧），两者同回；通知文案带退款明细；老单（voucher_used=0）退款行为与切换前一致。

**TC-O-003 · 双守卫任一失败删单（P0，最坏情况）**
步骤：券足额但现金不足 / 现金刚好但券被并发扣空，两种交错各一发。
预期：工单不存在（删单）、400 文案、券与现金**都**没扣。

### D. 管理组发放（TC-G）

**TC-G-001 · 发放与审计（P1）**
步骤：admin `POST /api/admin/vouchers/grant`（clubIds=[1,2], amount=3.5, note）两次同参。
预期：第一次两俱乐部各 +3.5（`admin_grant` 流水 + 审计 `voucher_grant` origin='user'）；第二次幂等跳过或按 ref 语义拒绝（实施定，断言不重复入账）；非 admin 401/403；amount<=0 / note 缺失 400。

### E. 候选名单（TC-S）

**TC-S-001 · CRUD 与上限（P0）**
步骤：A 加 3 名球员（含自由身/在册/自家球员）→ 带备注 → 查名单 → 改备注 → 移除 1 名；连加到 31 名（cap=30）。
预期：201/200 各步形状正确；31st 409 文案带当前上限；同球员重复 409；名单按加入时间倒序、摘要行字段齐（显示名/位置/年龄/CA/PA/身价/所属队/状态）。

**TC-S-002 · 跨俱乐部隔离与权限（P0）**
步骤：B 的教练调 A 的名单行（PATCH/DELETE）；匿名 / 未绑定用户 / 观众访问五端点。
预期：B 动 A 的行 404/403（看不到别家名单行）；匿名 401；未绑定 403「先绑定俱乐部」；`/ids` 匿名 401。

**TC-S-003 · `?shortlist=1` 筛选（P1）**
步骤：A 带 `?shortlist=1` 请求球员列表。
预期：只出 A 名单内球员（与其他筛选键可叠加）；B 带同参只出 B 自己的；匿名带此参不 500（按未登录处理：空或 401，实施定并断言）。

### F. 三事件通知（TC-N）

**TC-N-001 · 被挂牌通知（P0）**
前置：A 收藏球员 X（属 B 或自由身）。
步骤：B 挂牌 X（普通挂牌，deadline_at 落库）。
预期：A 收到站内信，文案含球员名、B 队名、挂牌价（ask_price）、预计竞价截止时刻（= deadline_at）；激活首价窗场景取 activation_deadline；B 自己（操作方）不发；C 不发。

**TC-N-002 · 被签走通知：全路径覆盖（P0）**
前置：A 收藏球员 X；成交路径按查证清单逐条：市场竞价成交 / `acceptOffer` / 直接转会 / 海捞 / 管理旁路。
步骤：每路径完成一次 X 换队（买方 = Y 队）。
预期：每路径 A 各收一条 `shortlist_sold`，文案带实际成交价 + Y 队名；买家 = A 自己时不发（改按成交方视角不发，实施按计划最简口径断言「A 无 sold 通知」）。

**TC-N-003 · 解约变自由身通知（P1）**
步骤：B 解约 X。
预期：A 收 `shortlist_released`；B（操作方）不发。

**TC-N-004 · 自家收藏与自家动作排除（P0）**
步骤：A 收藏自家球员 → A 自己挂牌他 / A 自己解约他。
预期：A 零通知（操作方 = 收藏者）；变异验证「删排除规则」定向变红。

### G. 前端（TC-U）

**TC-U-001 · 球员库星标列与筛选（P1）**
步骤：登录 A：星标列默认显示、点星 toggle（本地状态刷新）；勾「只看候选」；匿名打开球员库。
预期：toggle 后 `/ids` 刷新、公开列表响应**不含**星标字段（缓存不污染）；筛选只出名单；匿名无星标列且无报错。

**TC-U-002 · 球员页 SideOps 开关行（P1）**
步骤：A 打开候选球员页 / 非候选球员页 / 未绑定用户打开。
预期：✓ 已在（可移出）/ ☆ 加入（可加入）/ 观众看不到开关行（或不渲染，实施定并断言）。

**TC-U-003 · CoachPanel 候选卡与券展示（P1）**
步骤：A 打开我的球队：候选卡列表（备注/移除/跳转）；余额区显示「消费券」余额与来源说明（建设返 25% + 管理组发放）；账本页「消费券」页签流水可读。
预期：文案全站无「建设券」残留（新渲染面）；跳转路径正确。

**TC-U-004 · 消费中心券抵展示（P2）**
步骤：A 在工单表单提交一笔券部分抵的商品。
预期：提交结果与「我的工单」行展示券抵额与实付现金。

## 四、最坏情况口径（必做）

1. **迁移**：重跑幂等（TC-V-001）；「账本与库脱节」——手工把某俱乐部 vouchers 改坏后对账探针能暴露（TC-V-002 的对账断言定向）。
2. **并发**：TC-B-002 / TC-O-003 双守卫交错各取「先扣成功一半」的最坏交错。
3. **最大组**：cap=30 满名单（31 拦截）；管理组发放对全部 20 队一次（批量上限 = 俱乐部总数）。
4. **变异验证清单**（每处确认失败的正是该断言，按将来最可能的重构方式弄坏）：
   - 删 migrate 幂等闸 → TC-V-001④ 红
   - 删券守卫 guardSql → TC-B-002 / TC-O-003 红
   - 双退漏券退 → TC-O-002 红
   - 删 shortlist cap → TC-S-001 红
   - 删「操作方俱乐部排除」→ TC-N-004 红
   - 挂牌通知漏截止时间字段 → TC-N-001 红
   - 漏挂某条成交路径 → TC-N-002 对应路径红
