# 测试计划 · v6.26.0 消费中心 + 外部工单

> 依据 qa-test-planner 设计（2026-09-28 用户指令：测试统一用 qa-test-planner 设计）。执行层 = vitest（tests/shop-orders.test.ts）+ 定向变异验证 + e2e smoke；全部本地，不连远端。

## 1. 范围

**In**：六类商品（pa / badge / badge_upgrade / role / position / club_shell）的提交校验、审批执行、扣费退款原子性、外部工单两步流、位置相邻判定（22 条边定稿表）、game_attrs json_set 空槽语义、导入台账重放幂等、管理端与教练端端点契约、相邻表/角色归属/PlayStyle 名单的前后端同值锁。

**Out**：通知 QQ 通道实际投递（web 行断言即止）、config 管理端 UI、性能与读量（shop 读面全是小表点查）、积分系统本身。

### B. 审批 / 拒绝 / 并发

| TC | 场景 | 优先级 |
|---|---|---|
| TC-B01 | 审批通过：效果生效（PA 上涨 / json_set 落槽 / 徽章行 source='shop'）+ player_purchases 台账行 + 审计行 | P0 |

| TC-B07 | 端点契约：/api/shop/* 匿名 401、未绑定 403；/api/admin/shop/* 非 admin 403；admin 列表 status/source 筛选 | P1 |

### C. 数据语义与保护

| TC | 场景 | 优先级 |
|---|---|---|
| TC-C01 | json_set 空槽语义：remove 后 `$.RoleIDn` / `$.PosIDn` 是 JSON null（与导入 `?? null` 同形），不是键消失 | P0 |
| TC-C02 | 导入重放：有台账球员重导后 PA = 源 PA + 台账SUM（≤cap）、角色/位置槽恢复；**重跑导入结果不变**（整体幂等）；响应带 replayed 计数 | P0 |
| TC-C03 | 徽章不重放但独立表不受整列覆盖影响（重导后 shop 徽章仍在） | P1 |
| TC-C04 | 相邻表锁：POSITION_ADJACENCY 22 条边与独立字面量逐值同、自反对称；与 role.json/position.json 的名称域一致 | P0 |

## 5. 风险

| 风险 | 缓解 |
|---|---|
| json_set 跨引擎类型漂移（REAL 化） | 整数一律服务端校验后内联 SQL 字面量；TC-C01 锁空槽语义 |
| 审批与状态流转的并发窗口 | 守卫压 'pending' + 状态 UPDATE 批末（v6.11.0 教训），TC-B05 锁 |
| 导入 upsert 与重放语句顺序 | 重放语句 append 在同 chunk upsert 之后，TC-C02 隐含验证顺序 |
