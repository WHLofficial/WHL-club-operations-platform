## 1. 口径（实现即契约）

| # | 口径 | 落点 |
| --- | --- | --- |
| 1 | 强制拍卖成交后不再固定新违约金：会话 `release_fee` 落 `NULL`，由买方在第一步提交 | `src/worker/bypass.ts`（删 `fixedReleaseFee: transfer.fee` 分支） |
| 2 | 上下限基准是**过户前**的合同：优先读 `transfers.pre_settle_snapshot.contract.release_fee` | `rcBoundsFor()`（`src/worker/negotiations.ts`） |
| 3 | 快照缺失（`0088` 之前开出的在途单）才回落现行 `contracts.release_fee` | 同处（第二级回落） |
| 4 | 两级都没有 ⇒ `rcBounds = null` = 自由定（下限 1、上限不设） | 同处（返回 null）+ `submitReleaseFee`（只保留正整数闸） |
| 5 | `submitReleaseFee` 与 `GET /api/negotiations?mine=1` 的 `rcBounds` 必须同源，不得出现「DTO 给区间、提交不校验」 | 同函数两处调用 |
| 6 | 有基准时行为与 v6.66.x 完全一致：`releaseFeeBounds` 的 ±10 / ±50% 区间不变，越界仍 400 | `src/core/negotiation-rules.ts:38-43` |

| 8 | 前端第一步判据 = `releaseFee === null \|\| (type === 'forced_auction' && expectedWage === null)`；普通转会判据不变 | `needsReleaseFee()`（`NegotiationsSection.tsx`） |
| 9 | 回到第一步时预填已落库的 `releaseFee`；`rcBounds === null` 时提示「可自由定（整数 m，下限 1）」 | `ReleaseFeeStep` |
| 10 | 审核队列 match 摘要显示「（原 Xm）」，旧违约金由 `newReleaseFee − diff` 反算；缺字段显示「（原 —）」 | `web/src/pages/admin/MarketPage.tsx` |
| 11 | 三笔在途强拍单只清 `expected_wage`，`release_fee` 原值保留作预填 | `scripts/prod-20261102-forced-rc-open/02-apply.sql` |
| 12 | 清 E 后关窗前仍未定 RC ⇒ 与普通转会一致 409 逼谈，不按成交价兜底 | `src/worker/window-machine.ts:400-420`（既有行为） |
| 13 | 球员库翻页条在表格上方与列表末尾各一份；下方那份不做 sticky | `PlayersLibrary.tsx` + `.lib-bar-bottom` |

## 2. In / Out

- **In**：上述 13 条；有快照 / 无快照 / 无合同三种分档；强拍在途单（F 有值、E 为空）与普通转会（F 为空）两种第一步判据；两份翻页条的渲染、禁用态与点击翻页。
- **Out**：匹配差额公式（维持「新 − 旧」）、`fixedReleaseFee` 的其余四类（rc_change / free_agent / match / promotion）口径、训练营直签、生产迁移、站内信提醒（owner 裁决不发，上线后运营口头通知）。

## 6. 已知边界

- 自由定无上限：「高价成交 + 低违约金」可两头获利（`expectedWage` 随 RC 上升，仍是一道经济刹车）——owner 已裁决记风险不设限。
- 快照覆盖范围只到 `0088` apply（2026-11-01T14:50Z）之后成交的单；更早的在途单回落现行合同，若该行已是买方占位合同（`release_fee = 0`）会得到 `[1,10]`，生产现存三笔因球员无合同行而落 `null`，不受影响。
- 审核队列的「原 Xm」是反算值，不是服务端下发的旧 RC。
- 翻页条两份共用同一个元素实例（React 元素复用），页码状态仍只有一份；不做 sticky 与滚动跟随。
- transfer 139（Bastoni → 慕尼黑1860）在数据修复前已按旧口径结算完成（`release_fee = 28` 定死、`wage = 4`），无法回溯重谈；这是本版上线前就既成的事实，不是本次脚本的影响。
