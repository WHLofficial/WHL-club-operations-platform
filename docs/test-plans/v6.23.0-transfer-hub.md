# 测试计划 · v6.23.0 转会中心（市场 / 报价 / 谈判三域前端合并）

日期：2026-10-03。范围：**纯前端信息架构**（零后端改动、零迁移）。新页 `/market/desk`（我的转会台）聚合谈判 / 报价 / 挂牌 / 出价；`/offers`、`/negotiations` 重定向；TopBar 三入口合一「转会中心」；流水线显式呈现 + 逐条阶段徽标。

## 范围

**In**：重定向与参数映射、desk 四区块结构、待办计数派生、阶段徽标、导航收敛、软提示、站内链接、报价/谈判/挂牌/出价操作回归（逻辑组件搬家后行为不变）。
**Out**：后端端点行为（offers/negotiations/market 全部 vitest 照旧回归即可）、海捞区与在售市场功能、管理端页面、业务规则。

## TC

### 重定向（P0）

**TC-RED-01** `/negotiations` → `/market/desk?tab=nego`
前置：已登录教练。步骤：直接访问 `/negotiations`。预期：URL 变为 `/market/desk?tab=nego`（replace，不留历史栈）、谈判区滚动到位或高亮、谈判列表正常渲染。

**TC-RED-02** `/offers` → `/market/desk?tab=offers&box=in|out`
步骤：访问 `/offers`；再访问 `/offers?box=out`。预期：分别落到 desk 报价区且页签停在「我收到的」/「我送出的」——box 参数逐一映射不丢。

**TC-RED-03** 旧页组件退役
步骤：访问 `/offers`、`/negotiations` 后检查 DOM。预期：不再出现旧页专属 `<h1>转会报价</h1>` / `<h1>签约谈判</h1>`（新壳为转会台标题）；`/market/mine` 同理不再可达（并入 desk）。

### 导航（P0）

**TC-NAV-01** TopBar 单入口
步骤：登录后看顶栏。预期：出现一枚「转会中心」（指 `/market`）；「转会报价」「签约谈判」两个旧导航项消失。

**TC-NAV-02** MarketNav 四 tab
步骤：进 `/market/desk`。预期：市场子导航四项 = 在售市场 / 我的转会台 / 海捞 / 市场情报；当前项「我的转会台」高亮；旧「我的」项不再存在；四个 tab 各自可达且内容正确。

### 权限与软提示（P0）

**TC-AUTH-01** 匿名访问 `/market/desk`
步骤：登出态直接访问。预期：RequireUser 软提示卡（不白屏、不跳转、提示登录/绑定）；与 `/market/free` 同模式。

**TC-AUTH-02** viewer（登录未绑定）
预期：desk 区块显示「只对教练开放」引导卡；报价/谈判区块不发起无谓请求或错误不外抛。

### 转会台结构（P0/P1）

**TC-DESK-01** 四区块齐全
前置：有进行中谈判 + 收到报价 + 出过价的教练账号（本地夹具造数）。预期：自上而下依次为：流水线说明条（五段：挂牌/报价→竞价→审核→谈判→成约过户 + 「报价被接受 ≠ 成交，会生成挂牌继续竞价」机制句）、待办提醒行、谈判区（会话卡 + 已落定表）、报价区（收到/送出页签 + 状态筛选 + 谈判桌）、我的挂牌 + 我的出价。

**TC-DESK-02** 待办提醒行计数派生
预期：「轮到我 N」= 报价区 pending 且 myTurn 的条数（含收到与送出两侧）；「谈判 M」= active 会话数；「竞价中 K」= 我的出价 status=active 条数；三项与对应区块实际行数一致，零额外请求（Network 面板核对请求数 = 各区块自身的）。

**TC-DESK-03** 深链锚点定位
步骤：从 SideOps 点「我收到的报价」。预期：落 `/market/desk?tab=offers&box=in` 且报价区页签正确；无 JS 报错。

**TC-DESK-04** 旧页数据不丢
预期：合并后 desk 报价区/谈判区/挂牌/出价的行数与字段与合并前三页逐一一致（对照截图或 dev 数据）。

### 阶段徽标（P1）

**TC-BDG-01** 报价行徽标
预期：pending+myTurn=「待你表态」（gold）、pending+!myTurn=「等对方」、accepted=「已接受·挂牌竞价中」（green）、rejected/withdrawn/expired=对应灰色徽标；与原 STATUS_BADGE 语义一致。

**TC-BDG-02** 出价行徽标
预期：active=领先中、listing 待审核=待审核、谈判阶段=谈判中、won=成交、其余灰——新增的「待审核/谈判中」阶段由 listingStatus/holdStatus 推导，不新增请求。

**TC-BDG-03** 谈判卡阶段
预期：未定违约金显示「第一步：定违约金」；已定显示「工资谈判 · 剩 N 轮」；settled 显示成约方式徽标（报价成约/强制成约/直败/训练营）。

### 操作回归（P0，逻辑组件搬家后行为不变）

**TC-ACT-01** 报价四操作：还价（金额校验严格递增）/ 同意（提示自动挂牌）/ 拒绝（卖方可见）/ 撤回（买方可见）——成功 toast、清单刷新、谈判桌时间线新增事件。
**TC-ACT-02** 谈判流程：定违约金（幅度受限提示）→ 工资报价（≤3 轮、逐轮递增）→ 成约后 NumberPrompt 定号（可跳过）。
**TC-ACT-03** 直签训练营：二次确认 → 成约过户 → 定号卡。
**TC-ACT-04** 挂牌我的球员（规则价提示）与我的出价列表（冻结/解冻/划转资金标）在 desk 内原样工作。
