## 最坏情况口径（铁律）

- **坏输入绝不放大**：用户可贴 50 个 id 的分享串。解析链（切分 → 整数校验［非数字/≤0 丢弃］→ 去重保序 → 取前 3）后，请求数恒 ≤3，多余项只准产生提示、不准产生请求 → TC-CMP-URL-02/03/04/07。
- **URL 是唯一事实源**：任何自动改写（`replaceState` 清洗 ids、跳转详情页、消除非法项）都破坏分享链路。最坏场景＝粘贴一个含非法项的旧 URL，页面清洗后把用户的地标改掉 → TC-CMP-URL-06。
- **门将轴只认「全员 GK」**：混比（1 GK + 1 外场）必须走外场轴；最坏是把判据写成「任一 GK」。门将专属能力只在 34 属性表逐行可见 → TC-CMP-RADAR-01/02。
- **平手语义 ＝ 至少不落下风**：等值两侧都加粗，因此 `[5,3,3]` 会三粗（两个 3 互相不输）、`[5,5,5]` 三粗；只有「唯一的最小值」才是常规字重。语义反直觉，必须由纯函数矩阵锁死 → TC-CMP-TBL-03。
- **色随人走，移除不回填**：3 人移除中间 1 人后，剩余两人颜色不得跳变（否则视觉上等于换人）；直接开 URL 按 URL 顺序分配。最坏＝用 `index % 3` 按存活后重排 → TC-CMP-RADAR-06、TC-CMP-LIB-06。
- **404 ≠ 失败**：404 丢弃并提示、不留槽；5xx/网络错误留可重试槽，重试**只重拉失败者**（命中缓存的成功者零新请求）。最坏＝两者混同 → TC-CMP-STATE-02/03。
- **数据面最坏**：长尾球员 `game_attrs` 可能为 null（生产 18,301 人中仅 570 有完整 game_attrs 面），属性行必须「—」且不参与胜负，页面不崩 → TC-CMP-TBL-07、TC-CMP-RADAR-03。
- **jsdom 只锁语义不锁视觉**：jsdom 不跑样式表，加粗、定宽对齐、吸顶几何、断点表现只能锁类名/属性，真实视觉由 e2e 截图与三视口扫描兜底 → TC-CMP-TBL-05、TC-CMP-DESK-03/04、TC-CMP-MOB-01。

### TC-CMP-URL · URL 解析与降级（①⑧）

**TC-CMP-URL-01 · 空/无 ids：0 人页面级空态且不重定向**（P0 · e2e + vitest 组件）
- 前置：匿名可访问（公开路由，不要求登录）。
- 步骤：分别访问 `/players/compare`（无 query）、`/players/compare?ids=`、`/players/compare?x=1`。
- 预期：URL 不被改写（无重定向、地址栏不变）；渲染页面级空态「还没有选择球员」＋「去球员库选人」；对 `/api/players/:id` 发 0 次请求。
- 变异：解析为空时 `navigate('/players', {replace:true})` → 本条红。

**TC-CMP-URL-02 · 非法 id：忽略并计数提示、不产生请求**（P0 · vitest 纯函数 + 组件）
- 前置：`ids=abc,1,2`。
- 步骤：打开对比页。
- 预期：只发 id 1、2 两次请求；提示「已忽略 1 个无效 id（abc）」（N 与列举实现轮抄终稿屏）；URL 保留原串。
- 备注：非法 id 的完整边界矩阵见 TC-CMP-URL-07；50 个非法 id 的提示长度口径 spec 未限，实现轮定并回填（登记在风险表）。

**TC-CMP-URL-03 · 重复 id：去重保序 + 提示**（P1 · vitest 纯函数 + 组件）
- 前置：`ids=5,5,3,3,5`（夹具两球员均 200）。
- 预期：存活 [5,3]（保序）；各发 1 次请求；提示「重复的球员已自动去重」。
- 变异：去重不保序（Set/反向）或丢计数 → 本条红。

**TC-CMP-URL-04 · 超 3：按 URL 顺序取前 3 + 提示**（P1 · vitest 纯函数 + 组件）
- 前置：`ids=4,2,7,9,1`。
- 预期：只请求 4、2、7（顺序一致，不请求 9、1）；提示「最多同时对比 3 人，已只取前 3 位」；页面按 3 人形态渲染。
- 变异：改为取后 3 / 任意 3 → 本条红。

**TC-CMP-URL-05 · 少于 2（单人）：合法单人态，不重定向**（P0 · e2e + vitest 组件）
- 前置：`ids=7`。
- 预期：单人雷达 ＋ 虚线空槽「还差 1 名球员」＋「＋ 从球员库选」；**不出对比表**（34 属性表与杂项区不出现）；URL 仍为 `?ids=7`（不跳详情页、不补代码）。
- 变异：单人时重定向到 `/players/7` 或隐式补齐第 2 人 → 本条红。

**TC-CMP-URL-06 · URL 即事实源：不自动改写、改地址栏即改对比、顺序敏感**（P0 · e2e）
- 前置：2 人态（`?ids=1,2`）、3 人态（`?ids=1,2,3`）各一。
- 步骤：(a) 地址栏把 ids 改成另一对 → 页面按新对渲染（发新 id 请求）；(b) 把 `?ids=1,2` 改成 `?ids=1,2,3,4,5` → 页面按前 3 人渲染、**地址栏保留原串**（多余 id 不被删、无 replace 清洗）；(c) `?ids=3,1` 与 `?ids=1,3` 左右顺序与颜色互换；(d) 页面内滚动、开合吸顶条不改 URL。
- 预期：四条全成立；「已忽略/已去重/超 3」提示出现也**不改写**地址栏。
- 变异：解析后 `history.replaceState` 回写清洗串 → 本条红。

**TC-CMP-URL-07 · `parseCompareIds` 边界矩阵（解析顺序与计数）**（P0 · vitest 纯函数）
- 前置：纯函数 `parseCompareIds(raw) → { ids, droppedInvalid, droppedDuplicate, overLimit }`（`web/src/lib/compare.ts` 建议落点）。
- 步骤：逐格输入 ``（空串）/ `undefined` / `,` / `1,,2` / `abc` / `1.5` / `1e3` / `0x10` / `+1` / `0` / `-3` / `7` 前后带空格 / `007` / `3,1,3,2,1` / `9,8,7,6,5` / `5,5,5,4,4` / 大小写混合。
- 预期：ids 长度 ≤3、保序、无重复；非法（非整数、≤0）丢弃并计数；计数与处理顺序一致（示例 `3,1,3,2,1` → ids `[3,1,2]`、droppedDuplicate 2、overLimit 0；`9,8,7,6,5` → ids `[9,8,7]`、overLimit 2）。
- 备注：`007`（Number 化后 7）与前后空格（trim 后接受）两格 spec 未逐字规定——实现轮在 `compare.test.ts` 里显式落值并把实际口径回填本行；倾向 trim 容忍，避免 `ids=%207` 静默变 0 人态。
- 变异：删整数校验 / 去重乱序 / 超限取法错 → 本条红。

### TC-CMP-STATE · 状态机（⑧）

> 9 态映射：0 人＝URL-01、1 人＝URL-05、2/3 人＝DESK-01/02、加载中＝STATE-01、部分失败＝STATE-03、全失败＝STATE-04、重复＝URL-03、语法非法＝URL-02、超 3＝URL-04、404＝STATE-02。

**TC-CMP-STATE-01 · 加载中：骨架屏与请求数**（P1 · vitest 组件）
- 前置：详情请求打桩为 pending（不 resolve）。
- 预期：骨架屏「正在调阅球员数据…」在场；无属性表/雷达数据；URL 不改；请求数＝存活人数（≤3）。
- 备注：加载态是否复用站点既有骨架样式以实现轮为准，本条只锁文案与「不闪错态」。

**TC-CMP-STATE-02 · 未知 id（404）：丢弃 + 提示，不留重试槽**（P0 · vitest 组件 + e2e）
- 前置：`ids=1,999999`，999999 回 404。
- 预期：999999 被丢弃并提示「未找到 id 999999 对应的球员，已忽略」；存活 1 人 → 单人态；**不出现重试槽**（与 STATE-03 区分）。
- 变体：两人全 404 → 0 人空态（TC-CMP-URL-01 的渲染）。
- 变异：404 与 5xx 同待遇（丢弃改留槽、或留槽改丢弃）→ 本条与 STATE-03 互锁变红。

**TC-CMP-STATE-03 · 部分失败：留可重试槽，重试只重拉失败者**（P0 · vitest 组件）
- 前置：2 人，第 2 人 500（或网络错误）；apiMock 按 URL 计数。
- 预期：第 1 人正常渲染 ＋ 失败者位置留可重试槽（带「重试」）；点重试 → **只发失败者的 1 次请求**（成功者 0 次新请求）；重试成功后转 2 人形态。
- 变体：3 人中 1 成功 2 失败 → 两个槽各自可重试；逐个重试各自只补 1 次请求。
- 备注：404 与 5xx 的判定以实现轮的 React Query 错误对象口径为准（`status === 404` 走丢弃）。
- 变异：重试重拉全部（含成功者/命中缓存者）→ 请求计数断言红。

**TC-CMP-STATE-04 · 全部失败：页面级错误态 + 重试恢复**（P1 · vitest 组件）
- 前置：2 人全 500。
- 预期：页面级错误态（提示 + 重试），不是白屏、不是 0 人空态；点重试成功后渲染 2 人形态（不刷新页面）。
- 备注：错误文案以实现轮抄终稿屏为准。

**TC-CMP-STATE-05 · 存活数变化后形态重判**（P1 · vitest 组件）
- 前置：3 人，其中 1 人 404 丢弃。
- 预期：存活 2 人 → **从 3 人形态回落 2 人形态**（雷达改双色叠图、左右热区图位置出现、属性表每行 2 值格）；反之（重试补回第 3 人）回 3 人形态（热区图撤下、3 值格）。
- 变异：形态按「URL 人数」而非「存活人数」判定 → 本条红。

**TC-CMP-STATE-06 · 多类提示并存且文案逐字**（P1 · vitest 组件）
- 前置：`ids=abc,1,1,2,3,4`（→ 非法 1 + 重复 1 + 超 3 取 [1,2,3]），再让其中一个 id 404。
- 预期：四条提示同场且互不吞没——「已忽略 N 个无效 id（…）」「重复的球员已自动去重」「最多同时对比 3 人，已只取前 3 位」「未找到 id … 对应的球员，已忽略」；页面仍按存活人数正常渲染。
- 变异：提示合并/吞错（只显示第一条）→ 本条红。
