## 最坏情况口径（铁律）

- **本批「通过」的失败场景定义（整批口径）**：375×812 下全路由扫描（含各编辑面板**打开态**）**任何一处** `scrollWidth > clientWidth + 1` → 整批不通过。不得按「个别页面」「历史遗留」豁免，不得用白名单/跳过把红扫绿；卡片化新引入的溢出只能修绿不能登记。
- **桌面零变化铁律**：1280 下任一 DOM 节点、类名序列或关键计算样式相对批前变化（卡片节点渲染进桌面 DOM、`entry-sumbar` 渲染、粘性生效等）→ 违反铁律，整批不通过。桌面项分级归 P2，失败判定与 P0 同级。
- **粘性最坏情形**：1280 下 computed `position` 必须为 `static`（桌面表不粘）；375 横滚后对手列/球员列滚出可视区 = 粘性失效。判定不能只看类名，必须几何断言（列右缘仍在裹层可视区内）+ computed style 双口径。
- **双分支盲区**：`useMediaQuery` 分支渲染让同一逻辑存在两份渲染（卡片 / 表格）。只测卡片侧时表格侧是盲区，反之亦然——卡片侧状态由 TC-ENT-02..08 覆盖，桌面表格侧由 TC-REG-01 + `mobile-baseline` 既有扫描兜底；两端 DOM 必须互斥（不是 `display:none`）。
- **假绿风险（⑭ 前置）**：⑭ 依赖本地 TOUR_DB 数据；本地旧 schema 致部分 admin 端点 500 有 ⑪ 后置先例——「无已确认比赛可录」时不得静默跳过或切绿，必须显式失败/报前置缺失（TC-E2E-04 / V6）。
- **粘性「测得出但不成立」风险**：`position:sticky` 生效而 z-index/背景未设 → 背面内容透底叠字，computed style 断言仍全绿——必须人工/几何抽查（TC-CCH-05 备注）。
- **断点边界**：760/761 与 640/641 必须双侧验证，避免「375 测过就以为桌面也对」。
- **e2e 失败态（铁律要求补失败态）**：⑮ 的失败态 = 摘掉 `coach-sticky` 必须红（V1）；⑭ 的失败态 = 前置缺失必须红（V6 / TC-E2E-04）。
- **单测测最大组**：卡片状态用例覆盖**全部状态枚举**（已录 / 训练营 / 校验 / 只读 / 脏行）而非抽样；类名契约 6 个全扫（扫描器遍历 `web/src` 全树 `*.tsx` + `styles.css`，不抽样）。

**TC-ENT-05 · 保存 → 已录锁定态（含重复提交 no-op）**（P0 · e2e，⑭ 第 4 步）

**TC-ENT-06 · trainee 置灰与校验红框（状态与表格版一致）**（P1 · vitest + e2e）
