## 最坏情况口径（铁律）

- **语义单一出处**：`walkover_side` 的读法只准经 `src/core/walkover.ts`。任何地方再写 `walkover_side === 'home' → 主队胜` 就是回归（这正是本轮要消灭的读法）→ TC-WO-01…03、TC-WOR-01…04、TC-WOT-01…06。
- **弃权方一分不发**：弃权场连**败方出场补贴**也没有；胜方照发胜场奖金；双弃权双方都不发。最坏情况是「把护栏只加在一处」——联赛与超级杯两条败方补贴路径必须各带护栏，冠军杯小组/淘汰赛分支不得凭空多出败方项 → TC-WOP-02…05、TC-WOP-06、TC-WOP-07。
- **弃权场不发比赛日收入**：`matchAttendanceStatements` 必须在写任何一行前早退（含 `both`）；最坏情况是「只挡收入、仍落上座行」——上座行是收入幂等闸（`home.ts:327` 按 `match_id` 查存在性），落了行会让未来重放有机会重发 → TC-WOA-02。
- **既有数据不删行只清零**：生产 5 行 `match_attendance` 用 `UPDATE ... SET attendance/ticket/commercial/broadcast = 0` 处理，**保留行与 weather**；删行会破坏幂等闸、也会让该场从主场战报里消失 → TC-WOB-04、TC-WOB-07。
- **判据与渲染同源**：生产批的期望值由生成器按「收回 39.74 / 补发 75.20 / 差额 19.00 / 净 +54.46」硬断言（`selfCheck()`），不得只写「跑完就行」；`--verify` 必须能区分「键在位」与「金额正确」→ TC-WOB-05、TC-WOB-06。
- **不双发、不补错人**：生成器两条最易犯的错——漏过滤 CPU 队（会给 10/131681 补发 21.9）、对已走差额的场次整笔重发（双发）——必须由 `CPU_CLUBS` 与 `DELTA_KEYS` 双过滤 + `selfCheck()` 断言钉死 → TC-WOB-03、TC-WOB-05。
- **守恒位而非绝对笔数**：cron 会持续写账（prize/revenue），验收不得断言流水绝对条数；用 `conserve = Σbalance − Σamount` 作与增长无关的硬断言 → TC-WOB-06、TC-WOB-09。
- **批后余额漂移**：批执行后管理员另有 2 笔「接队资金」（club 241 / 112172 各 +30.00，`ledger_entries` id 271/272，晚约 20 分钟）——验收期望值必须含 `POST_BATCH` 项，否则会把别人的钱当成自己的差异 → TC-WOB-06。
- **离线副本同步**：`scripts/prod-*/engine.mjs` 里的公式副本必须与运行期同向；改运行期公式时只搜 `src/` 会漏 → TC-REG-05。
- **老测试的旧口径必须订正而非删除**：6 处老测试把「`walkover_side=home` ⇒ 主队胜」当既有口径钉住（注释还写「仓库既有口径」），若只改实现不改测试，会得到「测试仍绿但语义已改」的假安全；订正后同一断言必须反向 → TC-WOT-01…06。
