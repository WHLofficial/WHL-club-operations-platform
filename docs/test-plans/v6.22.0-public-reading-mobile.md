## 最坏情况口径（铁律）

- **本批「通过」的失败场景定义（整批口径）**：375×812 下全路由扫描（含球员页页签打开态、卡片流打开态）**任何一处** `documentElement.scrollWidth > clientWidth + 1` → 整批不通过。不得按「个别页面」「历史遗留」豁免，不得用白名单/跳过把红扫绿；卡片化/粘性新引入的溢出只能修绿不能登记。
- **桌面零变化铁律**：1280 下任一 DOM 节点、类名序列或关键计算样式相对批前变化（卡片节点渲染进桌面 DOM、粘性生效等）→ 违反铁律，整批不通过。桌面项分级归 P2，失败判定与 P0 同级（TC-PLR-06 / TC-STK-04 / TC-REG-05 兜）。
- **粘性最坏情形**：1280 下 computed `position` 必须为 `static`（桌面表不粘）；≤760 横滑后粘列滚出可视区 = 粘性失效。判定不能只看类名，必须几何断言（列 right 缘仍在视口内）+ computed style 双口径（TC-STK-01/02/03/06）。
- **双分支盲区**：`useMediaQuery` 让同一份数据存在两份渲染（卡片 / 表格）。只测卡片侧时表格侧是盲区，反之亦然——两端 DOM 必须互斥（不是 `display:none`），375 卡片在场时 `.transfer-table` 必须不在 DOM，1280 反之（TC-PLR-03/06/07）。
- **假绿风险（⑯ 前置）**：⑯ 依赖本地种子。`/api/players?limit=1` 无数据时 `assert(pid, …)` 必须显式红并点名文案「取样球员失败……⑯ 玩家页断言前提不成立」；intel 无数据时 ⑯ 走 `console.warn` 点名降级（静态闸门兜底）——不得静默跳过、不得切绿；成长页签无种子时只断言「不撑破」，卡片语义转人工并记「前置缺失」，不得记「已覆盖」（TC-E2E-01/03、TC-PLR-04、V6）。
- **断点边界双侧**：759/760、760/761（卡片↔表格、粘性↔static）、899/900（单列↔双栏）、1024/1025（渐隐↔无渐隐）必须两侧验证，避免「375 测过就以为 760/桌面也对」（TC-PLR-08 / TC-STK-06 / TC-TOP-02）。
- **⑫ 只量 `documentElement` 的口径继续有效**：容器内横滚（`.table-wrap`、`.dossier-tabs`）不计入 375 零溢出扫描——这是登记口径，不是漏测；容器级横滑的可用性由 TC-PLR-01 / TC-STK-01/02/03 的几何断言兜（TC-REG-01）。
- **粘性「测得出但不成立」风险**：`position:sticky` 生效而 z-index/背景未设 → 背面内容透底叠字，computed style 断言仍全绿——三态行底色（trainee/flagged/hover）与右缘分隔必须人工抽查（TC-STK-06 备注）。
- **e2e 失败态（铁律要求补失败态）**：⑯ 的失败态 = 摘 `table-sticky-2` 类 / 种子缺数据必须红（V1 / V6）；不得有「永远绿的空断言」。
- **单测测最大组（不抽样）**：卡片类名契约 5 类名全扫（token 正则防 `table-sticky-2-broken` 式子串假绿）；粘性三表逐文件计数「各恰 1 处挂类」；白名单双向核对（白名单外零命中 + 每条恰中 1 次）不抽样。

## 用例

### TC-PLR 球员档案页公开阅读（≤900 单列 / ≤760 卡片）

**TC-PLR-01 · 375 档案单列 + 页签横滑 + 文档级零溢出**（P0 · e2e，⑯ 第 1–2 段）
- 前置：`npm run build` + `npm run dev`（8791）；`/api/players?limit=1` 可取到球员（取 `fcId ?? id`）；375×812。
- 步骤：375 进 `/players/:id`；读 `.dossier` computed `grid-template-columns`（应单列、无空格）；读 `.dossier-tabs` 的 `scrollWidth` 与 `clientWidth`；依次点四页签（合同/属性/成长/转会记录）确认 `is-active`/`on` 跟随；量 `documentElement.scrollWidth - clientWidth`。
- 预期：`.dossier` 单列（≤900 档生效）；`.dossier-tabs` 可横滑（`scrollWidth > clientWidth`）、四页签均可达且点击切换；文档级溢出 ≤1px（页签行横滑而非撑破文档）；旧 ≤640 档 `.dossier` 单列规则仍在（双保险）。
- 备注：页面级溢出只量 `documentElement`，容器内横滚不算（⑫ 既有口径）；active 页签居中由 TopBar 的 `scrollIntoView` 负责，不在本条断言。

**TC-PLR-02 · 641–900 中屏同样单列（768 档 + 899/900 双侧）**（P0 · e2e，⑯ 第 3 段）
- 前置：同 TC-PLR-01；768×900 与 641/899/900/901 档。

- 备注：900 是既有阅读布局档（PlayersLibrary 已确立），非新断点扩散；⑯ 已覆盖 768 档。

**TC-PLR-03 · 转会事件卡：DOM 互斥 + 字段语义逐条与表格一致**（P0 · e2e + 人工）
- 前置：375 与 768 两档；本地球员有转会记录（9001 阿大 4 条 completed，与 ⑯ 取样同口径）。
- 步骤：375 进转会页签，读全部 `.event-card` 文本；768 同页签读 `.transfer-table` 行文本；逐条比对五字段：完成时间（`slice(0,10)`，null 为 `—`）、类型徽标（`TRANSFER_TYPE_LABEL[t.type] ?? t.type`，`badge gray`）、「转出 → 转入」（`fromClubName ?? '自由身'` → `toClubName ?? '自由身'`）、费用（`fee===null?'—':X.XX m`，`extraFee>0` 才附 ` +Y.YY`）、赛季（`S{season} 第 {windowSeq} 窗`，season null 为 `—`）；同时断言 375 DOM 无 `.transfer-table`、768 DOM 无 `.event-card`。

**TC-PLR-04 · 成长事件卡：事件名 + 数值/来源 + `+XP` 金徽标（种子依赖显式口径）**（P1 · e2e / 人工）
