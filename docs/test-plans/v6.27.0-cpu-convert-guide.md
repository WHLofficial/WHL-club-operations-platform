# 测试计划 · v6.27.0（CPU 接管向导：跨仓改名 + 本仓四端点 + 管理端 5 步页）

> 设计：qa-test-planner（2026-10-04）。执行层：vitest（两仓）+ e2e smoke + 变异验证（最坏情况口径）。基线：v6.26.1 发布时 vitest 75 文件 / 1298 例、e2e 21/21。零迁移（不新增 0062）。

## 1. 范围

**In**：① tour 仓新机器端点 `POST /api/internal/team-rename`（HMAC 与 team-upsert 逐字同口径：`POST|{path}|{ts}|{rawBody}`、`x-timestamp`/`x-sign`、±300s、密钥 `TEAM_SYNC_SECRET`、未配 503 / 错签 403；同名幂等 200 `renamed:false`；撞名 409 指名；写审计）。② 本仓 `src/worker/tourClient.ts` 新增 `pushTeamRename`（永不抛错、10s 超时）。③ 本仓 4 个管理端点（全走 `club.clubs.manage` + 审计）：`GET /api/admin/clubs/:id/cpu-convert`（只读聚合：club/tour/infra/binding/suggest）、`POST .../rename-tour`（前置 is_cpu=1，代调 tour，失败不改本仓可重试）、`POST .../rename-local`（`UPDATE clubs SET name=?, is_cpu=0 WHERE id=? AND is_cpu=1` 幂等守卫）、`POST .../seed-ops`（一次批全幂等建行：stadiums 12000/tier 0/图值壳奖励/fans=diehardTarget(teamInfluence)、ledger 0 余额、club_facilities 5 key 0 级、clubs.league_tier 定值）。④ 读侧小改：`GET /api/admin/clubs` 加 `isCpu`、`GET /api/admin/overview` 加 `cpuClubs`。⑤ 前端：`CpuConvertPage` 5 步向导（路由 `/admin/clubs/cpu-convert`，无 id 时 CPU 队选择器）+ ClubsPage CPU 行入口 + 总览「CPU 队」卡。

**Out**：生产 4 队（曼城 id 10 / 巴塞罗那 241 / AC米兰 131681 / RB莱比锡 112172）的实际接管操作——属发布后管理员手动运维，不在自动化范围；v6.28.0 对 `league_tier` 级别系数的消费侧；侧栏新增导航项（本版刻意不加）；非 CPU 队的任何入口。

**Entry**：两仓代码与测试就绪、`TEAM_SYNC_SECRET` 在测试内注入假值。**Exit**：本仓全量 vitest ≥75 文件全绿（用例数 ≥1298 + 本版新增）、三份 typecheck 零错、build 过、e2e 21/21；tour 仓全量 vitest 全绿、typecheck 零错；变异验证五条按预期红后还原全绿。

## 3. 变异验证（按将来最可能的重构方式弄坏，确认**正是该断言**红）

| M | 变异 | 预期红 |
|---|---|---|
| M1 | tour 仓 `team-rename` 删验签（或删未配 503 分支） | TC-TR-01/TC-TR-05 红 |
| M2 | tour 仓删「同名早退」或撞名检测退化为不排除自身 | TC-TR-03（或 TC-TR-04）红 |
| M3 | 本仓 rename-tour 删 `is_cpu!==1` 前置 | TC-CV-05 红 |
| M4 | 本仓 rename-local 的 UPDATE 删 `AND is_cpu = 1` | TC-CV-06 重放/非 CPU 断言红 |
| M5 | seed-ops 把 `ON CONFLICT DO NOTHING` 改成带 `updated_at` 的 upsert（样式同 ledger.ts 增量模式） | TC-CV-09 快照红（updated_at 变） |
| M6 | seed-ops 的 fans 改为定值或漏 `playerSum` | TC-CV-08 公式断言红 |
| M7 | 预设表改错一格（如曼城 bonus 0、级别对调） | TC-CV-01 对应队红 |
| M8 | 前端删 CPU 行 `isCpu` 条件 | TC-UI-03 红 |

执行方式：逐个 Edit → 定向 vitest → 记录红点 → 还原 → 确认全绿（后台 subagent 执行，最坏情况口径）。

## 4. 回归套件

- **定向**（每步提交前）：本仓 `tests/cpu-convert.test.ts`、`tests/team-sync.test.ts`、`tests/admin-clubs-create.test.ts`；tour 仓 `tests/internalTeamRename.test.ts`、`tests/clubTeamSync.test.ts`。
- **全量**（收口前）：本仓 `npx vitest run`（≥75 文件、用例数 = 1298 + 本版新增）+ `npm run typecheck`（三份）+ `npm run build` + `npm run test:e2e`（21/21）；tour 仓 `npm test` + 其 typecheck。
- **发布闸**（两仓分别等令）：tour 先部署——新端点上线、未配语义 503 正确；本仓后 push（CF 自动部署）；上线回读 `GET /api/admin/clubs/10/cpu-convert` 形态正确（只读，不动数据）。生产接管操作由管理员在向导页逐步执行，每步可见成功/失败态。

## 5. 风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 两仓签名口径漂移（路径/字段顺序/时钟窗） | 低 | 高（步1 永久失败） | 双仓金标准同 hex 锁（TC-TR-01 + TC-PT-01） |
| 步1 成功但步2 前中断 → 两仓名暂不一致 | 中 | 低 | 幂等：步1 重复执行为 `renamed:false`；向导状态端点如实展示两仓当前名 |
| seed-ops 幂等语义被将来重构改成 upsert | 低 | 中（重放可能重置已演进数据） | TC-CV-09 全字段快照闸（含 updated_at） |
| 级别1/2 → premier/second 映射与用户口径不符 | 低 | 中（v6.28.0 系数取错档） | 表单可改 + 本文件与 CHANGELOG 留痕；发布前请用户复核 |
| RB莱比锡奖励「空」按 0 预填非用户原意 | 低 | 低 | 表单可改；docs 留痕（计划已裁决） |
| tour 未配 `TEAM_SYNC_SECRET` 时步1 失败 | 中 | 低 | 503 文案明确；向导可重试，本仓零改动 |
