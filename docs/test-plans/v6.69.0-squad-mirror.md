## 1. 口径（期一）

1. 球队名单 = `players ⋈ contracts`（`is_active = 1 AND contracts.club_id = players.club_id`）的纯推导视图，没有任何人工入口。
2. 分桶：无在队合同 → `unsigned`；`contract_type = 'trainee'` → 训练营；其余（含脏值）→ 一线队。
3. 已退役球员（`players.status = 'retired'`）不进任何桶。
4. `GET /api/club/squad` 的 `players` 带 `squad: 'first_team' | 'trainee' | null`；未签约者 `squad: null` 且 id 进 `unsigned`。
5. `compliance` 仍然只在 `tier !== null && rules !== null` 时计算，规则一条不减。
6. 未签约球员额外贡献一条 `rule: 'contract'` 的 issue，并置 `pass = false`（不占人数、不计工资、上不了场）。
7. `POST /api/club/registrations` 不再存在（404）；`registration_check_mode` 的 config 行保留、代码不再读取。
8. 管理端 `GET /api/admin/registrations`：当前季 `source: 'live'` 现算（带 `isCpu` / `unsigned`），历史季 `source: 'archive'` 读 `registrations`。
9. 管理端 `GET /api/admin/compliance`：同上 live/archive；`not_registered` 只在存档路径出现。
10. `demand-ops` 的 roster 由 `contracts.contract_type` 推导 `squad`，不再读 `registrations`。
11. 前端工作台不再有「分配 ▾」「提交名单」「超帽确认弹窗」「特例期放行档 banner」。

## 2. In / Out

- **In**：视图推导与三桶、squad 响应形状、管理端 live 现算、需求规则数据源、前端只读化、静态锁。
- **Out**：薪资三段与基线表（期二）、关窗看板与核验存档/通知（期三）、`registrations` 表本身的迁移（表保留，降级为存档）。

## 7. 期二：窗口期薪资三段

### 口径

12. `now` = Σ 本队 `is_active` 合同（含训练营 0.75），与 `window-payroll.ts` 扣费基数同一个数。
13. `baseline` = 开窗瞬间的 `wage_total`（新表 `club_wage_baselines`，主键 `(season, window_seq, club_id)`）；本窗没有行 → `null`，前端退两段，不显示假的 0（D12）。
14. `delta = now - baseline`；`baseline` 为 null 时同样为 null。
15. `projected = now + 待生效增量`，只含已过户、条款未定（`terms_applied = 0`）的人（D14）。
16. `overspend = max(0, now - cap)`；未报名定级赛事时 `cap = null`、`overspend = 0`。
17. `inCount` = 本窗 `completed` 且 `to_club_id` 为本队的 `transfer` / `activation` / `forced_auction` / `free_agent`；`outCount` 再加 `termination`，排除 `rc_change` / `match`（D13）。
18. 开窗批写基线时排除 CPU 队（与工资不扣 CPU 同口径）。
