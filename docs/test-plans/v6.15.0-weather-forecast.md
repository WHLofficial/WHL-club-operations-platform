# 测试计划 · v6.15.0 天气预报表（赛前按轮预报）

本计划承载 v6.15.0 的验收口径：天气从「赛果确认时逐场现掷」改为「管理员按轮手动触发预报」，预报值落新表 `match_weather`，确认钩子按「事件预置 > 场次预报 > 现掷」三档优先级消费。

- **TC 编号即执行层 vitest 用例名**，按 `describe('TC-MIG')` / `describe('TC-FC')` / `describe('TC-PV')` / `describe('TC-PRI')` / `describe('TC-PUB')` / `describe('TC-CACHE')` 分组。
- **用例总数 50（P0 34 / P1 13 / P2 3）**；变异验证清单 10 条。
- 建议落点：新增 `tests/weather-forecast.test.ts`（MIG/FC/PV/PRI）与 `tests/fixtures.test.ts`（PUB/CACHE）；回归不动（见文末套件）。
- 涉改文件：`src/db/migrations/0057_match_weather.sql`、`src/worker/weather-ops.ts`（新，`forecastRound`）、`src/worker/routes/admin/weather.ts`（新）、公开只读 fixtures 路由（新文件）、`src/worker/home.ts`（消费端 289-293 行区块）、`src/lib/cache-policy.ts`、`tests/d1.ts`（MIGRATION_FILES）。
- **数值上下文**：`weather_probabilities`(40/30/20/10) 与 `weather_ranges` 四区间是用户裁决值，本版**零改动**；天气与上座的所有既有数字断言必须逐字不变。

## 0. 基线常数（本计划全部数值断言的推算依据）

推算自 `src/core/config.ts:125-147`（attendance_model 默认值）+ `src/core/config.ts:149-154`（tier_table 默认值），场景对齐既有夹具 `tests/event-ops.test.ts:974-987`（主队球场 fans=1800/capacity=20000/tier=0/shell=90/next_attendance_mod=1/next_weather=''，客队无球场行 → awayInfluence=default_influence 90，停用随机事件）。

- 固定 `rng = 0.5`（`env.rng`，`src/worker/env.ts:13`）。
- 需求常数：`multiplier = 4.0`；`tierCoef(tier0) = 1.0`；无战绩 → neutral 4 分 → `form_coef_table[4] = 1.0`；`opp = 1+0.05×(90/90) = 1.05`；`uniform(perturbation)=1.00`；`sell_out_fill` 取 0.992（不生效，demand < capacity）。
- **K = 1800 × 4.0 × 1.0 × 1.0 × 1.05 = 7560.0**；`上座 = floor(K × wx)`。
- 天气系数（rng=0.5 → 区间中点）：晴 `1.15`、多云 `0.97`、雨 `0.845`、雪 `0.77`。
- 对应上座：晴 `8694`、多云 `7333`、雨 `6388`、雪 `5821`。后两档与既有用例逐字一致（`tests/event-ops.test.ts:996-997` 多云 7333、`:1023` 雨 6388），基线可信。
- **rng 消费次数**（计数 rng 断言用）：预报命中 = **2**（perturbation + fill）；事件预置且无预报 = **3**（wx + perturbation + fill）；无预报无预置 = **4**（weather + wx + perturbation + fill）。消费顺序固定为「weather → wx → perturbation → fill」，预报命中时前两笔整笔不抽。
- 收入档（ticket/commercial/broadcast）走设施等级：夹具 `club_facilities` 为 commercial=2 / broadcast=3 时，`ticket = round(wan×1.5, 2)`、`commercial = round(wan×0.1×2, 2)`、`broadcast = 0.3×3`（`src/worker/home.ts:329-333`）。

## 范围

**In scope**

1. 迁移 0057：`match_weather` 表结构、索引 `(tournament_id, round)`、`tests/d1.ts` MIGRATION_FILES 追加。
2. `POST /api/admin/weather/forecast`（触发预报）+ `GET /api/admin/weather/forecast`（预览），权限键 `club.registrations.manage`，审计 `weather_forecast`（origin='user'）。
3. 消费端三档优先级（`src/worker/home.ts:288-293` 及 memo 文案 `:343`）。
4. 公开只读 `GET /api/fixtures?tournament_id=&round=`（assertPublicRate + cachedJson，scope `fixtures` TTL 1h）。
5. 缓存治理：`CacheScope` 增 `fixtures`、`CACHE_TTL_MS`、`PUBLIC_SCOPES`（3→4）、`WRITE_SCOPE_PREFIXES` 派生数组断言同步 3→4。
6. 回归锁：预报缺席时行为与 v6.10.0/v1.5.0 逐字一致。

**Out of scope**

- 天气概率/区间数值调整（40/30/20/10 与四区间冻结）。
- 事件预置写端 `weather_set`（v6.10.0 `event-ops.ts`，行为已锁，只测消费侧）。
- CPU 队（tour 队无平台映射）的天气展示与预报；无球场行俱乐部的预报。
- 前端/管理台 UI；赛事系统侧 round 语义与赛程变更流程。
- `match_weather` 历史回填（旧场次无预报属预期，不补）。

1. **并发触发：两个管理员同一时刻触发同一轮**（两次 POST 同时进入，各自读到"未预报"）。
   - 口径：`match_weather.match_id` 是 PK，第二笔 INSERT 冲突即幂等（TC-MIG-02/TC-FC-03）。
   - 取数：并行两次 trigger 后断言 `COUNT(*) = 该轮可预报场次数`、每场 `weather/wx_coef` 唯一且落在区间内；任一 500 视为不通过（应被吞成"已存在"或整批回滚）。**若实现是逐场 INSERT 而非批量事务，需实测中断点并在此回填**。
   - 实测（2026-10-01）：实现为一次 `DB.batch([逐场 INSERT ... ON CONFLICT DO NOTHING, audit])`，非逐场提交；两次并发 POST → 一个 200、一个 500（夹具单连接 BEGIN IMMEDIATE 的 "cannot start a transaction within a transaction"，生产 D1 为独立会话）；落库 3 行 = 可预报 3 场，每场唯一且在区间。数字见「执行留痕」。
2. **预报后赛果先确认，再触发同轮预报**。
   - 口径：已确认场次跳过（`match_attendance` 存在）→ 预报不覆盖已落库的实际天气（TC-FC-04）。
   - 取数：确认一场后触发同轮，断言该场 `match_weather` 仍无行（或保持原值）、`match_attendance.weather` 不变、`/api/fixtures` 该场返回实际值；再断言 `confirmResult` 重放仍是 `detail=null`（双闸，TC-PRI-09）。
3. **TOUR_DB 该轮没有主队场比赛**（轮次未排、或全是 CPU 主场/客队场次）。
   - 口径：触发返回 200 + 四段全空/全跳过；不写 `match_weather`、不写多余 ledger；预览同参返回空列表。
   - 取数：TC-FC-09 + TC-PUB-06 跑一次；确认审计是否留痕（口径见 TC-FC-09 回填），并确认 `/api/fixtures` 返回 `matches: []` 且不写空数组以外的形状。
4. **`wx_coef` 存了非法/异常值（人工改库）**。
   - 分档口径：合法但极端（1.0 / 区间端点）→ **直用**（TC-PRI-07）；NULL / 文本 / 0 → **不在防御范围**，但必须实测「不抛异常、`match_attendance.weather` 与 memo 仍可读、上座为整数或 0」，并把实测结果回填本行（若出现 NaN 落库，登记为必修缺陷而非"已知不防御"）。
   - 取数：手工 UPDATE 三种形态各跑一次 `confirmResult`，记录落库值。
   - 实测（2026-10-01）：NULL 被表级 NOT NULL 拒绝；文本 `'abc'` 可落库（typeof=text）→ demand=NaN → 整批语句失败，无 match_attendance / 无 memo，`needsReview=true`；`0` → attendance=0 正常入账。均无 NaN 落库，不登记必修缺陷。
5. **（附加核对）预报后该场主队被替换/改期**：`match_weather.club_id` 与解析出的主场不一致，口径见 TC-PRI-10；报通过前必须给出实测落库值（预报被用 / 被跳过），不能留"未测"。
