## 1. 口径（实现即契约）

| # | 口径 | 落点 |
|---|---|---|
| 1 | 在途挂牌 = `status IN ('listed','bidding','matched_pending') AND type <> 'forced'`；强拍单独立成表 | `src/worker/workbench.ts` |
| 2 | CPU 参与方默认隐藏；**转会只看卖方**（CPU 不买人，过买方会把「真人买 CPU 球员」藏掉）；**强拍不做 CPU 过滤** | 同上 |
| 3 | 列表只回 `hasProof` 布尔，凭证 key 不随列表下发 | 同上 |
| 4 | 五表各 `LIMIT 50`，一次 `Promise.all` 取全 | 同上 |
| 5 | 搜索：纯数字并行探 7 种 id（球员内部 / FC id / 俱乐部 / 挂牌 / 出价 / 谈判 / 转会）；文字查球员名 + 俱乐部名，各 10 条；`%` `_` 走 `ESCAPE '\'` | 同上 |
| 6 | 三个工作台端点全部 `requireAdmin`；`cpu` 只认 `0`/`1`，`q` 空串回空、>64 字符 400，`listingId` 非正整数 400 | `src/worker/routes/admin/workbench.ts` |
| 7 | 凭证可见范围：管理员全可见；卖方（`seller_club_id` 命中所绑队）可见；其余 403；无凭证 404 | `src/worker/routes/market.ts` |
| 8 | 前端凭证按钮自己探一次端点，非 200 一律不渲染（不把 403 显示成红字） | `web/src/pages/market/ActivationProofButton.tsx` |
| 9 | 桌面端侧栏 `max-height: calc(100dvh - var(--topbar-h) - 24px)` + `overflow-y: auto`；窄屏抽屉不变 | `web/src/styles.css` |
| 10 | 迁移 `0089` 只建索引，`IF NOT EXISTS`，可重放 | `src/db/migrations/0089_bids_status_index.sql` |

## 2. In / Out

**In**：五表数据与 CPU 过滤、凭证权限四态、搜索七种 id 与文字、迁移登记、侧栏滚动。

**Out**：工作台动作（暂停/恢复/强制送审/作废/强制成交/取消强拍）的**业务结果**——这些走的是既有端点，行为由各自测试锁；本期只保证按钮打到正确路径与带原因。

## 6. 已知边界

- 五表各 50 条上限、无分页（在途量级远小于上限；真顶到上限时按时间升序只看到最老的 50 条）。
- 「显示 CPU」不记忆，刷新回默认隐藏。
- 凭证按钮对非激活单会白打一次 404（换来决定是否渲染的简单性）。
- 工作台是只读+动作台，**不替代**审核队列：`transfer_confirm` 仍要去 `/admin/market` 逐条看（批选仍在期 B 的队列页）。
