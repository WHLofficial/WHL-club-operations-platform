## 2. 改动面

### 2.1 导入公式（`src/worker/players-import.ts` upsert）

- china 行：`pa = MAX(excluded.pa, 83)`（与 Q1 守卫同句）。
- **全量**（minor/major 两分支）：`ca = MIN(最终 pa, excluded.ca + δ)`，δ 按模式取（minor 全保留 / major ⌈δ/3⌉；china 行 major 也全保留）。
- 钳制对**最终 PA** 取 MIN（即 china 行按 83 钳，不是按源值 55-79）；已购 PA 点回放（+台账、上限 95）在 upsert 之后，只会再抬 PA，不破钳。
- 插入时 growable 建议值：china 行 `ca < pa`（不看年龄）；冲突分支本就不更新 growable（维持现状）。

### 2.2 赛季结算 / 开季重判（`src/worker/season-settle.ts:184-193`、`src/worker/routes/admin/seasons.ts`）

- `growableStatement` 给 `china_plan=1` 开例外：不看 `age_cap`，只看 `ca < pa`。**两处调用（开季重判 + 赛季结算）都要改**，否则一次性批下季被冲掉。

### 2.3 档位（`src/core/growth-tier.ts`）

- `GROWTH_TIER_CONDITIONS` c3 `points: 1 → 2`（UI 显示「中国籍 +2」自动跟随）；`GROWTH_TIER_SQL` 中 c3 项改 `2 * (…)`。
- 生产批重算存量 `growth_tier`（用 SQL 表达式直接 UPDATE）。

### 2.4 徽章名额（`src/worker/growth.ts` grantChinaPlaystyles、`src/core/playstyle-rules.ts`）

- 名额公式不变（`quota = china_badges(3) − 现存 source='china' 行数`），新增约束：**kind='gold' 的行至多 1 条**。
- 金进金槽（13-15），沿用 v6.63.0/v6.81.0 抑制语义（金明细盖 FC 同基础银、删行复原）。

### 2.5 config

- `china_xp_bonus` 默认 20→40（改 `src/core/config.ts` 默认值；实现时核对生产 `config` 表有无该行——若像 `badge_cap_silver` 一样无行则代码默认直接生效，有行则批内 UPDATE）。

### 2.6 UI

- 签约前权益展示：谈判 / 海捞 / 球员页头部，列「PA 不低于 83 · 每季 +40 XP · 档位 +2 · 3 银或 2 银+1 金」。
- 名额未领提醒：站内通知（一次性，勿重复轰炸）。
- 待升级列表展示收口：练满 PA 后 pending 级 CA 收益为 0（钳制），别让它以「+0」形式挂在 UI 上。

### 2.7 生产数据批（`scripts/prod-20261110-china-plan/`，按惯例不 commit）

- 399 行 `pa = MAX(pa, 83)`；growable 按 china 例外式重判；`growth_tier` 重算；审计（`origin='user'`/actor=用户）；KV `cache:epoch:public` bump。
- 与代码同版上线（Q18）。

### 2.8 明确不做

## 4. 风险与边界

1. **规则文本同步 3 处**（用户自行改规则书）：XP 20→40、档位「中国籍 +2」、名额「3 选 1 可金」（规则书写「自选 3 银徽章」）。PA 83 本就是规则书原文。
2. ≤18 岁 19 人 = c3+c5 双加成（4 档），一季从 55 冲顶；pending 级 CA=0 的展示收口见 2.6。
3. 训练营 7 坑：中国项目与本土苗子抢位（均用 3.8/7，目前不紧）。
4. 399 人价值重估后自由市场被扫货——受 30 人帽 + 营 7 自然限制，且正是设计意图。
5. 中国球员 30+ 岁 141 人也能进营/一线成长（Q3/Q11 的直接后果，用户已裁定接受）。
6. `young_blend_age`（25，工资混合档）与 growable 年龄帽是两个不同 config，Q3 只动后者。
