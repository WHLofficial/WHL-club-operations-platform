## 0. 一句话结论

把「点激活 → 直接弹系统文件框 → 选中即上传」改成「点激活 → 打开说明弹窗 → 选中后先看预览和三样检查 → 点确认激活才上传」，并让转会市场激活页与球员页 SideOps 两个入口共用同一个弹窗。

## 1. 问题与边界

### 1.1 现状

两个入口都是隐藏 `<input type="file">`：

- `web/src/pages/market/MarketActivationPage.tsx` 的 `ActivateSection`：点行内「激活」直接 `proofInputRef.current?.click()`，选中文件后立即上传并创建激活。
- `web/src/pages/player/SideOps.tsx` 的 `activatePanel`：面板里直接摆文件输入框，点「提交激活」才上传。

玩家在选文件前看不到「什么算合格截图」，选错后只能靠服务端 400 或管理组事后核查；页面底部还写着「证据制」这类内部词。规则 4.4.2.2 要求激活方私信被激活方，消息里要有激活方名、球员名、匹配提醒，并截图发给转会管理方——这个标准应该在上传前就摆出来。

### 1.2 In scope

1. 新增共用弹窗组件：拖拽/点选、客户端校验、缩略图预览、三项检查、示例折叠、确认后才上传。
2. 转会市场激活页与球员页 SideOps 两个入口接入同一弹窗。
3. 文案去掉「证据制」，改成普通玩家能读懂的第二人称说明。
4. `GLOSSARY.md` 增加两条术语。

### 1.3 Out of scope

- 不改 `POST /api/media/activation`、`POST /api/market/activations`、R2 存储、5MB/类型服务端校验。
- 不做图片内容识别（OCR 校验俱乐部名/球员名）、不做自动审核。
- 不改举报入口与匹配窗规则。
- 不新增后端表、迁移或配置键。

## 2. 领域模型与术语

规则 4.4.2.2 的三项信息是合格判据：**激活方名、球员名、匹配提醒**。界面上用第二人称，不直接写「激活方 / 被激活方」：

| 术语 | 定义 | 界面用法 |
|---|---|---|
| **激活通知** | 激活方在 QQ 私信被激活方主教练的消息，须包含激活方名、球员名、匹配提醒 | 「先在 QQ 私信对方主教练」 |
| **激活通知截图** | 上述通知的截图，作为凭证上传给转会管理方 | 标题「上传激活通知截图」 |

_Avoid_：证据图、证明图、QQ 截图（单独使用时指代不明）、证据制（内部流程词）。

## 3. 交互与状态

### 3.1 打开

点「激活」不再触发文件框，而是打开居中弹窗（复用 `.modal-mask` / `.modal-card card`）。弹窗标题「上传激活通知截图」，正文先给合格标准，再给上传区。

### 3.2 选择文件

上传区是一个可点击的拖拽区：

- 点击 → 打开系统文件选择器（`accept="image/png,image/jpeg,image/webp"`）。
- 拖入 → `dragover` 高亮，`drop` 取第一个文件。
- 选中后进入预览态：缩略图、文件名、大小、「重新选择」按钮。
- 预览态下不再显示拖拽区，避免重复投放。

### 3.3 客户端校验

按顺序校验，失败留在弹窗内显示错误，不调用上传接口：

1. 文件为空（`size === 0`）→「截图是空的，换一张试试」
2. 类型不在 `image/png`、`image/jpeg`、`image/webp` →「只支持 png、jpg、webp 图片」
3. 超过 5MB（`5 * 1024 * 1024`）→「截图超过 5MB，压缩后再传」

服务端原有校验保留，作为第二道闸。

### 3.4 确认与失败

- 底部按钮：「取消」「确认激活」。未选文件时「确认激活」禁用。
- 点「确认激活」才调用上传：`POST /api/media/activation` → 拿 `key` → `POST /api/market/activations`。
- 提交中按钮显示「提交中…」，取消、关闭、重新选择、遮罩点击全部禁用。
- 失败：弹窗不关，显示接口错误或「激活失败，请重试」；用户可重新选择或重试。
- 成功：由父组件关闭弹窗。转会市场页照旧进入「落激活首价」表单；球员页照旧刷新并 toast。

### 3.5 关闭

- Esc、点遮罩、点「取消」均可关闭；提交中禁止。
- 关闭或换图时释放 `URL.createObjectURL` 生成的预览地址。

## 4. 文案

### 4.1 弹窗

| 位置 | 文案 |
|---|---|
| 标题 | 上传激活通知截图 |
| 说明 | 激活前，先在 QQ 私信对方主教练，再把通知截图传上来。 |
| 检查项标题 | 截图里要看清三样： |
| 检查项 1 | 你的俱乐部名 |
| 检查项 2 | 球员名 |
| 检查项 3 | 一句提醒：竞价结束后请选择是否匹配 |
| 示例折叠 | 看一条示例 |
| 示例正文 | `{对方俱乐部}主教练您好，我是{你的俱乐部}主教练，我方即将激活您的球员「{球员名}」，请在竞价结束后根据规则选择是否匹配。` |
| 拖拽区 | 把截图拖到这里，或点此选择文件 |
| 格式提示 | png、jpg、webp，最大 5MB |
| 主按钮 | 确认激活 / 提交中… |
| 次按钮 | 取消 |

示例优先用当前球员与两家俱乐部的真实名字；缺名字时回退为规则原文的示例（国际米兰 / 利物浦 / 阿切尔比）。

### 4.2 页面说明

转会市场激活页底部改为：

> 训练营球员激活费固定 5.00m；正式球员按违约金与保护期计。点「激活」后，先上传你在 QQ 里发给对方主教练的通知截图；对方没收到可以举报。激活成功后本页会摆出首价表单：5 分钟内落首价（=激活价）才转公开竞价。

球员页 SideOps 不再内嵌文件框与「证据制」说明；点「激活」直接开同一弹窗。

## 6. 验收与测试

- 组件测试覆盖：打开文案、三项检查、点选、拖拽、类型/大小/空文件拦截、预览后确认、取消不发请求、上传失败留在弹窗、成功由父组件关闭。

## 7. 风险与取舍

- **不做客户端图片内容校验**：俱乐部名/球员名是否清楚只能靠人看。把标准前置到弹窗，管理组仍按现流程核查。
- **预览用 object URL**：jsdom 不实现，测试里需要 stub；组件卸载/换图时统一释放，避免内存泄漏。
- **两个入口共用组件**：SideOps 原本是内嵌面板，改成弹窗后交互层级变化；但文案与校验只维护一份，避免两个入口再次漂移。
- **移动端文件选择**：微信/手机相册返回的 MIME 可能是 `image/jpeg`，与 `accept` 一致；不接受 HEIC，服务端本来也不收。
