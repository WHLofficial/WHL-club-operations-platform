## 1. 三入口统一进竞价（后端核心）

### 1.1 现状与靶点

- 主动挂牌 → listed → 出价进 bidding：**已进竞价，不动**
- 报价 accepted → `fulfillAcceptedOffer` 自动生成 listing + 首价 bid：**已进竞价，不动**
- 激活 → `routes/market.ts:797-798`「激活挂牌不开放竞价：激活方的首价就是成交价」+ 训练营首价落定即送审、正式合同进 matched_pending：**唯一跳过竞价的路径，本轮废除**

### 1.2 新激活流程

1. 激活挂牌照旧（type='activation'，ask_price=激活价，激活方 5 分钟首价窗：仅激活方可出价、金额固定 = 激活价）
2. 首价落定 → `status='bidding'` + `deadline_at`（按 §2 判定规则，静默起点 = 首价时刻）——**首价从成交价变为起拍价**，公开竞价开始
3. 竞价期间任何人可加价（步长、冻结、过线守卫与普通挂牌同轨；`seller_club_id` 不可出价的限制照旧——被激活方自己不能买回，匹配权另说）
4. 竞价截止（静默满）：
   - **训练营**：直接 `pending_review`（合同固定，无匹配环节），最高价成交
   - **正式合同**：进 `matched_pending`（24h 匹配窗）——被激活方按「新违约金 > **最终最高价**」决定 match（付差额留队）/ pass（按最高价成交）；到期未匹配按最高价成交进待审。匹配基准从首价改为最终最高价（`submitMatch` 的 `bid.amount` 取 active 最高价已天然如此，改的是文案与通知口径）

### 1.3 改动点

- `routes/market.ts` 出价处理器：删 797-798 的「不开放竞价」拦截；激活分支的 `listingAdvance` 从「matched_pending + match_deadline」改为「bidding + deadline_at」；训练营「首价落定即 settleListingForReview」删除（改为进竞价）
- `market-settle.ts`：activation 的 remnants 收口（listed 过期带出价 / bidding → 直接送审）改走通用静默期判定；matched_pending 到期结算复用（`settleListingForReview` 的 fromStatus 已支持）；训练营 activation 单竞价截止 → 送审（无匹配窗）
- `activations.ts`：`submitMatch` 文案与通知改口径（「新违约金必须高于最终最高价」）；到期通知照搬
- 前端：`matchPhase` 语义更新（`api.ts` 类型注释）、匹配窗文案、`MarketBidForm` 激活分支提示
- 种子/文档：`scratch/seed-transfers.sql` 的 matched_pending 演示行语义仍成立（竞价截止后进匹配窗）

## 2. 竞价截止判定（规则文档化，引擎不改）

用户 2026-10-03 场景题裁决：**窗内重新数 3 小时 + 不满足顺延下一天**（即现行 `bidDeadline` 行为）。

1. 判定窗：每日 18:00–23:00（config `deadline_hours`），交易日历（`trade_calendar`）节假日跳过；从挂牌**次日**的窗开始生效
2. 窗内静默起点 = max(最后一次出价时刻, 18:00)；连续 `silence_hours`（默认 3）小时无新出价 → 静默满时刻 = 截止/成交时刻
3. 窗内凑不满（如出价在 20:00 后，+3h 出窗）→ 顺延下一天同窗重新数
4. 每次新出价 → `deadline_at` 重算（新出价即静默起点），浮层与卡片即时刷新
5. **行为变更（用户 2026-10-03 确认口径：第一天挂牌 → 截止起初即第二天 21:00）**——现行实现的三处缺口一并补齐：
   a. `POST /market/listings` 挂牌时即调 `bidDeadline`（lastBidAt = 挂牌时刻）落 `deadline_at`（无人出价情形 = 次日 21:00）；
   b. 前端 listed 状态也渲染倒计时（现行只在 bidding 显示，listed 脚行只有「还没人出价」——改为出价数 + 倒计时并列）；
   c. `settleOverdue` 不再跳过 listed：`deadline_at` 到点 → 无人出价走 `delistUnbid`（下架费、球员还原、冻结释放照现行逻辑），有人出价的单走原静默结算。激活挂牌例外：首价窗（`activation_deadline`）优先，激活方未落价走 `voidExpiredActivation` 作废，落价后进 bidding 才按本判定
6. 显示层：卡片倒计时 `hh:mm:ss` 读秒（全局单一定时器 1Hz 驱动全页，不逐卡 interval）；超 24h 显「X天 HH:MM:SS」；最后 1 小时红色；绝对时刻「M月D日 HH:MM 判定」收进浮层小字并随倒计时同源反推
7. **归零即拒（用户 2026-10-03 补充铁律：时间归零时无论后端是否结算都拒绝出价）**——前端倒计时到 0 立即禁用出价提交（不等后端确认）；后端三层硬闸补齐：
   a. 出价处理器过线检查扩到激活首价窗：现行只查 `deadline_at`，激活挂牌首价窗内该列为 NULL → 补「`type='activation' AND status='listed' AND activation_deadline <= now`」分支（激活方落价同样被拒，等作废）；
   b. 触发器 `fund_holds_bid_deadline_guard` 同口径扩展（新建迁移），堵住「惰性结算未先跑时激活方过线落价」的竞态窄口；
   c. 竞价单 `deadline_at` 过线的现有拒绝（409「这单竞价已截止」）与触发器兜底保留不动
8. **时间来源权威（用户 2026-10-03 铁律：时间的来源要可靠，避免被黑）**——分层锚定：
   a. **判定权威只在服务端**：截止判定全部用服务端时钟（D1 触发器内 `strftime('now')` 的 SQLite 时钟 + `settleOverdue`/出价处理器的 Worker 时钟）；前端倒计时是纯显示，被篡改（改本机时间/改 JS）对结算零效力——§2.7 的三层硬闸即防篡改的最终答案；
   b. **前端倒计时不信任本机时钟**：以服务端下发的 `deadline_at` 为锚、流逝量用单调时钟（`performance.now()` 差值）累计，本机改时间不影响显示走秒；接口响应必要时附带 `serverNow` 供校准；
   c. `deadline_at` 的写入源唯一：服务端计算（挂牌/出价处理器），客户端传任何时间参数一律不采信（现行接口本就不收客户端时间，保持）。

### 5.3 出价校验矩阵

后端（`POST /api/market/listings/:id/bids`；✚ 新增）：
- ✚ `Number.isInteger` → 400「出价须为整数（m）」；`Number()` 前置类型白名单（拦 '12abc'、1e3 记法按产品口径定：整数校验天然拦 1e3=1000? 否——`Number.isInteger(Number('1e3'))` 为 true，需字符串格式校验 `/^\d+$/` 或接受科学记数法；**裁决：接受 Number 语义、只校验整数值**，'1e3' 等价 1000 可过）
- ≤0 / 非有限数：已拦，保留
- 竞价暂停（全局/单卡 423）、已截止、窗已关、自己的挂牌 403、状态机 409、激活首价窗（非激活方 403 / 金额≠激活价 400）、首价 < 挂牌价、抬价 < 最高价+步长、资金不足（预检+触发器兜底）：**全部保留**
- 单笔上限：**不加**（可用资金即天花板）；如需「不超过挂牌价 X 倍」护栏由用户后续给倍数

前端（浮层表单，新增就地校验层）：
- `inputmode="numeric"`；**输入框预填默认值 = 符合规则的最低出价**（无人出价 = `ceil(挂牌价)`；有人出价 = `ceil(当前最高 + 步长)`；激活首价窗 = 激活价）——可直接点出价快捷加价，也可改大；行情刷新（他人出价）后默认值与最低要求同步重算。整数化与现有下限规则的交互：挂牌价本身可为小数，最低合法整数出价一律向上取整（`ceil`），后端 `validateBidAmount` 同口径
- 提交前就地校验：整数 / ≥ 当前最低要求（无人出价=挂牌价；有人出价=最高+步长，随行情动态）/ ≤ 可用资金，任一不满足红字标输入框下方、不发请求
- 出价按钮 loading 防连点；服务端 400/409/423 映射浮层内可读红字（全局 toast 保留）

## 9. 风险与边界

- 激活进竞价后，`listings` 的 `match_deadline` 列语义变化（只在 matched_pending 阶段使用）；存量 matched_pending 行（如 dev 种子 L103）兼容读侧

- §2.5（挂牌次日无人出价即下架）改变现行窗尾收口时点：下架费、球员还原、通知的触发时机提前，需在测试计划中单列回归（窗尾 delist 的既有测试改判定窗口径）
- 激活单进竞价后「一窗一次」额度语义不变（激活作废仍占额，§6.2 假设口径）
