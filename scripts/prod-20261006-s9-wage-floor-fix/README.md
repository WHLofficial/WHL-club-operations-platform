## 6. 执行器通道纪律（继承先例批）

- 用法：`node exec-shards.mjs <sql 文件> --remote|--local [--chunk=N] [--dry] [--retry=N] [--persist-to=<dir>]`；不带 `--remote` 默认 `--local`。
- 闸门：单条语句 > 4000 字节 ⇒ exit 3；单条含 `" % & | < >` ⇒ exit 3（`--command` 通道会被 shell 解释）；`--persist-to` **只认等号形式**（空格形式被静默忽略，会打到默认 `.wrangler/state`）。
- 通道：`--file` 下整批一个事务；本批走 `--command` 分批（每批若干条、批内顺序执行）。`--local` 不回传 changes。Windows 偶发 `exit 3221226505` + `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)` ⇒ `--retry` 兜住即可。
- **幂等设计（v2 版，2026-10-08 事故后重排）**：每队三条语句、顺序固定 **② 工资行触底（翻标记 OLD→NEW）→ ① 顺移「工资行之后的本队流水」→ ③ 账户对账**（「账户 ≠ 最新流水 `balance_after`」才写）。守卫分别是：② =「`amount = −旧值` 且 memo 尾为『 人现行合同）』」；① =「工资行已在触底值（memo 含『，按下限扣）』）**且** `nextChainBroken`（下一条本队流水与工资行不相接）」；③ = 对账不等才写。
  - 四种状态（P 全未跑 / M 只跑 ② / X 只跑 ① / N 全跑）**任一态跑一次 ②①③ 都收敛到 N**，N 态重放**全空跑**；回滚同理（②' 还原 → ①' 加回 → ③' 对账）。
  - 「下一条本队流水」必须用 `nextRowId` = `(SELECT MIN(m.id) … WHERE m.club_id = 本行 club_id AND m.id BETWEEN 本行 id + 1 AND 2147483647)`——**绝不能写成 `id + 1`**：生产 id 跨队交错，相邻假设恒假（首跑事故根因，`report.md` §2）。
- 执行后必跑 `03-verify.sql`（只读）：v2 不变式与 v3 合计能立刻暴露任何中途状态；预检 I 段的链诊断（linked / broken / no-downstream）能直接看出「顺移是否已做」。
