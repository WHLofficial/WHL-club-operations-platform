演练暴露并修掉的两个工件级问题（留在生成器注释里）：

1. **① 的守卫原来只认「OLD 标记」** ⇒ 只跑 ① 两次会**重复顺移**（实测 club 5：prize 108.5 → 104.73 → 100.96、shop 106 → 102.23 → 98.46，工资行不动）。修法：① 增加锚 `nextChainIntact`——工资行的**下一行**必须仍首尾相接（`n.balance_after = w.balance_after + n.amount`）；顺移一旦发生这条等式即假 ⇒ 重放 ① 空跑，且「① 已跑、② 未跑」的中途状态重跑整件即收敛（② 翻标记、③ 对账）。工资行是末行时锚恒假 ⇒ ① 空跑（本来也无行可移，与预检 C 段为空的情形一致）。
2. **原稿用 `id > (SELECT …)` 与 `instr(…) > 0`** 会撞 `exec-shards` 的元字符闸（`>` 在 cmd.exe 下会被当重定向）⇒ 改写为 `id BETWEEN (…) AND 2147483647` 与 `instr(…) != 0`。

其它演练口径：本地 wrangler `--local` **不回传 `meta.changes`**（恒 0）⇒ 演练用「行值逐字段比对」判定幂等，不看 changes；`scratch/` 在 `.gitignore` 内，演练件不会误提交。

## 6. 执行器通道纪律（继承先例批）

- 用法：`node exec-shards.mjs <sql 文件> --remote|--local [--chunk=N] [--dry] [--retry=N] [--persist-to=<dir>]`；不带 `--remote` 默认 `--local`。
- 闸门：单条语句 > 4000 字节 ⇒ exit 3；单条含 `" % & | < >` ⇒ exit 3（`--command` 通道会被 shell 解释）；`--persist-to` **只认等号形式**（空格形式被静默忽略，会打到默认 `.wrangler/state`）。
- 通道：`--file` 下整批一个事务；本批走 `--command` 分批（每批若干条、批内顺序执行）。`--local` 不回传 changes。Windows 偶发 `exit 3221226505` + `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)` ⇒ `--retry` 兜住即可。
- **幂等设计**：每队三条语句、顺序固定 ① 顺移 → ② 工资行触底（翻标记 OLD→NEW）→ ③ 账户对账（「账户 ≠ 最新流水 `balance_after`」才写）。② 在 ① 之后 ⇒ 重放时 ①② 守卫全假、③ 天然幂等。任意中途崩溃状态重跑整件都会收敛（演练阶段 4/5 实证）。
- 执行后必跑 `03-verify.sql`（只读）：v2 不变式与 v3 合计能立刻暴露任何中途状态。
