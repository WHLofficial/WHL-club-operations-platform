## 2. 事故：① 的锚假设「流水 id 相邻」

`gen-wage-floor-fix.mjs` 原有的 `nextChainIntact(id)` 这样判「工资行与其下一条流水首尾相接」：

```sql
JOIN ledger_entries w2 ON w2.id + 1 = n.id     -- ← 要求 id 恰好相邻
```

`ledger_entries.id` 是**跨队全局自增**，生产各队流水 id 交错分配：club 5 的工资行是 id 229，它的**下一条本队流水**是 id 277（228/230–276 都是他队行）。⇒ 锚恒假 ⇒ 每队 ①（顺移下游）全部空跑；③（账户对账）因 tail 与账户仍相等也随之空跑。

后果：只有 ②（工资行触底）照常落库 ⇒ club 5 / 449 停在**半成品态**（工资行已改、下游未移、账户未对账），账链中段断开：

| 队 | 半成品态 | 说明 |
| --- | --- | --- |
| club 5 | 工资行 −53 / 16.82，账户仍 27.19，row 277 仍 27.19 | 16.82 + 6.6 = 23.42 ≠ 27.19 ⇒ 断 |
| club 280 | 工资行 −43 / 42.95，账户 42.95 | 无下游行 ⇒ 恰好完整（唯一未被伤到的队） |
| club 449 | 工资行 −53 / 50.29，账户 48.98，245–254 六行未移 | 断 |

首次执行 changes = 4 的构成：club 5 ②=1、club 280 ②=1 ③=1、club 449 ②=1，其余守卫全假（0）。这与「期望 6 + Σk = 13」的偏差正是缺陷的可观测信号。

停手不继续的理由：① 空跑意味着「③ 会把账户写成**未顺移的 tail**」，继续跑只会把半成品态固化，故先取证再修。

## 3. 修复（生成器）

1. **删** `nextChainIntact`（id 相邻假设）；**新增**：
   - `nextRowId(id)` = `(SELECT MIN(m.id) FROM ledger_entries m WHERE m.club_id = id AND m.id BETWEEN (SELECT w.id + 1 FROM ledger_entries w WHERE w.club_id = id AND w.kind='wage' AND w.ref_type='window' AND w.ref_id=901) AND 2147483647)`
   - `nextChainBroken(id)` = `NOT EXISTS (SELECT 1 FROM ledger_entries n WHERE n.club_id = id AND n.id = nextRowId(id) AND ROUND(n.balance_after,2) = ROUND((SELECT x.balance_after …工资行) + n.amount, 2))`
   - 判据只用 `BETWEEN` / `ROUND` / `instr(…) != 0`（`exec-shards` 的 shell 元字符闸拒 `" % & | < >`）。
2. **语句顺序**：正向由 ①→②→③ 改为 **② 工资行触底 → ① 顺移下游 → ③ 账户对账**；回滚由 ①'→②'→③' 改为 **②' 工资行还原 → ①' 下游加回 → ③' 对账**。
   - ② 守卫「`amount = −旧值` 且 memo 尾为『 人现行合同）』」；① 守卫「工资行已在触底值（memo 含『，按下限扣）』）**且** `nextChainBroken`」；③ 守卫「账户 ≠ 最新流水 `balance_after`」。
   - 四态（P 全未跑 / M 只跑② / X 只跑① / N 全跑）**任一态跑一次 ②①③ 都收敛到 N**，N 态重放全空跑。
3. **01 预检扩到 A–I**：新增 H（CPU 两队的工资行 + 之后全部流水 + 账户）与 I（链诊断：`wage_id / next_id / wage_bal / next_bal / chain`）。
4. **工具加固**：`capture-snapshot.mjs` 的 `LABELS` 同步 A–I；JSON 定位先剥 ANSI 再按行首 `[` 找（wrangler 的代理警告文本里含 `[33m`，旧写法会误配）。

重生成后与**已执行**的 02/03/04 + 两个回滚件逐字节比对：除 `updated_at` 时间戳外**完全一致**（修复只动 01 的只读诊断），故重跑无需担心语句语义漂移。

## 7. 教训（已写进生成器注释与 README §5/§6）

1. **不要假设流水 id 相邻**。`ledger_entries.id` 跨队全局自增、各队交错 ⇒ 一切「下一行」判据必须用 `MIN(id) BETWEEN 本行 id + 1 AND 2147483647` 的本队窗口；`JOIN … id + 1 = n.id` 在生产必假。
2. **演练夹具必须复刻生产的交错 id 形状**。旧的形状级演练（27 断言全绿）用整齐相邻的 id，恰好把这个缺陷掩住了；新演练把生产真 id 与「他队行夹在中间」排布一起搬进来，缺陷才可见。
3. **只读诊断也要给 NULL 分支正确标签**。I 段链诊断最初把「无下游行」也报成 `broken`，会误导读数；已改为三态 `linked / broken / no-downstream`。
4. **半成品态是可自愈的**，前提是把「标记 + 锚」都放在守卫里、并把顺序排成 ②→①→③：本次事故形态（只跑过 ②）正是演练阶段 5 复现并验证自愈的形状。
